# Feature Specification: 聊天功能（第八阶段）

**Feature Branch**: `008-chat-conversations`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "按文档开发：0user chat/6聊天功能.md —— 开发聊天功能，用户可以选择 Agent 进行多轮对话，会话和聊天记录保存到数据库，刷新页面或重新打开后可以继续聊天。本阶段只实现模型直接回答，不调用工具、不启动 MCP Server、不加载 Skills。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 与选定的 Agent 发起对话并获得流式回复 (Priority: P1)

使用者打开聊天页，从底部选择一个 Agent（或使用快捷 `@` 唤起选择），输入消息后回车发送。系统先保存用户消息，显示"正在思考"，随后后端使用所选 Agent 的模型配置和系统提示词发起真实模型请求，回复内容随生成过程流式追加展示，并分别显示思考过程与回答正文。回复完成后整条回复保存到数据库。

**Why this priority**: 对话并拿到回复是聊天功能的核心价值，其余能力（会话持久化、多轮上下文、停止、切换）都围绕它展开。

**Independent Test**: 新建会话 → 选择 Agent → 输入一句话发送 → 观察到"正在思考" → 回答逐字流式出现（思考与正文分区展示）→ 完成后消息固定显示。

**Acceptance Scenarios**:

1. **Given** 系统中存在至少一个可用 Agent，**When** 使用者选择该 Agent 并发送一条非空消息，**Then** 消息靠右显示，随后出现"正在思考"，模型开始输出后显示"正在生成"并随流式输出逐步追加内容。
2. **Given** 一个流式回复正在进行，**When** 查看消息区域，**Then** 思考过程与回答正文分区展示，内容按生成顺序追加，无重复、无丢失、无乱序。
3. **Given** 一条回复生成完成，**When** 查看该条 Agent 回复，**Then** 顶部显示回复生成时所用的 Agent 名称，并提供"复制"操作。
4. **Given** 一条会话的最后一条 Agent 回复，**When** 使用者点击"重新生成"，**Then** 基于同一上下文重新发起生成；非最后一条的 Agent 回复不提供重新生成入口。
5. **Given** 使用者输入空内容或仅空白字符，**When** 尝试发送，**Then** 发送被禁止。
6. **Given** 使用者在中文输入法选词/组字状态按下回车，**When** 触发回车键，**Then** 不发送消息。
7. **Given** 使用者按 Enter，**When** 输入框非空，**Then** 消息发送；按 Shift + Enter 时输入框换行而不发送。
8. **Given** 系统中没有任何可用 Agent，**When** 使用者进入聊天页，**Then** 显示提示与前往 Agent 管理的入口，且发送被禁用。
9. **Given** 用户消息已发送，**When** 消息保存失败，**Then** 输入框保留原内容，显示失败原因，且不发起模型请求。

### User Story 2 - 会话列表管理与聊天记录持久化 (Priority: P1)

使用者可以在左侧会话列表新建会话、查看已有会话并点击加载对应聊天记录。会话和消息都保存在数据库中，刷新页面或重新打开后可以继续查看历史并继续发送消息。第一句用户消息保存成功后自动截取为会话标题。

**Why this priority**: "刷新后可继续"是本需求的硬性目标，没有持久化就无法构成连续对话体验；与 US1 同级，因为发送第一条消息即产生持久化需求。

**Independent Test**: 新建会话并发送两条消息 → 刷新页面 → 点击该会话 → 历史记录完整显示且自动滚动到底部 → 继续发送新消息成功。

**Acceptance Scenarios**:

1. **Given** 使用者在聊天页，**When** 点击"新建会话"，**Then** 会话保存到后端，保存成功后加入列表并自动选中，初始标题为"新会话"。
2. **Given** 一个标题仍为"新会话"的会话，**When** 第一条用户消息保存成功，**Then** 会话标题更新为该消息截取后的适当长度文本，不额外调用模型。
3. **Given** 会话列表，**When** 查看列表项，**Then** 展示标题与最后更新时间，按最后更新时间倒序排列；产生新消息时更新时间与排序，仅打开查看不改变排序。
4. **Given** 使用者点击某个会话，**When** 记录加载完成，**Then** 展示该会话的完整聊天记录，用户消息靠右、Agent 回复靠左，Agent 回复顶部显示对应 Agent 名称，并自动滚动到底部。
5. **Given** 使用者刷新页面或关闭后重新打开，**When** 再次进入聊天页并选择会话，**Then** 聊天记录完整加载，可继续发送消息。
6. **Given** 一个会话选择了某个 Agent，**When** 关闭后再次打开该会话，**Then** 恢复该会话保存的 Agent 选择。
7. **Given** 列表接口调用，**When** 返回结果，**Then** 只包含会话摘要（标题、时间等），不包含完整消息内容。

### User Story 3 - 多轮上下文与 Agent 切换 (Priority: P2)

同一会话内可以连续追问，每次请求模型时携带该 Agent 的系统提示词和本会话按顺序排列的有效历史消息。会话中途允许切换 Agent，切换只影响后续请求，历史保留。会话保存当前 Agent 选择，重新打开时恢复。

**Why this priority**: 多轮连贯与 Agent 切换是聊天体验的关键增强，但依赖 US1、US2 的发送与持久化基础，因此排后。

**Independent Test**: 在同一会话连续追问两轮，第二轮回答能体现对第一轮的理解；中途切换 Agent 后再发送，回复风格/内容体现新 Agent 的提示词，且历史仍完整。

**Acceptance Scenarios**:

1. **Given** 同一会话已有历史消息，**When** 使用者发送新消息，**Then** 模型请求携带该会话按顺序排列的有效历史消息与当前 Agent 的系统提示词，模型能理解连续追问。
2. **Given** 一次请求构造上下文，**When** 组装消息列表，**Then** 本条用户消息只出现一次，不重复追加；不混入其他会话的消息。
3. **Given** 使用者在会话内切换 Agent，**When** 之后发送消息，**Then** 请求使用新 Agent 的模型与系统提示词，历史消息保留，不沿用旧 Agent 的提示词。
4. **Given** 会话原选 Agent 已被删除或不可用，**When** 使用者打开该会话，**Then** 仍可查看聊天记录，但发送前需重新选择可用 Agent（旧回复的 Agent 名称显示不受影响）。

---

### User Story 4 - 生成控制：停止与后台继续 (Priority: P2)

生成过程中使用者可以点击"停止生成"结束本次回复；也可以在生成期间切换会话、新建会话或离开聊天页，后台继续生成，回到会话后能看到完整结果。

**Why this priority**: 属于体验完善类能力，在核心对话与持久化稳定后提供。

**Independent Test**: 发送消息后点击停止，输出立即终止并显示未完成状态；另开一次生成，切走再切回，回复仍完整出现。

**Acceptance Scenarios**:

1. **Given** 当前会话正在生成，**When** 使用者尝试再次发送或切换 Agent，**Then** 操作被禁止；生成结束（完成/失败/取消）后恢复可用。
2. **Given** 正在生成，**When** 使用者点击"停止生成"，**Then** 前端停止接收输出，后端尝试终止模型请求并清理资源，已生成部分保留。
3. **Given** 生成正在进行，**When** 使用者切换到其他会话或离开聊天页，**Then** 后台继续生成，回到原会话后可看到继续追加直至完成的完整回复。

---

### User Story 5 - 异常与失败状态处理 (Priority: P3)

模型连接失败、超时、空回复、流中断等各类异常均以独立提示展示原因，不影响已保存的用户消息；已生成的部分正文保存并标记为未完成，错误内容不写入聊天记录，也不作为上下文发给模型。

**Why this priority**: 异常分支不改变主流程价值，但必须处理以免误导用户；在核心流程稳定后补齐。

**Independent Test**: 在后端模拟模型请求失败（如错误密钥），发送消息后观察独立错误提示，用户消息仍在，聊天记录中不出现错误文本被当作回答。

**Acceptance Scenarios**:

1. **Given** 模型请求失败（连接失败、超时、返回空内容或流式中断），**When** 异常发生，**Then** 以独立的、便于理解的提示展示原因，聊天记录不新增"错误回答"。
2. **Given** 失败或用户取消，**When** 检查持久化结果，**Then** 用户消息保留；已生成部分正文的回复保存并标记为未完成，无正文时不产生空白回复。
3. **Given** 任一阶段失败，**When** 检查界面状态，**Then** 等待状态结束，用户可继续操作；错误信息与日志不泄露 API Key 等敏感信息。
4. **Given** 一条标记为未完成的回复，**When** 重新加载会话记录，**Then** 显示真实状态（未完成标识），不当作正常完成的回答。

---

## Edge Cases

- 历史消息总长超过模型可用上下文容量时，明确提示用户缩短输入或新建会话，不静默丢弃历史。
- Agent 被删除后，旧回复仍显示生成时的 Agent 名称与归属，不随删除变化。
- 同一会话在生成期间禁止切换 Agent 与重复发送，避免并发写入。
- 重新生成仅对最后一条 Agent 回复开放，避免中途重生成导致上下文歧义。
- 会话标题截取需处理纯英文长单词、表情等无法按字数整齐截断的内容，截断时以省略号结尾。
- 保存用户消息成功但模型请求尚未发起时用户离开页面，会话状态仍保持一致（用户消息已持久化，无半成品回复）。
- 流式输出过程中内容乱序、重复或丢失时，终止本次生成并提示输出异常。

## Requirements *(mandatory)*

### Functional Requirements

**会话与消息持久化**

- **FR-001**: 系统 MUST 将会话与每条聊天消息持久化到数据库，禁止以 JSON 文件或浏览器本地存储代替。
- **FR-002**: 每条消息 MUST 保存所属会话、Agent 标识与名称、正文、创建时间与完成状态，并使用稳定的顺序字段读取，不能仅依赖时间戳排序。
- **FR-003**: Agent 回复 MUST 保留生成时的 Agent 标识与名称；后续切换、改名或删除 Agent 不改变旧回复显示的归属。
- **FR-004**: 会话 MUST 保存当前选择的 Agent，重新打开时恢复该选择；本阶段不提供会话删除功能。
- **FR-005**: 会话列表 MUST 展示标题与最后更新时间并按最后更新时间倒序排列；产生新消息时更新会话时间，仅查看不改变排序。
- **FR-006**: 会话列表接口 MUST 只返回会话摘要，不提前加载完整消息。
- **FR-007**: 系统 MUST 在第一条用户消息保存成功后，截取适当长度作为会话标题，不调用模型生成标题。

**发送与流式回复**

- **FR-008**: 输入框 MUST 支持回车发送、Shift + Enter 换行；中文输入法组合状态回车不得触发发送；空内容或纯空白不可发送。
- **FR-009**: 发送后系统 MUST 先保存用户消息：成功后清空输入框并显示"正在思考"；失败时保留输入内容、提示原因、不请求模型。
- **FR-010**: 后端 MUST 读取所选 Agent 的模型配置和系统提示词发起真实模型请求；模型调用与密钥读取只能在后端完成，前端不得获取 API Key。
- **FR-011**: 后端 MUST 实时打印调用第三方大模型的 API 请求响应日志。
- **FR-012**: 前端 MUST 以流式方式随生成进度追加展示回复，先显示"正在思考"、收到正文后显示"正在生成"；内容必须保持顺序，不重复、不丢失。
- **FR-013**: 前端 MUST 分别展示思考过程与回答正文，消息内容使用 Markdown 渲染。
- **FR-014**: Agent 回复 MUST 支持复制操作；仅最后一条 Agent 回复支持重新生成。
- **FR-015**: 生成完成后系统 MUST 将完整回复保存到数据库；保存失败时明确提示，不得让用户误以为已可靠保存。

**多轮与上下文**

- **FR-016**: 每次请求模型 MUST 携带当前 Agent 的系统提示词与本会话按顺序排列的有效历史消息；本条用户消息在上下文中只出现一次。
- **FR-017**: 不同会话历史 MUST 相互隔离；失败或取消产生的未完成回复不加入后续上下文，错误提示不作为聊天内容发送给模型。
- **FR-018**: 本阶段不做自动摘要或上下文压缩；历史超限时系统 MUST 明确提示缩短输入或新建会话，不得静默丢弃历史。
- **FR-019**: 会话允许切换 Agent，切换只影响后续请求；后续请求使用新 Agent 的模型和系统提示词，保留有效历史，不沿用旧 Agent 提示词。

**生成状态与停止**

- **FR-020**: 当前会话生成中 MUST 禁止重复发送与切换 Agent；完成、失败或取消后恢复。
- **FR-021**: 用户点击停止时，前端 MUST 停止接收输出，后端 MUST 尽可能终止模型请求并清理资源。
- **FR-022**: 生成期间切换会话、新建会话或离开聊天页 MUST 支持后台继续生成。

**异常处理**

- **FR-023**: 系统 MUST 处理模型连接失败、请求超时、空回复、流式中断等异常，以独立提示展示原因；错误提示不得保存为 Agent 回答。
- **FR-024**: 失败或取消时系统 MUST 保留已保存的用户消息；已生成部分正文则保存并标记未完成，无正文不创建空白回复。
- **FR-025**: 任何阶段失败 MUST 结束等待状态；错误信息与日志不得泄露 API Key 等敏感信息。

**页面布局**

- **FR-026**: 聊天页 MUST 分为左右两部分：左侧会话列表（顶部含"新建会话"按钮），右侧为聊天区域。
- **FR-027**: 聊天区域顶部展示会话标题；中间消息区用户消息靠右、Agent 回复靠左，配色、字号与交互与现有管理页面保持一致。
- **FR-028**: 底部输入区 MUST 提供多行输入框、发送按钮和生成中的停止按钮，并支持选择 Agent 及快捷 `@` 唤起 Agent 选择。
- **FR-029**: 新建会话 MUST 默认选择"默认 Agent"；无可用 Agent 时提示用户先创建 Agent，提供前往 Agent 管理的入口并禁用发送。

### Key Entities *(include if feature involves data)*

- **会话（Conversation）**：一次连续对话的载体。属性：标题、当前选择的 Agent、最后更新时间、创建时间。一个会话包含多条消息，消息相互隔离于其他会话。
- **消息（Message）**：会话中的一条发言。属性：所属会话、角色（用户 / Agent）、Agent 标识与名称（Agent 回复时记录生成时刻的归属）、思考过程内容、回答正文、完成状态（生成中 / 已完成 / 未完成）、稳定顺序序号、创建时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者无需任何说明即可在 1 分钟内完成「新建会话 → 选择 Agent → 发送消息 → 收到完整流式回复」的闭环操作；发送成功后输入框清空与等待状态即时出现。
- **SC-002**: 刷新页面或重新打开后，100% 的已完成历史会话可完整恢复聊天记录并继续发送消息。
- **SC-003**: 流式回复展示与模型实际输出顺序一致，无重复、无丢失（抽查任意一次生成，正文内容与后端日志记录一致）。
- **SC-004**: 90% 以上的生成请求能正常完成并可靠持久化；失败场景均有明确、可理解的独立提示。
- **SC-005**: 同一会话连续 5 轮追问，模型回答均能正确关联前文（抽查问答相关性）。
- **SC-006**: 前端任意接口与日志中不出现 API Key 等敏感信息。
- **SC-007**: 会话列表加载只请求会话摘要，不加载全部会话的完整消息。

## Assumptions

- 本阶段仅实现"模型直接回答"：不调用工具、不启动 MCP Server、不加载 Skills；Agent 配置中的工具/Skills/MCP 绑定在本阶段聊天中被忽略。
- 用户体系沿用现有项目形态（单用户本地工作台），聊天不做多人、权限或登录态扩展。
- 会话列表顶部提供搜索或按标题过滤不在本阶段范围内，列表即全部会话。
- 重新生成 = 使用相同上下文（含被重新生成的回复之前的所有有效历史）再次发起模型请求，替换原回复的展示与存储。
- "适当长度"的会话标题默认取第一句用户消息的前 20 个字符（截断加省略号）。
- 停止生成的后端终止以"尽力而为"为标准：以平台能力允许的方式中断请求并释放资源，不承诺模型侧计费停止。
- 聊天页入口沿用现有侧边导航，路由与菜单由 Plan 阶段确定。
- Markdown 渲染范围限定为常规文本、代码块、列表、链接与表格等常见语法；不涉及自定义渲染扩展。
- 错误提示为界面内的独立提示（非聊天气泡内容），文案面向普通使用者描述原因与建议操作。
- API Key 安全沿用现有模型管理模块的既有约定：密钥仅存在于后端配置与调用链路。
