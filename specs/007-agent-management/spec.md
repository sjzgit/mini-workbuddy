# Feature Specification: Agent 管理（第七阶段）

**Feature Branch**: `007-agent-management`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "按文档开发：0user chat/5Agent管理.md —— 开发 Agent 管理功能。Agent 用于组合模型、系统提示词、工具、Skills 和 MCP Server，形成面向具体任务的配置。本阶段只实现配置管理和页面状态，不开发 Agent Loop、运行记录和历史会话。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新建 Agent 并完成编排配置 (Priority: P1)

使用者打开 Agent 管理页，点击"新建"进入全屏编辑界面，填写名称与说明、编辑系统提示词、选择一个模型、按需勾选工具 / Skills / MCP Server、设定最大执行轮数，点击"发布"保存全部配置。新建成功后回到列表，可以看到新 Agent 的卡片；保存的第一个 Agent 自动成为默认 Agent。

选择模型时以卡片列表展示各模型的名称与模型标识（不显示内部编号）；工具、Skills、MCP Server 的候选项同样以卡片列表展示名称与用途说明，均支持多选且允许一项不选。若系统中尚无任何可用模型，界面明确提示需要先添加模型，并提供跳转到模型管理的入口。

**Why this priority**: Agent 管理的核心价值就是把模型与能力组合成面向任务的配置；没有"能创建出一个 Agent"，列表、默认项、删除保护等都无从谈起。

**Independent Test**: 进入 Agent 管理页 → 点击新建 → 填写名称、说明，使用默认提示词模板，选择默认模型 → 发布 → 列表出现该 Agent 卡片且标记为默认。

**Acceptance Scenarios**:

1. **Given** 系统中已有至少一个已配置模型，**When** 使用者新建 Agent 并填写名称、选择模型后点击发布，**Then** 保存成功，列表出现该 Agent 卡片，且该 Agent 被自动设为默认 Agent。
2. **Given** 新建界面，**When** 查看系统提示词编辑区，**Then** 预填充了规定的角色模板文本（角色 / 目标 / 技能 / 工作流 / 输出格式 / 限制）。
3. **Given** 新建界面，**When** 查看模型选择区，**Then** 默认选中当前的默认模型，且每个候选项展示模型名称与模型标识。
4. **Given** 系统中没有任何模型，**When** 使用者进入新建界面，**Then** 界面明确提示需先添加模型，并提供前往模型管理的入口。
5. **Given** 使用者未填名称、或未选模型、或最大执行轮数不是正整数，**When** 点击发布，**Then** 保存被阻止，对应字段旁出现明确的错误提示，不产生任何数据。
6. **Given** 工具 / Skills / MCP 选择区，**When** 使用者不勾选任何一项并点击发布，**Then** 保存成功（能力绑定允许为空）。
7. **Given** 任意一次打开详情，**When** 查看主体内容第三列，**Then** "预览与调试"区域为占位展示，不提供可交互的对话功能。

### User Story 2 - Agent 列表浏览与详情查看 (Priority: P1)

使用者进入 Agent 管理页，以卡片列表浏览全部 Agent。每张卡片顶部展示名称、说明、所用模型、绑定的工具 / Skills / MCP Server 数量、是否默认 Agent 和最后更新时间；卡片中部展示部分关联的能力条目（最多三项，超出以 +N 汇总）；卡片底部提供编辑与删除按钮。点击卡片任意处进入该 Agent 的详情。没有 Agent 时页面展示空状态及新建入口。

**Why this priority**: 列表是 Agent 管理的日常入口，使用者需要一眼掌握"有哪些 Agent、各自用什么模型和哪些能力、哪个是默认"；与 US1 同级，因为创建后立即需要通过列表确认结果。

**Independent Test**: 创建 2~3 个绑定不同能力数量的 Agent → 核对每张卡片各信息项与统计数字正确、能力条目超过 3 个时显示 +N → 点击卡片进入详情且内容与保存一致。

**Acceptance Scenarios**:

1. **Given** 列表中存在若干 Agent，**When** 查看任一卡片，**Then** 顶部完整展示名称、说明、模型、工具数、Skills 数、MCP Server 数、默认标识与最后更新时间。
2. **Given** 某个 Agent 关联的工具、技能、MCP 合计超过 3 项，**When** 查看该卡片中部，**Then** 最多展示 3 个能力条目，并以 +N 形式显示剩余数量。
3. **Given** 绑定数量统计，**When** 其中包含已停用的能力，**Then** 数量仍按实际保存的绑定数计算。
4. **Given** 列表中没有任何 Agent，**When** 打开 Agent 管理页，**Then** 展示空状态并提供新建入口。
5. **Given** 列表中的任一卡片，**When** 使用者点击卡片（非编辑/删除按钮区域），**Then** 以全屏 dialog 打开该 Agent 的详情。

### User Story 3 - 编辑 Agent 与系统提示词版本管理 (Priority: P2)

使用者通过列表卡片或详情进入编辑，修改名称、说明、模型、能力绑定、最大执行轮数或系统提示词后发布保存。系统提示词区域右上角提供版本选择：首次保存时生成版本 1，此后仅当提示词内容发生变化才递增生成新版本；修改名称、模型、能力绑定等其他配置不产生新版本。使用者可以切换到任意历史版本查看并在此基础上编辑，保存时若内容与当前最新版本不同则生成新版本。

**Why this priority**: 编辑与版本管理保证配置可持续演进且提示词可回溯，但依赖 US1 建立的创建与保存链路。

**Independent Test**: 新建 Agent → 修改提示词保存（版本 +1）→ 仅改名称保存（版本不变）→ 切到版本 1 编辑保存（生成新版本）→ 重新打开详情核对各版本内容。

**Acceptance Scenarios**:

1. **Given** 首次保存的 Agent，**When** 查看其提示词版本，**Then** 存在版本 1，内容为首次保存时的提示词。
2. **Given** 编辑 Agent 时仅修改名称 / 说明 / 模型 / 能力绑定 / 最大执行轮数，**When** 发布保存，**Then** 保存成功且提示词版本号不变。
3. **Given** 编辑 Agent 时修改了系统提示词内容，**When** 发布保存，**Then** 生成新版本，版本号在前一版本基础上递增 1。
4. **Given** 版本选择器中存在多个版本，**When** 使用者切换到某个历史版本，**Then** 编辑区展示该版本的内容，可在此基础上修改。
5. **Given** 使用者基于历史版本修改后保存，**When** 保存内容与当前最新版本内容不同，**Then** 以新内容生成最新版本（追加，不覆盖历史版本）；**When** 保存内容与最新版本相同，**Then** 不新增版本。
6. **Given** 切换或新增版本操作，**When** 查看任一历史版本，**Then** 历史版本内容始终未被修改或删除。

### User Story 4 - 默认 Agent 管理与删除流程 (Priority: P2)

使用者可将任一 Agent 设为默认（系统中至多一个默认 Agent，设置新默认时旧的自动取消）。删除普通 Agent 前需要确认；删除当前默认 Agent 时，若还有其他 Agent，须先让使用者选择新的默认项，再完成删除与切换；删除最后一个 Agent 时确认后清除默认设置，页面回到空状态。全程保证不出现多个默认或默认指向已删除记录的情况。

**Why this priority**: 默认项与删除是配置生命周期的收尾能力，依赖列表（US2）存在后才有意义；其一致性规则直接影响后续所有阶段。

**Independent Test**: 创建 3 个 Agent → 设置第二个为默认并核对旧默认被取消 → 删除普通 Agent 出现确认 → 删除默认 Agent 时被要求先选定新默认 → 删除全部 Agent 后页面回到空状态。

**Acceptance Scenarios**:

1. **Given** 系统中已有默认 Agent，**When** 使用者将另一个 Agent 设为默认，**Then** 新 Agent 成为唯一默认，原默认自动取消。
2. **Given** 删除任一普通 Agent，**When** 使用者点击删除，**Then** 出现确认提示，确认后删除；取消则不删除。
3. **Given** 删除当前默认 Agent 且系统中还有其他 Agent，**When** 确认删除，**Then** 系统先要求使用者选择新的默认 Agent，完成选择后才执行删除并切换默认。
4. **Given** 删除最后一个 Agent，**When** 确认删除，**Then** 默认设置被清除，页面回到空状态。
5. **Given** 任意删除或默认切换操作完成后，**When** 检查数据，**Then** 系统中至多一个默认 Agent，且默认设置不指向已删除的记录。

### User Story 5 - 已停用能力的绑定保持 (Priority: P2)

只有处于启用状态的工具、Skills 和 MCP Server 才能被新加入 Agent 配置。已经绑定到 Agent 的能力后来被停用时，原有绑定保留并在编辑界面标记为"已停用，不可用"；使用者可以手动移除，也可以保留绑定直接保存其他修改，系统不得自动清除。列表中的绑定数量按实际保存的绑定统计（含已停用的能力）。本阶段仅处理配置与可用状态展示；运行时过滤停用能力的逻辑在 Agent Loop 阶段实现。

**Why this priority**: 停用是能力管理的常规操作，Agent 侧必须正确表现，否则使用者会在不知情的情况下丢失配置；依赖 US1 的绑定链路。

**Independent Test**: 创建绑定了某工具的 Agent → 在工具管理中停用该工具 → 打开 Agent 编辑，核对绑定仍在且标记"已停用，不可用"→ 不移除直接保存其他修改 → 重新打开核对绑定与标记均保留、卡片数量统计不变。

**Acceptance Scenarios**:

1. **Given** 能力选择列表，**When** 使用者查看候选项，**Then** 仅展示启用状态的工具、Skills 和 MCP Server。
2. **Given** 已绑定某能力的 Agent，**When** 该能力被停用后打开编辑，**Then** 该绑定仍存在并标记为"已停用，不可用"。
3. **Given** 存在"已停用"标记绑定的 Agent，**When** 使用者不移除该绑定并保存其他修改，**Then** 保存成功，绑定保留。
4. **Given** 存在"已停用"标记绑定，**When** 使用者手动移除该绑定并保存，**Then** 绑定被移除，且列表统计同步减少。
5. **Given** 任一 Agent 卡片，**When** 查看绑定数量，**Then** 数量包含已停用的绑定。

---

### User Story 6 - 被引用资源的删除保护 (Priority: P3)

当某个模型、Skill 或 MCP Server 被任意 Agent 引用时，在这些资源的管理模块中删除该资源必须被阻止，并展示正在使用它的 Agent 名称。使用者需要先修改相关 Agent（移除绑定或更换模型）或删除相关 Agent，使资源不再被引用后才能删除；系统不得自动解除绑定或替换模型。内置工具继续保持既有的不可删除规则。引用检查在服务端执行，不依赖前端按钮禁用。删除默认模型时，先执行 Agent 引用检查，再执行模型管理已有的默认项切换规则。

**Why this priority**: 保护的是跨模块数据一致性，防患于未然；在 Agent 尚不能运行的本阶段，错误删除的破坏面主要是后续阶段，故可稍后完成。

**Independent Test**: 创建引用某模型、某 Skill、某 MCP Server 的 Agent → 分别在三个管理模块尝试删除 → 均被阻止且提示引用该资源的 Agent 名称 → 在 Agent 中移除引用后再次尝试删除 → 删除成功。

**Acceptance Scenarios**:

1. **Given** 某资源被至少一个 Agent 引用，**When** 在对应管理模块发起删除，**Then** 删除被阻止，并展示引用该资源的 Agent 名称列表。
2. **Given** 删除请求绕过前端直接到达服务端，**When** 该资源仍被 Agent 引用，**Then** 服务端拒绝删除（引用检查不依赖前端）。
3. **Given** 引用某资源的全部 Agent 已移除引用或被删除，**When** 再次发起删除，**Then** 删除成功。
4. **Given** 删除请求针对的是默认模型且该模型被 Agent 引用，**When** 服务端处理，**Then** 先因 Agent 引用拒绝删除，不会触发模型管理的默认切换规则。
5. **Given** 删除请求针对内置工具，**When** 发起删除，**Then** 沿用既有规则不可删除。

---

### Edge Cases

- 名称重复：Agent 名称必须唯一（新需求修订：保存时校验重名，重名 → 409 人话提示；编辑时与其他 Agent 重名同样拒绝，与自身保持一致允许）。
- 最大执行轮数边界：输入 0、负数、小数或超大数值时的校验与提示（正整数，默认值与范围见 Assumptions）。
- 系统提示词极长（数千行）：编辑、保存与版本存储不受长度限制影响（大字段保存）。
- 并发编辑：两个页面同时编辑同一 Agent，后保存者覆盖先保存者（本阶段为单用户本地工作台，接受覆盖，不做冲突合并）。
- 唯一模型被删除保护覆盖：仅剩的默认模型被 Agent 引用时不可删除，避免出现"无模型 Agent 无法修复"的死局。
- 删除默认 Agent 时仅剩它一个 Agent：走"删除最后一个 Agent"分支（确认后清除默认并回到空状态），不要求选择新默认。
- 能力在编辑会话期间被停用：编辑页打开期间某能力被停用，保存时保留该绑定并按停用状态标记（以后端保存时的状态为准）。

## Requirements *(mandatory)*

### Functional Requirements

**列表（卡片）页面**

- **FR-001**: Agent 管理页 MUST 提供新建、编辑、删除和设置默认 Agent 的操作入口。
- **FR-002**: 系统中没有任何 Agent 时，页面 MUST 展示空状态并提供新建入口。
- **FR-003**: Agent 列表 MUST 采用卡片样式；每张卡片顶部 MUST 展示名称、说明、所用模型、工具绑定数、Skills 绑定数、MCP Server 绑定数、是否默认 Agent 与最后更新时间。
- **FR-004**: 卡片中部 MUST 按工具、技能、MCP Server 三类分行展示：每行展示该类绑定数量与全部已选项名称（列表接口返回全量绑定，不做条目截断）。
- **FR-004a**: 编辑界面中工具、Skills、MCP Server 的选择 MUST 通过"维护"弹窗完成：表单区每类仅展示已选概要（数量/名称），弹窗内提供关键词筛选与卡片式勾选（保留名称+用途说明的卡片形态）。
- **FR-005**: 卡片底部 MUST 提供编辑与删除按钮；点击卡片非按钮区域 MUST 进入该 Agent 详情。
- **FR-006**: 绑定数量统计 MUST 按实际保存的绑定计算，包含已停用的能力。

**Agent 详情（编辑）**

- **FR-007**: Agent 详情 MUST 以全屏 dialog 呈现，包含顶部基本信息与下方三列主体内容。
- **FR-008**: 顶部基本信息 MUST 包含：名称、说明、是否默认 Agent，以及发布按钮；点击发布 MUST 保存 Agent 的全部配置（含主体内容中的所有配置）。
- **FR-009**: 第一列系统提示词 MUST 为铺满可用高度的文本域，长度不限，以大字段保存；新建时 MUST 预填充规定的角色模板文本。
- **FR-010**: 系统提示词区域右上角 MUST 提供版本选择，可切换版本查看与维护；提示词变化后保存时 MUST 新增版本。
- **FR-011**: 第二列 Agent 编排 MUST 自上而下包含：模型选择（单选一个已配置模型）、深度思考开关与深度思考程度（关闭 / 低 / 中 / 高；本阶段仅保存配置，实际效果在 Agent Loop 阶段实现）、工具多选、Skills 多选、MCP Server 多选、最大执行轮数（正整数；本阶段仅保存配置，执行限制在 Agent Loop 阶段实现）。
- **FR-012**: 第三列 MUST 为"预览与调试"占位区域，本阶段不提供交互功能。
- **FR-013**: 各能力选择项 MUST 以卡片列表展示名称与用途说明；模型选项 MUST 展示名称及模型标识（不得只显示内部编号）；工具、Skills 与 MCP Server MUST 支持多选且允许不选。
- **FR-014**: 新建 Agent 时 MUST 默认选中当前默认模型；没有任何可用模型时 MUST 明确提示先添加模型，并提供前往模型管理的入口。
- **FR-015**: 保存前 MUST 校验名称（必填）、模型选择（必选）与最大执行轮数（正整数）；最大执行轮数 MUST 提供合理默认值与范围说明。
- **FR-016**: 能力候选项 MUST 仅包含启用状态的工具、Skills 与 MCP Server。
- **FR-017**: 已绑定能力被停用后，系统 MUST 保留原绑定并在编辑界面标记为"已停用，不可用"；使用者 MAY 手动移除，MAY 保留绑定保存其他修改；系统 MUST NOT 自动清除。

**系统提示词版本**

- **FR-018**: Agent 首次保存时 MUST 为系统提示词生成版本 1；此后仅当提示词内容发生变化时 MUST 才生成新版本并递增版本号。
- **FR-019**: 修改名称、模型、能力绑定等其他配置 MUST NOT 增加提示词版本号。
- **FR-020**: 使用者 MUST 能够切换到历史版本查看并编辑；保存时内容与最新版本不同则生成新版本，相同则不生成；历史版本 MUST 不可被修改或删除。

**默认 Agent 与删除**

- **FR-021**: 系统 MUST 保证至多一个默认 Agent；保存第一个 Agent 时 MUST 自动将其设为默认。
- **FR-022**: 设置新的默认 Agent 时，系统 MUST 自动取消旧 Agent 的默认状态。
- **FR-023**: 删除普通 Agent 前 MUST 经使用者确认。
- **FR-024**: 删除当前默认 Agent 且还有其他 Agent 时，系统 MUST 先让使用者选择新的默认项，再完成删除与默认切换。
- **FR-025**: 删除最后一个 Agent 时，确认后 MUST 清除默认设置并使页面回到空状态。

**资源引用保护**

- **FR-026**: 模型、Skill 或 MCP Server 被任意 Agent 引用时，系统 MUST 阻止在对应管理模块删除该资源，并展示正在使用它的 Agent 名称。
- **FR-027**: 引用检查 MUST 在服务端执行，不得仅依赖前端禁用按钮。
- **FR-028**: 系统 MUST NOT 自动解除绑定或替换模型；内置工具继续沿用既有的不可删除规则。
- **FR-029**: 删除默认模型时，服务端 MUST 先执行 Agent 引用检查，通过后再执行模型管理已有的默认项切换规则。

**数据保存与页面**

- **FR-030**: Agent 配置、能力绑定、默认状态与系统提示词版本 MUST 持久化，刷新页面或重启服务后 MUST 完整保留。
- **FR-031**: Agent 管理页面的配色、字号、布局与交互方式 MUST 与既有管理页面保持一致。

### Key Entities *(include if feature involves data)*

- **Agent**：面向具体任务的配置单元。属性：名称、说明、是否默认、当前系统提示词内容、引用的模型、最大执行轮数、最后更新时间。与其他实体的关系：引用一个模型；绑定多个工具 / Skills / MCP Server。
- **Agent 能力绑定**：Agent 与工具 / Skill / MCP Server 之间的引用关系，记录绑定时的资源与该资源当前启用状态的表现（启用 / 已停用，不可用）。一个资源可被多个 Agent 绑定；一个 Agent 可绑定多类多个资源，也可为空。
- **系统提示词版本**：某 Agent 系统提示词的一次内容快照。属性：版本号（从 1 起递增）、内容、生成时间。属于且仅属于一个 Agent；历史版本只读。
- **被引用的资源（既有实体）**：模型、Skill、MCP Server、工具。本特性为其追加"被 Agent 引用"这一维度，用于删除保护判定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者从打开新建界面到保存成功一个含模型与至少一项能力绑定的 Agent，全程不超过 3 分钟。
- **SC-002**: 保存的 Agent 配置、绑定与提示词版本在页面刷新和服务重启后 100% 完整保留。
- **SC-003**: 任意时刻检查数据，系统中至多存在一个默认 Agent，且默认设置不指向已删除记录（一致性校验 100% 通过）。
- **SC-004**: 被任意 Agent 引用的模型 / Skill / MCP Server 的删除请求 100% 被服务端拒绝，且提示中包含引用它的 Agent 名称。
- **SC-005**: 提示词版本号仅在提示词内容变化时递增，历史版本内容 100% 保持不变（可回溯任一历史版本）。
- **SC-006**: Agent 卡片展示的信息项（名称、说明、模型、三类绑定数量、默认标识、更新时间）与实际保存数据 100% 一致。
- **SC-007**: 使用者在无模型环境下进入新建界面时，能通过明确提示与入口一步跳转到模型管理。

## Assumptions

- **"发布"按钮的语义**：本阶段没有运行时与发布状态机，"发布"等同于"保存全部配置"（含主体三列中的所有配置），不引入独立的已发布 / 草稿状态。
- **最大执行轮数**：默认值取 10，允许范围 1~100；界面在字段旁说明"限制后续 Agent Loop 的执行轮数"。
- **卡片能力条目排序**：卡片中部最多三项按 工具 → 技能 → MCP Server 的顺序合并展示，超出以 +N 汇总（N 为全部绑定数减 3）。
- **名称唯一性**：Agent 名称全局唯一；保存（新建/编辑）时后端校验，重复 → 409。
- **无模型引导**：详情中模型选择区在无可用模型时整体展示引导提示与跳转入口；保存校验同时拦截（模型必选）。
- **删除默认 Agent 时的新默认选择**：通过确认对话框内列出其余 Agent 供选择；若使用者在选择步骤取消，则不执行删除。
- **停用能力在候选项中的呈现**：已绑定的停用能力不出现在可勾选候选项中，而是保留在绑定区并单独标记"已停用，不可用"。
- **范围边界（本阶段不做）**：Agent Loop 执行、运行记录、历史会话、预览与调试的交互功能、运行时过滤停用能力、Agent 名称查重、并发编辑冲突处理均不在本阶段范围内。
