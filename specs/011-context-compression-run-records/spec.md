# Feature Specification: 上下文压缩与运行记录可观测（第十一阶段）

**Feature Branch**: `011-context-compression-run-records`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "结合两个文档的要求实现上下文压缩和运行记录保存及查看：0user chat/9 上下文压缩.md、0user chat/10 运行记录和可观测.md —— 在统一 Agent Runtime 中加入上下文容量管理与自动压缩，避免长会话超过模型上下文限制；同时开发运行记录功能，将 Runtime 运行过程与工具执行数据一并持久化存储，提供运行列表与详情时间线的保存及查看，统一指标口径并做好敏感信息脱敏。"

## Clarifications

### Session 2026-09-15

- Q: 流式正文的内容增量（delta）事件是否持久化到数据库？ → A: 不逐条持久化。只持久化结构性事件（运行开始/结束、模型请求开始/结束、工具调用开始/结束、压缩、错误等）；内容增量仅用于实时流式展示，最终回答正文以会话消息数据为单一事实来源，详情页从消息数据读取。
- Q: 会话删除时关联的运行记录、事件与详细载荷如何处理？ → A: 级联删除。删除会话时其运行记录、事件与详细载荷一并删除，不保留孤儿记录；单用户工作台定位，无跨会话审计需求。
- Q: 使用者回到聊天页时，对后台运行中/后台已完成的运行如何呈现？ → A: 自动续播。进入会话时查询该会话运行状态：后台运行中则展示运行状态并自动订阅事件流，工具卡片与正文实时补齐直至完成；已后台完成则正常展示最终回答。
- Q: 详细载荷超过保存大小上限时如何处理？ → A: 不设截断。详细载荷使用大容量字段完整保存，确保能完整存入表中，MUST NOT 截断或丢弃；读取入口仍保持独立受控与脱敏。源文档中的"限制保存大小"按此决定调整为完整保存。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 运行记录持久化与生命周期状态 (Priority: P1)

使用者在聊天页发送消息并启动 Agent 后，本次运行对应生成一条运行记录（Run），记录运行所属会话、Agent 与模型的运行时快照、开始时间、最终状态与结束原因。运行状态至少区分：运行中、成功、部分完成（如因执行轮数耗尽等限制结束）、失败（模型服务错误或内部异常导致终止）、已取消（用户主动停止）。状态与结束原因分开保存：单个工具失败不代表整个运行失败，Agent 仍可能继续完成任务；模型失败前已输出的部分文字仍保留，运行仍标记为失败。使用者关闭页面或断开浏览器连接不会终止运行——运行在后台继续执行，最终结果仍写入原运行记录；后端重启或异常退出导致运行无法继续时，遗留的"运行中"记录被标记为失败并注明"运行中断"，不永久停留在运行中。Runtime 运行过程中的事件与工具执行数据一并持久化，记录由真实运行产生，不重复创建、不另写模拟日志。

**Why this priority**: 运行记录持久化是本阶段一切可观测能力（列表、详情、指标、压缩事件展示）的数据基础，也是补齐前两阶段 Runtime 与工具执行数据未落库的关键缺口；没有它，其余故事无从展示，后续评测也无接口可复用。

**Independent Test**: 分别触发正常成功、工具失败后继续完成、模型失败、用户取消、轮数耗尽、后台运行结束、异常中断恢复七类运行 → 每次产生且仅产生一条运行记录，状态与结束原因与实际情形一致；重启后遗留记录被标注"运行中断"。

**Acceptance Scenarios**:

1. **Given** 使用者发送消息并启动 Agent，**When** 运行启动，**Then** 生成一条运行记录（而非整个会话一条或每轮模型调用一条），包含唯一运行标识、所属会话、Agent 与模型快照及开始时间。
2. **Given** 各类结束情形，**When** 查看运行记录，**Then** 正常完成状态为成功；执行轮数耗尽等限制结束为部分完成；模型服务错误或内部异常终止为失败；用户主动停止为已取消。
3. **Given** 一次运行中单个工具执行失败，**When** Agent 借助后续轮次仍完成任务，**Then** 运行状态为成功，工具失败只体现在对应步骤，不标记整个运行失败。
4. **Given** 模型失败前已输出部分文字，**When** 运行终止，**Then** 运行标记为失败，已输出的未完成内容保留。
5. **Given** 运行进行中使用者关闭页面或断开连接，**When** 运行继续在后台执行，**Then** 最终结果仍写入原运行记录，运行不因断开被取消。
6. **Given** 后端重启或异常退出时有遗留的运行中记录，**When** 系统恢复，**Then** 遗留记录被标记为失败并注明"运行中断"。
7. **Given** 任意一次运行，**When** 检查持久化数据，**Then** 运行事件与工具执行数据由统一 Runtime 依据真实运行写入，无另行创建的记录或模拟日志。
8. **Given** 后台运行进行中或已后台完成，**When** 使用者重新进入该会话，**Then** 聊天页查询运行状态并自动续播：运行中的自动订阅事件流直至完成，已完成的正常展示最终回答。

### User Story 2 - 运行列表与指标统计 (Priority: P1)

使用者打开运行记录页面，看到按开始时间倒序的运行列表，支持分页与按状态、Agent 筛选。每行展示状态、Agent、模型、开始时间、总耗时、模型调用次数、工具调用次数、Token 用量和错误摘要（正常完成的运行不显示错误）。Agent 与模型名称使用运行时快照，后续配置改名或删除不改变历史记录。指标来自实际运行事件与模型返回的真实用量，口径明确：总耗时从运行开始到进入最终状态；模型调用次数为实际发出的模型请求次数（含失败请求，重试每次单独计数）；工具调用次数为实际进入工具执行入口的次数（权限或参数校验被拒绝的请求单独记录、不计为已执行）；Token 用量汇总各次请求返回的输入、输出及缓存命中用量且不重复累计；首个输出耗时从运行开始到收到首段可展示正文（空数据块与工具参数片段不算正文）。模型未返回 Token 用量时显示"未知"，无正文输出时首个输出耗时显示"无正文输出"。

**Why this priority**: 列表是使用者回答"每次请求是否成功、耗时多久、调用了几次模型和工具"的第一入口；指标口径在本阶段统一后，详情页与后续评测复用同一口径，避免两套数字。

**Independent Test**: 构造含重试、工具校验拒绝、无 Token 返回、无正文输出的运行 → 打开列表逐行核对九个展示字段与快照正确性；对比不同返回行数下加载列表的查询次数不随行数增长。

**Acceptance Scenarios**:

1. **Given** 多条运行记录，**When** 打开运行列表，**Then** 按开始时间倒序展示，支持分页与按状态、Agent 筛选。
2. **Given** 任意一行，**When** 查看展示字段，**Then** 包含状态、Agent、模型、开始时间、总耗时、模型调用次数、工具调用次数、Token 用量；失败运行附带简短错误摘要，正常完成的运行无错误摘要。
3. **Given** 某 Agent 或模型在运行后被改名或删除，**When** 查看历史运行列表，**Then** 展示的名称仍为运行时快照。
4. **Given** 一次发生重试的运行，**When** 统计模型调用次数，**Then** 每次实际发出的请求单独计数，包含失败请求。
5. **Given** 一次工具请求被权限或参数校验拒绝的运行，**When** 统计工具调用次数，**Then** 被拒绝的请求不计入已执行次数，且被单独记录。
6. **Given** 某次模型请求未返回 Token 用量，**When** 查看统计，**Then** 显示"未知/统计不完整"而非零；**Given** 无正文输出的运行，**When** 查看首个输出耗时，**Then** 显示"无正文输出"。
7. **Given** 固定分页条件，**When** 对比不同返回行数下的列表加载，**Then** 数据库查询次数恒定，不随行数逐条增长；列表加载不读取详情事件与详细载荷。

### User Story 3 - 运行详情与事件时间线 (Priority: P1)

使用者点击列表中的某条运行，进入详情页，看到运行摘要和按真实事件顺序排列的时间线。时间线包含 Agent 开始、模型请求、工具执行、最终回答、错误和运行结束；系统实际发生了上下文压缩时也展示压缩事件，未发生则不出现虚构事件。模型步骤展示模型名称、状态、耗时、调用模型接口的完整输入输出和 Token 用量；工具步骤展示易读名称、状态、输入摘要、结果摘要和耗时，MCP 工具同时展示所属 Server 名称。每个事件携带运行标识、步骤或调用标识和稳定的顺序字段，开始与结束通过调用标识配对（不依赖时间戳或工具名称），失败步骤清楚标明原因——使用者无需翻看原始日志即可定位问题发生在哪一步。详情默认读取安全事件与摘要，大段详细载荷按需单独加载。

**Why this priority**: 时间线回答"失败发生在哪一步"，是运行记录的核心价值；列表（US2）提供入口后即可独立交付验证。

**Independent Test**: 触发一次含模型调用、内置与 MCP 工具调用及一次失败步骤的运行 → 打开详情核对时间线顺序、配对关系、模型与工具步骤字段、失败原因说明；验证详细载荷默认不加载、按需可查看。

**Acceptance Scenarios**:

1. **Given** 一条已结束的运行，**When** 打开详情页，**Then** 展示运行摘要与按真实事件顺序排列的时间线，包含 Agent 开始、模型请求、工具执行、最终回答、错误与运行结束。
2. **Given** 一次含工具调用的运行，**When** 查看模型步骤，**Then** 展示模型名称、状态、耗时、完整输入输出与 Token 用量；**When** 查看工具步骤，**Then** 展示易读名称、状态、输入摘要、结果摘要与耗时，MCP 工具附带 Server 名称。
3. **Given** 事件配对关系，**When** 检查开始与结束事件，**Then** 通过调用标识一一配对，失败步骤标明原因。
4. **Given** 详情页加载，**When** 检查默认请求内容，**Then** 只读取安全事件与摘要，大段详细载荷按需单独加载。
5. **Given** 系统实际发生一次上下文压缩，**When** 查看该运行详情，**Then** 时间线出现对应压缩事件；未发生压缩的运行不出现虚构压缩事件。

### User Story 4 - 长会话上下文自动压缩 (Priority: P1)

长会话持续聊天时，统一 Runtime 在每次模型请求前估算实际请求的 Token 占用（系统提示词、已启用 Skills、工具定义、会话摘要、历史消息，以及本次新增的消息与工具结果），按"模型上下文长度减去输出预留与安全余量"得到可用输入容量。估算输入达到触发比例（默认 80%）时自动触发压缩：保留系统提示词、Skills、工具定义、已有会话摘要、最近若干完整对话轮（默认 5 轮，每轮含用户消息、Agent 回答及相关工具交互的完整内容）和本次用户消息，把较早的完整对话交给当前运行使用的模型整理成摘要。摘要保留用户目标、已确认事实、重要工具结果、明确限制和未完成事项，按任务清单方式整理；会话已有摘要时，以旧摘要为基础与新增待压缩消息合并生成新摘要，不丢失此前信息。新摘要与"已压缩到哪条消息"的边界一起保存；下一次压缩只处理边界之后新增的较早消息。摘要以会话背景（用户消息角色）进入上下文，不替代系统提示词。压缩只改变发送给模型的上下文，原始消息与完整历史仍可查看。

**Why this priority**: 压缩直接解决"长会话超过模型上下文限制"的核心痛点，是本阶段两大目标之一；压缩事件需经 US1 的事件持久化才能被详情页观测，故排在运行记录之后。

**Independent Test**: 用小上下文模型构造长会话持续对话 → 观察到估算达到触发比例后产生压缩开始/成功事件，压缩后的请求正常完成；查看聊天记录仍完整；再次触发压缩时摘要基于旧摘要增量更新，且不从第一条消息重新处理全部历史。

**Acceptance Scenarios**:

1. **Given** 会话估算输入达到触发比例，**When** 下一次模型请求前检查容量，**Then** 自动触发压缩，压缩后重新估算的输入降至可用容量内，运行继续完成。
2. **Given** 压缩发生，**When** 检查发送给模型的上下文，**Then** 保留系统提示词、Skills、工具定义、已有摘要、最近配置轮数的完整对话与本次用户消息，较早内容以摘要形式作为会话背景进入上下文，不替代系统提示词、不提升历史内容指令优先级。
3. **Given** 会话已有摘要且边界之后有新增较早消息，**When** 再次压缩，**Then** 以已有摘要为基础合并新增内容生成新摘要并更新边界，不从第一条消息重新处理全部历史，也不只摘要新增内容而丢失此前信息。
4. **Given** 待压缩内容过多，**When** 生成摘要，**Then** 按完整消息组分批处理，不一次性提交超长历史，也不递归触发压缩流程。
5. **Given** 压缩完成后使用者翻看聊天记录，**When** 查看完整历史，**Then** 原始消息全部保留，未被删除或改写。
6. **Given** 一次压缩过程，**When** 查看运行事件，**Then** 记录压缩开始与成功（或失败、备用处理），至少含触发原因、压缩前后估算 Token 数、处理与实际保留的消息数量、压缩耗时；摘要生成计入模型调用次数与实际 Token 用量并标记用途为"上下文压缩"，不占用任务执行轮数。

### User Story 5 - Agent 压缩配置与关闭压缩行为 (Priority: P2)

使用者在 Agent 管理中为每个 Agent 配置压缩策略并持久化保存：自动压缩开关（默认开启）、触发比例（默认估算输入达到可用输入容量的 80%）、保留最近对话轮数（默认 5 轮）、摘要目标长度（默认约 1000 Token，作为摘要生成目标，不保证精确等长）。每个字段提供清晰说明与校验；摘要目标长度结合实际可用容量限制，避免在小窗口模型下反而占满上下文。关闭自动压缩后，系统不再调用模型生成摘要；输入超过容量时明确提示使用者缩短内容、开启压缩或新开会话，不静默丢弃历史。

**Why this priority**: 配置让不同模型窗口与使用习惯得到合适的压缩策略；默认配置已让 US4 开箱即用，配置项属于可控性增强，故列于其后。

**Independent Test**: 打开 Agent 编辑页核对四个配置项的存在、默认值、说明与校验，分别保存合法与非法值；关闭自动压缩后构造超容量输入，确认得到明确提示、未发起摘要请求、历史未被静默丢弃。

**Acceptance Scenarios**:

1. **Given** Agent 管理编辑页，**When** 查看配置，**Then** 提供自动压缩开关、触发比例、保留最近对话轮数、摘要目标长度四个设置项，默认值分别为开启、80%、5 轮、约 1000 Token，保存后持久化生效。
2. **Given** 使用者输入非法配置值，**When** 保存，**Then** 得到明确的字段校验错误，非法值不被保存。
3. **Given** 摘要目标长度超过当前模型可用输入容量，**When** 压缩执行，**Then** 摘要目标被限制在可用容量内，不出现摘要本身占满上下文的情况。
4. **Given** 自动压缩已关闭，**When** 输入超过可用容量，**Then** 不发起摘要请求，使用者得到"缩短内容 / 开启压缩 / 新开会话"的明确提示，历史不被静默丢弃。

### User Story 6 - 压缩失败与备用裁剪 (Priority: P2)

摘要请求超时、模型调用失败、返回空摘要或摘要保存失败时，聊天不会一直等待：系统保留当前有效摘要，按完整消息组从最早内容开始逐步减少上下文、尽量保留最近对话，作为本次请求的备用处理。压缩后重新估算仍超限时，同样逐步减少较早的保留对话并记录实际保留数量。备用处理只影响本次请求，不更新压缩边界、不删除历史；容量允许时继续运行，仍无法容纳必要内容时返回明确错误。压缩与备用裁剪都以完整对话或工具交互组为单位，保留工具请求与结果的正确配对，不留下孤立的调用或结果；本次用户消息与尚未完成的工具交互不被裁掉。压缩过程响应运行取消信号并清理相关请求资源。

**Why this priority**: 保证压缩不可用或仍超限时长会话仍能降级继续对话，是压缩能力可靠性的兜底；依赖 US4 的容量估算与消息分组，故排在其后。

**Independent Test**: 模拟摘要请求失败、超时与空返回 → 观察到备用裁剪事件，本次请求完成且最近对话保留、工具配对完整、压缩边界未变、历史未删除；压缩期间触发取消，确认压缩请求及时终止并清理资源。

**Acceptance Scenarios**:

1. **Given** 摘要请求超时、调用失败、返回空摘要或保存失败，**When** 压缩流程处理，**Then** 聊天不无限等待，保留当前有效摘要并转入备用裁剪，产生压缩失败与备用处理事件。
2. **Given** 备用裁剪发生，**When** 检查影响范围，**Then** 只影响本次请求：压缩边界不更新、历史记录不删除；容量允许时运行继续完成。
3. **Given** 备用裁剪后仍无法容纳必要内容，**When** 请求处理，**Then** 返回明确错误，不静默发送必然超限的请求。
4. **Given** 压缩或备用裁剪操作，**When** 检查消息分组，**Then** 以完整对话或工具交互组为单位，工具请求与结果保持配对，无孤立调用或结果；本次用户消息与尚未完成的工具交互不被裁掉。
5. **Given** 压缩进行中收到运行取消信号，**When** 处理取消，**Then** 压缩请求尽快终止并清理相关请求资源。
6. **Given** 正常压缩后重新估算仍超限，**When** 处理容量，**Then** 逐步减少较早的保留对话并记录实际保留数量，而非直接失败。

## Edge Cases

- 首次发送时系统提示词、Skills、工具定义与必须保留内容本身已超过容量：结束本次运行并明确说明原因，提示减少配置内容或缩短输入，不发送必然超限的请求。
- 关闭自动压缩且输入超容量：明确提示缩短内容、开启压缩或新开会话，不静默丢弃历史。
- 运行中某轮工具结果过大导致超限：每轮请求前检查容量，按压缩或备用流程处理，处理已完成的工具交互时保留调用配对与必要结果，不删除其中一条。
- 小窗口模型下摘要目标长度超过可用容量：摘要目标受限缩小，不占满上下文。
- 模型接口未返回 Token 用量：统计显示"未知/统计不完整"，不填零。
- 事件重复投递或页面重新加载：不重复插入步骤、不重复累计次数与 Token；运行已结束后无步骤永久显示"执行中"。
- 摘要与边界保存部分失败：保留上一份有效摘要与边界，不提前推进边界导致内容丢失。
- 压缩触发时恰好收到取消信号：压缩请求终止并清理资源，运行按取消路径收尾，不产生半个事件。
- 会话更换模型（上下文长度不同）：容量估算以本次运行实际使用模型的配置为准。
- 摘要请求反复失败：受独立次数或超时限制约束，避免反复压缩无法结束。

## Requirements *(mandatory)*

### Functional Requirements

**运行记录与持久化**

- **FR-001**: 每次用户发送消息并启动 Agent 时，系统 MUST 生成一条运行记录；MUST NOT 为整个会话或每轮模型调用单独创建记录。
- **FR-002**: 运行记录 MUST 保存唯一运行标识、所属会话、Agent 与模型的运行时名称快照、开始时间、结束时间、最终状态、结束原因与错误摘要；运行记录、事件与详细载荷随所属会话级联删除，MUST NOT 在会话删除后保留孤儿记录。
- **FR-003**: 运行状态 MUST 至少区分运行中、成功、部分完成、失败、已取消；状态与结束原因 MUST 分开保存。
- **FR-004**: 单个工具失败 MUST NOT 直接将整个运行标记为失败；模型失败前已输出的部分文字 MUST 保留。
- **FR-005**: 统一 Runtime 运行过程中的事件与工具执行数据 MUST 持久化存储（补齐前两阶段未落库的部分，并在既有会话与消息数据基础上拓展）；运行记录 MUST 由 Runtime 依据真实运行产生，MUST NOT 由页面另行创建或另写一套模拟日志；后续评测 MUST 能复用同一套记录接口。持久化粒度为结构性事件（运行开始/结束、模型请求开始/结束、工具调用开始/结束、压缩、错误等）；流式正文的内容增量片段仅用于实时展示，MUST NOT 逐条持久化；最终回答正文以会话消息数据为单一事实来源，详情页从消息数据读取，MUST NOT 在事件中重复存储整段正文。
- **FR-006**: 浏览器断开后运行 MUST 沿用后台运行机制继续执行，最终结果 MUST 写入原运行记录；使用者重新进入会话时，聊天页 MUST 查询该会话运行状态并自动续播——后台运行中的自动订阅事件流直至完成，已后台完成的正常展示最终回答。
- **FR-007**: 后端重启或异常退出导致运行无法继续时，系统 MUST 将遗留的运行中记录标记为失败并注明"运行中断"，MUST NOT 永久停留在运行中。
- **FR-008**: 持久化事件 MUST 包含运行标识、步骤或调用标识与稳定的顺序字段；开始与结束 MUST 通过调用标识配对；事件重复投递或重新加载时 MUST NOT 重复插入步骤、重复累计调用次数或 Token。
- **FR-009**: 运行结束后 MUST NOT 出现步骤永久显示执行中的情况；运行状态、指标汇总与事件保存 MUST 保持一致。

**运行列表与指标**

- **FR-010**: 运行列表 MUST 按开始时间倒序展示，支持分页，支持按状态与 Agent 筛选。
- **FR-011**: 列表每行 MUST 展示状态、Agent、模型、开始时间、总耗时、模型调用次数、工具调用次数、Token 用量与错误摘要；正常完成的运行 MUST NOT 显示错误。
- **FR-012**: Agent 与模型名称 MUST 使用运行时快照；配置改名或删除 MUST NOT 改变历史记录展示。
- **FR-013**: 列表 MUST 只读取摘要字段，MUST NOT 加载完整事件、模型输入或工具结果；展示数据 MUST 通过快照字段、关联查询或批量查询获取，相同分页条件下数据库查询次数 MUST NOT 随返回行数逐条增长。
- **FR-014**: 指标统计 MUST 采用统一口径：总耗时为运行开始到进入最终状态的时间；模型调用次数为实际发出的模型请求次数（含失败请求，重试每次单独计数）；工具调用次数为实际进入工具执行入口的次数（权限或参数校验被拒绝的请求单独记录，不计为已执行）；Token 用量为汇总各次模型请求返回的输入、输出及缓存命中用量且不重复累计；首个输出耗时为运行开始到收到首段可展示正文的时间（空数据块与工具参数片段不算正文）。
- **FR-015**: 模型服务未返回 Token 用量时 MUST 显示"未知/统计不完整"，MUST NOT 填零；没有正文输出时首个输出耗时 MUST 显示"无正文输出"；缓存命中用量是否计入输入 Token MUST 按接口定义处理，MUST NOT 重复相加。

**运行详情与时间线**

- **FR-016**: 运行详情页 MUST 展示运行摘要与按真实事件顺序排列的时间线；时间线 MUST 包含 Agent 开始、模型请求、工具执行、最终回答、错误与运行结束；实际发生上下文压缩时 MUST 展示压缩事件，MUST NOT 生成虚构事件。
- **FR-017**: 模型步骤 MUST 展示模型名称、状态、耗时、调用接口时的完整输入输出与 Token 用量；工具步骤 MUST 展示易读名称、状态、输入摘要、结果摘要与耗时，MCP 工具 MUST 同时展示 Server 名称；失败步骤 MUST 清楚标明原因。
- **FR-018**: 详情页 MUST 默认读取安全事件与摘要；大段详细载荷 MUST 按需单独加载。

**与聊天页共用事件**

- **FR-019**: 聊天中的工具卡片与运行详情 MUST 使用同一批事件及同一套名称、状态、摘要规则，同一次调用在两个页面 MUST NOT 显示不同结果。

**敏感信息与详细载荷**

- **FR-020**: 写入日志、运行记录与展示事件之前 MUST 统一脱敏：模型 API Key、MCP 环境变量、认证 Header、完整系统环境与用户设备绝对路径 MUST NOT 进入持久化记录；路径需要展示时 MUST 使用工作区相对路径或脱敏占位符；错误信息与工具输出 MUST 经过检查后再持久化。
- **FR-021**: 模型完整输入输出与完整工具结果 MUST 使用独立、受控的详细载荷存储，读取入口独立受控；载荷 MUST 使用大容量字段完整保存，确保能完整存入表中，MUST NOT 截断或丢弃；详细载荷同样 MUST 脱敏，MUST NOT 因访问受控而保存秘密原文。

**上下文容量估算**

- **FR-022**: Runtime MUST 在每次模型请求前估算实际请求的 Token 占用，范围 MUST 覆盖系统提示词、已启用 Skills、工具定义、会话摘要、历史消息，以及本次运行新增的消息与工具结果。
- **FR-023**: 可用输入容量 MUST 按"模型配置的上下文长度减去输出预留与安全余量"计算，MUST NOT 将整个窗口用于输入；上下文压缩 MUST 在统一 Runtime 中实现，页面 MUST NOT 单独处理上下文裁剪，聊天与后续评测 MUST 复用同一套逻辑。
- **FR-024**: Token 计数 MUST 优先复用已有统计工具；无适配当前模型的实现时 MAY 使用稳定估算方法，但代码、页面与运行事件 MUST 明确标注"估算"，MUST NOT 与模型接口返回的实际 Token 用量混淆。

**Agent 压缩配置**

- **FR-025**: Agent 管理 MUST 提供并持久化保存：自动压缩开关（默认开启）、触发比例（默认估算输入达到可用输入容量的 80%）、保留最近对话轮数（默认 5 轮，每轮含用户消息、Agent 回答及相关工具交互的完整内容）、摘要目标长度（默认约 1000 Token）；MUST 提供清晰说明与字段校验。
- **FR-026**: 摘要目标长度 MUST 结合实际可用容量限制，避免在小窗口模型下摘要本身占满上下文。
- **FR-027**: 关闭自动压缩后系统 MUST NOT 调用模型生成摘要；输入超过容量时 MUST 明确提示缩短内容、开启压缩或新开会话，MUST NOT 静默丢弃历史。

**压缩范围与摘要内容**

- **FR-028**: 触发压缩时 MUST 保留系统提示词、已启用 Skills、工具定义、已有会话摘要、最近配置轮数的完整对话及本次用户消息，将较早的完整对话交由当前运行使用的模型整理成摘要。
- **FR-029**: 摘要 MUST 保留用户目标、已确认事实、重要工具结果、明确限制与未完成事项，MAY 缩短或忽略闲聊、重复表述与失效过程，按任务清单方式整理。
- **FR-030**: 已有摘要 MUST 作为后续压缩的更新基础，与新增待压缩消息一起生成新摘要，MUST NOT 只摘要新增内容而丢失此前信息。
- **FR-031**: 摘要 MUST 以会话背景（用户消息角色）进入上下文，MUST NOT 替代系统提示词或提升历史内容的指令优先级。
- **FR-032**: 摘要请求自身 MUST 满足模型容量限制；待压缩内容过多时 MUST 按完整消息组分批处理，MUST NOT 将超长历史一次性提交，MUST NOT 递归触发压缩流程。

**增量保存与历史保留**

- **FR-033**: 压缩成功后 MUST 将新摘要与"已压缩到哪条消息"的边界一起保存到当前会话；后续压缩 MUST 只处理边界之后新增的较早消息，MUST NOT 每次从第一条消息重新处理。
- **FR-034**: 摘要与边界 MUST 一致更新；生成或保存失败时 MUST 保留上一份有效摘要与边界，MUST NOT 提前推进边界导致内容丢失。
- **FR-035**: 原始消息与运行记录 MUST 继续保留，使用者 MUST 能查看完整历史；压缩 MUST 只改变发送给模型的上下文，MUST NOT 删除或改写会话中的聊天记录数据。

**消息完整性与容量不足**

- **FR-036**: 压缩与备用裁剪 MUST 以完整对话或工具交互组为单位，保留工具请求与结果的正确配对，MUST NOT 留下孤立的调用或结果。
- **FR-037**: 正常压缩后 MUST 重新估算容量；仍超限时才逐步减少较早的保留对话并记录实际保留数量；本次用户消息与尚未完成的工具交互 MUST NOT 被直接裁掉。
- **FR-038**: Runtime MUST 在每轮模型请求前检查是否需要压缩；处理已完成的工具交互时 MUST 保留调用配对与必要结果，MUST NOT 只删除其中一条消息。
- **FR-039**: 首次发送时若系统提示词、Skills、工具定义与必须保留内容本身已超过容量，系统 MUST 结束本次运行并明确说明原因，提示减少配置内容或缩短输入，MUST NOT 继续发送必然超限的请求。

**压缩失败与备用处理**

- **FR-040**: 摘要请求超时、模型调用失败、返回空摘要或摘要保存失败时，系统 MUST NOT 让聊天一直等待：MUST 保留当前有效摘要，按完整消息组从最早内容开始减少、尽量保留最近对话。
- **FR-041**: 备用处理 MUST 只影响本次请求，MUST NOT 更新已压缩边界，MUST NOT 删除历史；容量允许时继续运行，仍无法容纳必要内容时 MUST 返回明确错误。
- **FR-042**: 压缩过程 MUST 响应运行取消信号并清理相关请求资源。

**压缩事件与统计**

- **FR-043**: 系统 MUST 复用现有运行事件记录压缩开始、成功、失败与备用处理；事件至少包含触发原因、压缩前后估算 Token 数、处理的消息数量、实际保留的消息数量与压缩耗时。
- **FR-044**: 运行详情 MUST 展示压缩安全摘要；完整历史或摘要正文 MUST NOT 直接写入普通日志。
- **FR-045**: 摘要生成 MUST 计入模型调用次数与实际 Token 用量并标记用途为"上下文压缩"；MUST NOT 占用 Agent Loop 的任务执行轮数；MUST 有独立的次数或超时限制，避免反复压缩无法结束。

### Key Entities *(include if feature involves data)*

- **运行记录（Run）**：一次 Agent 运行的持久化记录。属性：唯一运行标识、所属会话、Agent 名称快照、模型名称快照、状态（运行中/成功/部分完成/失败/已取消）、结束原因、开始与结束时间、总耗时、模型调用次数、工具调用次数、Token 用量汇总、首个输出耗时、错误摘要；随所属会话级联删除。
- **运行事件（RunEvent，持久化）**：Runtime 真实事件的落库形态。属性：运行标识、稳定顺序字段、事件类型、轮次、调用标识，以及按类型附带的状态、耗时、Token 用量与脱敏安全摘要；是聊天页工具卡片、详情时间线与指标统计的共同来源。粒度为结构性事件，流式正文的内容增量片段不落库。
- **详细载荷**：模型完整输入输出与完整工具结果的受控存储。属性：关联的事件或调用标识、载荷类型、脱敏后的完整内容；使用大容量字段完整保存、不截断，读取入口独立且受控。
- **会话压缩状态**：会话的摘要与边界信息。属性：当前摘要内容、已压缩到哪条消息的边界、更新时间；与摘要生成及保存的一致性绑定。
- **Agent 压缩配置**：Agent 级压缩策略。属性：自动压缩开关、触发比例、保留最近对话轮数、摘要目标长度。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 正常成功、工具失败后继续完成、模型失败、用户取消、轮数耗尽、后台运行结束、异常中断恢复七类场景逐一验证，运行记录的状态与结束原因 100% 正确；后端重启后遗留的"运行中"记录 100% 被标注"运行中断"。
- **SC-002**: 抽查运行的事件配对 100% 通过调用标识一一对应；事件重复投递与页面重新加载场景 100% 不重复插入步骤、不重复累计调用次数与 Token。
- **SC-003**: 相同分页条件下，10 行与 50 行返回的列表加载数据库查询次数相同（不随行数增长），且列表加载不读取详情事件与详细载荷。
- **SC-004**: 抽查持久化记录、详情页与日志，100% 不含模型 API Key、MCP 环境变量、认证 Header、完整系统环境及用户设备绝对路径。
- **SC-005**: 抽查 10 次运行，列表展示的指标（总耗时、模型调用次数、工具调用次数、Token 用量、首个输出耗时）与事件明细核算结果一致率 100%；无用量返回时 100% 显示"未知"而非零。
- **SC-006**: 长会话估算输入达到触发比例后 100% 自动触发压缩；压缩后请求在容量内正常完成；原始聊天记录 100% 保留可查看；连续两次压缩验证摘要为增量更新且边界一致推进。
- **SC-007**: 摘要失败四类场景（超时、调用失败、空摘要、保存失败）100% 在限定时间内转入备用处理，聊天不无限等待；备用处理 100% 不改变压缩边界、不删除历史记录。
- **SC-008**: 关闭自动压缩且超容量时 100% 得到明确提示；首次发送即超容量时 100% 结束运行并说明原因，无必然超限的请求发出。
- **SC-009**: 摘要生成 100% 计入模型调用统计并标记"上下文压缩"用途、不占用任务轮数；压缩事件 100% 含触发原因、前后估算 Token、处理与保留消息数量及耗时。
- **SC-010**: 聊天工具卡片与运行详情对同一次调用展示的名称、状态与摘要 100% 一致。

## Assumptions

- 输出预留与安全余量的具体默认值、压缩独立次数/超时限制的具体数值在 Plan 阶段确定。
- Token 估算的具体算法在 Plan 阶段确定；事件类型清单沿用第九阶段 contracts 并按需扩展（新增压缩相关事件类型）。
