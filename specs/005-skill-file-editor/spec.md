# Feature Specification: Skill 目录浏览与文件在线编辑（第五阶段）

**Feature Branch**: `005-skill-file-editor`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "skill管理中增加skill目录结构及文件在线编辑：skill详情改为大的dialog——上方显示基础信息（skill名称、描述、是否启用、技能目录名称、更新时间），支持单独保存基础信息；下方左侧显示 skill 的文件夹目录结构，右侧为选中文件后的在线编辑区域（textarea 编辑即可），可保存写入到文件中"

> 说明：本特性是 004 Skills 管理的迭代增强（详情形态升级 + 文件级访问能力），遵循同一文件为本架构。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 详情大对话框与基础信息独立保存 (Priority: P1)

使用者在 Skills 列表点击某 Skill 的编辑入口后，打开一个大对话框（而非原右侧抽屉）。对话框上方是基础信息区：Skill 名称、描述、是否启用（状态展示）、技能目录名称（只读展示）、更新时间（只读展示）；使用者修改名称与描述后可单独保存基础信息，保存后写回 skill.md 的 frontmatter，列表中的名称、说明与更新时间随之刷新。对话框下方是工作区：左侧目录树、右侧文件编辑区（见 US2/US3）。

**Why this priority**: 详情对话框是本特性的容器与入口，基础信息独立保存沿用 004 已有的编辑语义（frontmatter 重写），是后续两个故事的操作舞台。

**Independent Test**: 打开某 Skill 的详情对话框，核对上方基础信息五项完整展示；修改名称与描述并单独保存，核对列表与 skill.md 文件同步更新；核对目录名称与更新时间只读、启用状态在对话框内可见。

**Acceptance Scenarios**:

1. **Given** 列表中存在某 Skill， **When** 使用者打开其详情对话框， **Then** 上方展示名称、描述、是否启用、技能目录名称、更新时间五项基础信息。
2. **Given** 使用者在详情对话框修改了名称或描述， **When** 点击保存基础信息， **Then** skill.md 的 frontmatter 同步更新，列表中该 Skill 的名称、说明与更新时间随之刷新。
3. **Given** 详情对话框处于打开状态， **When** 使用者查看技能目录名称与更新时间， **Then** 两项为只读展示，不提供修改入口。

---

### User Story 2 - Skill 目录结构浏览 (Priority: P1)

详情对话框下方的左侧展示该 Skill 目录的完整文件结构：目录与文件按层级呈现（树形），使用者点击任意文件后，右侧进入该文件的编辑区域。目录结构反映磁盘真实内容（含 skill.md 与其他全部文件、子目录）。

**Why this priority**: 目录树是文件编辑的导航入口，没有它右侧编辑区无从选择文件；与 US3 构成"浏览 → 编辑"的最小闭环。

**Independent Test**: 在某 Skill 目录下手工放置多级子目录与文件，打开详情对话框核对左侧树形结构与磁盘一致；点击任一文件，右侧切换为该文件的编辑区并加载内容。

**Acceptance Scenarios**:

1. **Given** 某 Skill 目录内存在多级子目录与多个文件， **When** 打开详情对话框， **Then** 左侧树形完整展示目录与文件的层级结构，与磁盘内容一致。
2. **Given** 使用者点击树中的某个文件， **When** 右侧编辑区加载完成， **Then** 显示该文件的路径标识与内容。
3. **Given** 某 Skill 目录内只有 skill.md 一个文件， **When** 打开详情对话框， **Then** 左侧树至少展示该文件，页面不出现报错或空白树。

---

### User Story 3 - 文件在线编辑与保存 (Priority: P1)

使用者在右侧编辑区以纯文本编辑框（textarea）修改选中文件的内容，点击保存后内容写回磁盘上的该文件。不可编辑的文件（非 UTF-8 文本、超过大小上限）在加载时明确提示且不进入编辑态。文件保存成功后编辑区内容与磁盘一致；关闭对话框后再次打开，内容保持已保存状态。

**Why this priority**: 在线编辑与写回是本特性的核心交付——"页面修改 ↔ 文件写回"延续文件为本原则；与 US2 共同构成可用闭环。

**Independent Test**: 选中 skill.md 修改内容并保存，用文本编辑器核对磁盘文件已更新；再次打开详情对话框核对内容保持；放置一个非 UTF-8 文件与一个超大小上限文件，核对两者加载时被明确提示且不可编辑。

**Acceptance Scenarios**:

1. **Given** 编辑区已加载某 UTF-8 文本文件， **When** 使用者修改内容并点击保存， **Then** 内容写回磁盘该文件，提示保存成功。
2. **Given** 某文件不是有效的 UTF-8 文本（如二进制文件）， **When** 使用者点击该文件， **Then** 明确提示该文件不可编辑，编辑区不展示乱码内容。
3. **Given** 某文件超过单文件大小上限， **When** 使用者点击该文件， **Then** 明确提示超过上限不可编辑。
4. **Given** 一次已保存的文件编辑， **When** 关闭并重新打开详情对话框， **Then** 该文件内容与保存时一致（文件为本，无缓存漂移）。

---

### Edge Cases

- 文件路径包含 `..`、绝对路径、盘符等可逃逸 Skill 目录的形态怎么办？—— 一律拒绝（读取与保存同等校验），返回明确错误；这是与 ZIP 导入同级的安全底线。
- 选中的文件在打开后被外部删除怎么办？—— 保存失败并给出"文件不存在"类明确提示；刷新目录树后消失。
- 保存时文件已被外部修改怎么办？—— 以页面保存为准直接覆盖（第一版不做冲突检测），保存成功即写回。
- 新建文件 / 删除文件 / 上传文件怎么办？—— 本版本不提供（浏览 + 编辑现有文件为边界），目录结构变化仅来自 ZIP 导入与外部手工维护。
- 保存的文件内容为空怎么办？—— 允许空内容（清空文件合法）。
- 目录树中点击的是目录而非文件怎么办？—— 目录仅展开/收起，不进入编辑区。
- skill.md 被文件编辑区改坏了 frontmatter 怎么办？—— 文件为本：解析失败时列表展示按兜底规则处理（名称取目录名），不阻塞其他功能；使用者可在编辑区修正。
- 空目录在树中怎么展示？—— 展示为无子节点的目录节点。
- 很大的文本文件（未超上限但很长）怎么办？—— 正常加载，编辑区自身可滚动。
- 对话框内启停开关与列表页启停是什么关系？—— 同一数据（skills.enabled），在对话框内切换即保存生效，列表同步刷新。

## Requirements *(mandatory)*

### Functional Requirements

**详情对话框与基础信息**

- **FR-001**: Skills 详情 MUST 以大对话框形态呈现（替换原右侧抽屉），分为上方基础信息区与下方工作区（左目录树 + 右文件编辑区）。
- **FR-002**: 基础信息区 MUST 展示：Skill 名称、描述、是否启用、技能目录名称、更新时间；其中名称与描述可编辑，技能目录名称与更新时间为只读。
- **FR-003**: 基础信息 MUST 支持单独保存：保存后同步写回 skill.md frontmatter 并刷新列表信息与更新时间（沿用 004 编辑语义）。
- **FR-004**: 是否启用 MUST 在基础信息区可见且可切换，切换即生效并同步列表（复用既有启停接口）。

**目录结构浏览**

- **FR-005**: 左侧 MUST 以树形展示该 Skill 目录内全部目录与文件的层级结构，反映磁盘真实内容。
- **FR-006**: 点击树中的文件 MUST 在右侧加载该文件的编辑区；点击目录仅展开/收起。
- **FR-007**: 目录读取 MUST 限定在该 Skill 目录内：任何路径解析后落在该目录之外的请求 MUST 被拒绝并返回明确错误。

**文件在线编辑**

- **FR-008**: 右侧编辑区 MUST 使用多行纯文本编辑框承载文件内容，并提供保存操作。
- **FR-009**: 保存 MUST 将编辑内容写回磁盘对应文件（UTF-8），成功后给出明确提示。
- **FR-010**: 非 UTF-8 文本文件与超过单文件大小上限的文件 MUST 在加载时明确提示不可编辑，MUST NOT 展示乱码内容。
- **FR-011**: 文件读取与保存 MUST 复用既有的单文件大小上限配置；内容为空合法。
- **FR-012**: 保存 skill.md MUST 同步刷新列表中的名称、说明与更新时间（frontmatter 可能被修改）；保存其他文件不影响列表信息。

**页面一致性**

- **FR-013**: 详情对话框的配色、字号、布局与交互 MUST 与既有管理页面保持一致（引用设计令牌）。

### Key Entities

- **Skill 详情对话框（视图形态）**: 上（基础信息表单）/ 下（左目录树 + 右文件编辑区）三区布局；替换 004 的编辑抽屉。
- **Skill 文件节点（Skill File Node）**: 目录树中的一个节点。属性：相对路径、类型（目录/文件）、子节点列表。
- **Skill 文件内容（Skill File Content）**: 单个文件的文本内容。属性：相对路径、内容（UTF-8 文本）、是否可编辑（否的原因：非文本/超上限）。
- **授权边界（Skill 目录）**: 所有文件读取与保存 MUST 限制在该 Skill 的目录内（路径解析后包含性校验），与 ZIP 导入的逃逸防护同一安全口径。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 详情对话框基础信息五项 100% 展示；名称/描述单独保存后磁盘 frontmatter、列表信息与更新时间 100% 同步刷新。
- **SC-002**: 在 Skill 目录内手工构造的多级子目录结构，树形展示与磁盘一致率 100%；点击任意文件 100% 正确加载对应内容。
- **SC-003**: 文件编辑保存后，页面内容与磁盘文件的一致率 100%；关闭重开后内容 100% 保持。
- **SC-004**: 在包含 `..`、绝对路径、盘符形态的越界路径测试中，读取与保存的拒绝率 100%，且无任何该 Skill 目录之外的文件被触碰。
- **SC-005**: 非 UTF-8 文件与超上限文件 100% 被明确提示不可编辑，零乱码展示。

## Assumptions

- 本版本只提供"浏览 + 编辑现有文件"：新建文件、删除文件、上传文件、重命名均不在范围内（目录结构变化来自 ZIP 导入与外部手工维护，符合 004 的文件为本工作流）。
- 保存采用"页面为准直接覆盖"语义，第一版不做文件冲突检测（与 004 编辑 skill.md 的覆盖语义一致）。
- 目录树不设自动轮询刷新，提供手动刷新入口。
- 单文件大小上限沿用既有配置（1MB，与 003 文件工具同口径）；编辑区不限输入字数，由上限校验兜底。
- 文件内容均按 UTF-8 文本处理，二进制文件不进入编辑态。
- 对话框内的启停与列表页启停共享同一持久化状态，无独立语义。
