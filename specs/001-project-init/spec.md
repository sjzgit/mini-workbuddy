## User Scenarios & Testing *(mandatory)*

### User Story 1 - 搭建可运行的前后端工程骨架 (Priority: P1)

开发者按照仓库说明，在全新环境中一次性完成依赖安装并启动前后端服务：前端开发服务器启动后可以看到完整的应用界面；后端服务启动后提供健康的 `/api` 接口入口和正式的 SQLite 数据库连接。本阶段不包含任何业务功能，但工程骨架必须是"真实的"——构建、测试、数据库迁移等基础设施全部可用，而非演示性空壳。

**Why this priority**: 一切后续功能都依赖可运行的工程骨架。没有这一层，后续任何阶段的开发与验证都无法进行。

**Independent Test**: 在干净环境中按说明执行安装与启动命令，前端页面可打开、后端接口可访问、数据库迁移可执行，即为本故事交付完成。

**Acceptance Scenarios**:

1. **Given** 一台装有 Node.js 和 uv 的全新机器，**When** 开发者按仓库说明安装依赖并启动前后端，**Then** 前端开发服务器正常启动并渲染应用界面，后端服务正常启动并响应 `/api` 请求。
2. **Given** 后端工程已建立，**When** 执行数据库迁移命令，**Then** 迁移成功执行，SQLite 数据库文件按正式连接配置生成。
3. **Given** 前端开发环境，**When** 页面请求相对路径 `/api` 下的接口，**Then** 请求被开发代理转发到后端服务，无需在前端代码中出现后端绝对地址。
4. **Given** 后端依赖管理文件（`pyproject.toml` 与 `uv.lock`）已生成，**When** 开发者添加或安装依赖，**Then** 全程通过 uv 工作流完成，说明文档中不存在要求用户直接运行 pip 的步骤。

---

### User Story 2 - 统一的应用布局与模块导航 (Priority: P1)

使用者打开应用后看到统一的工作台布局：页面占满浏览器高度、不出现整页横向滚动；桌面宽度下左侧为固定宽度 188px 的导航栏，顶部显示产品名称 mini-workbuddy（可配一个简单的圆形字母标记），右侧为内容区。导航按固定顺序显示 8 个入口：聊天、Agent 管理、模型管理、工具管理、MCP 管理、Skills 管理、运行记录、Agent 评测。每个入口有独立地址，点击后右侧页面正常切换；默认打开聊天页面；刷新任意地址仍能打开对应页面，不出现空白页。

**Why this priority**: 布局与导航是所有后续模块的容器，决定了整个产品第一阶段的可见形态；路由可靠性（刷新不白屏）是工作台类产品的基本要求。

**Independent Test**: 逐一点击 8 个菜单项验证页面切换与地址变化，并对每个地址执行刷新验证页面正常渲染，即为本故事交付完成。

**Acceptance Scenarios**:

1. **Given** 使用者在桌面宽度下打开应用，**When** 应用加载完成，**Then** 页面占满浏览器高度、无整页横向滚动，左侧导航固定 188px，顶部显示产品名称，右侧为内容区。
2. **Given** 应用已加载，**When** 使用者依次点击 8 个菜单项，**Then** 每个菜单项切换到对应独立地址的页面，当前选中项有明确的选中背景。
3. **Given** 使用者停留在任一模块地址，**When** 刷新浏览器，**Then** 对应模块页面正常打开，不出现空白页或回到默认页。
4. **Given** 使用者首次打开应用，**When** 不做任何操作，**Then** 默认落在聊天页面。

---

### User Story 3 - 诚实的占位页面 (Priority: P2)

使用者进入聊天之外的任一模块（或本阶段的聊天页）时，看到统一的页面结构：顶部为页面标题和一句简短说明，下面为内容卡片。卡片写明"本模块将在后续阶段开发"，并告诉使用者当前阶段先完成什么。页面不出现任何虚构的统计数字、对话和列表。

**Why this priority**: 占位页面让整个导航结构真实可用且诚实——使用者清楚每个模块的当前状态，同时确立了后续所有页面复用的统一结构。

**Independent Test**: 逐一访问 8 个模块页面，验证标题、说明、占位文案齐全且无虚构内容，即为本故事交付完成。

**Acceptance Scenarios**:

1. **Given** 使用者进入任一模块页面，**When** 页面渲染完成，**Then** 页面顶部显示该模块标题与一句简短说明，下方为内容卡片。
2. **Given** 模块尚无业务内容，**When** 使用者阅读占位卡片，**Then** 文案写明"本模块将在后续阶段开发"，并说明当前阶段先完成什么；页面不含虚构的统计数字、对话和列表。

---

### User Story 4 - 统一视觉设计令牌（配色、字体、字号） (Priority: P2)

所有页面呈现一致的暖色工作台视觉风格：颜色全部来自集中定义的全局 CSS 变量（背景层级、边框、主色、文本层级、语义色按约定方式使用）；正文使用 DM Sans，页面标题和产品名称使用 Outfit，代码/命令/日志使用 Fira Code，字体不可用时回退系统字体且页面仍可用；字号遵循统一规格（页面主标题 18px/字重 650，卡片标题 14–15px/字重 600，正文和表单 12.5px，按钮和菜单 12–12.5px，辅助说明 10.5–11.5px，代码 12px，正文行高 1.5），不出现 32px 以上的大标题。整体不出现蓝紫渐变、霓虹光效、大面积纯黑背景和高饱和荧光色；阴影很轻且只用于弹窗和浮层；卡片依靠白色背景和浅色边框区分。

**Why this priority**: 设计令牌集中定义是后续所有页面的视觉基础，决定产品的统一质感；本阶段落地后，后续模块只需引用变量。

**Independent Test**: 抽查全部 8 个页面与导航、布局：颜色均引用全局变量（无散落的相近色硬编码）、字体与字号符合规格、无禁用的视觉元素，即为本故事交付完成。

**Acceptance Scenarios**:

1. **Given** 全局样式已定义，**When** 检查任意页面或组件的样式来源，**Then** 颜色与字体均引用全局 CSS 变量，不存在页面内自定的相近色或脱离规格的字号。
2. **Given** 使用者的网络环境无法加载网络字体，**When** 打开应用，**Then** 页面回退到系统字体正常渲染与使用，不出现不可用或长时间空白。
3. **Given** 使用者浏览任意页面，**When** 观察整体视觉，**Then** 卡片以白色背景和浅色边框区分，无蓝紫渐变、霓虹光效、大面积纯黑背景和高饱和荧光色，阴影仅出现在弹窗与浮层。
4. **Given** 浏览器宽度小于 900px，**When** 使用者使用应用，**Then** 左侧菜单收起为窄栏或抽屉（任选一种稳定做法），收起后仍能打开所有菜单，主内容不被菜单遮挡。

### User Story 5 - 开发规范单一事实来源（AGENTS.md） (Priority: P3)

开发者在仓库根目录的 `AGENTS.md` 中读到完整的开发约定：项目名称、固定技术栈、前后端目录结构、常用启动和测试命令、Python 必须使用 uv 的规则、数据库迁移方式、配色与字号入口，以及每次修改后需要运行的前后端检查清单，并包含前后端开发规范。后续开发约定变化时只更新这一个文件，相同规则不散落在各任务说明中。

**Why this priority**: 规范文档保证后续每个阶段的开发与验证口径一致；它是流程性基建，价值在后续阶段持续兑现，故列为 P3（但必须在本阶段完成，因为后续阶段依赖它）。

**Independent Test**: 一名新加入的开发者仅依据 `AGENTS.md` 即可完成环境搭建、启动、测试与修改后检查，且文件中能找到上述全部约定条目。

**Acceptance Scenarios**:

1. **Given** `AGENTS.md` 已补充完善，**When** 开发者查阅该文件，**Then** 能找到项目名称、固定技术栈、前后端目录、常用启动与测试命令、uv 强制规则、数据库迁移方式、配色与字号入口、修改后的检查清单及前后端开发规范。
2. **Given** 后续开发约定发生变化，**When** 约定被更新，**Then** 仅更新 `AGENTS.md` 这一个文件，不产生散落在其他任务说明中的重复规则。

### Edge Cases

- **网络字体加载失败**：页面回退到系统无衬线/等宽字体，功能与布局不受影响，不因字体阻塞渲染。
- **直接访问或刷新深层模块地址**：每个模块路由独立可直达，刷新后渲染对应模块页面而非空白页。
- **浏览器宽度在 900px 附近来回拖动**：菜单在展开与收起状态间切换稳定，不出现布局错乱、内容被遮挡或横向滚动条。
- **菜单收起状态下的操作**（窄屏）：所有 8 个菜单入口仍可到达，打开菜单不永久遮挡主内容。
- **后端服务未启动时**：仅做布局浏览的前端开发环境仍可正常启动与展示页面（本阶段页面不依赖后端业务数据）。
- **数据库首次使用**：执行迁移命令时 SQLite 数据库文件与基线结构自动就绪，无需手工建库。
- **重复执行迁移命令**：已应用的迁移不重复执行，不报错。

## Requirements *(mandatory)*

### Functional Requirements

**工程骨架**

- **FR-001**: 前端工程 MUST 按固定技术栈初始化：Vue 3、TypeScript、Vite、Vue Router、Pinia、sass、npm 管理依赖、Ant Design（ant-design-vue），测试使用 Vitest；不得引入 React、Next.js、Nuxt、Django、Flask。
- **FR-002**: 后端工程 MUST 按固定技术栈初始化：Python 3.12、FastAPI、Pydantic、SQLAlchemy、Alembic、SQLite；测试使用 pytest。
- **FR-003**: 后端 MUST 在 `backend/` 目录中用 uv 初始化，生成并持续维护 `pyproject.toml` 与 `uv.lock`；添加依赖用 `uv add`、安装依赖用 `uv sync`、运行后端命令（含 Alembic、pytest）用 `uv run`；README 中不得出现要求用户直接运行 pip 的步骤。
- **FR-004**: 后端 MUST 提供正式的 SQLite 数据库连接（SQLAlchemy engine/session），并准备 Alembic 迁移环境与基线迁移；后续功能数据一律写入数据库，不得用 JSON 文件代替。
- **FR-005**: 前端开发环境 MUST 始终请求相对路径 `/api`，由 Vite 转发到后端；前端代码中不得硬编码后端绝对地址。
- **FR-006**: 前端代码 MUST 放在 `frontend/src` 下，页面、路由、状态、请求封装、通用组件和样式分目录放置；后端代码 MUST 放在 `backend/app` 下，应用入口、路由、业务逻辑、数据访问和数据校验各自放在含义明确的目录下。
- **FR-007**: 系统 MUST NOT 为显得完整而创建大量空文件或空目录；当前无业务内容的模块仅保留一个前端占位页面，不提前搭建空的后端业务目录。

**布局与导航**

- **FR-008**: 整个页面 MUST 占满浏览器高度，不出现整页横向滚动。
- **FR-009**: 桌面宽度下，左侧导航 MUST 固定为 188px，右侧内容区占据剩余空间；导航顶部显示产品名称 mini-workbuddy，可配一个简单的圆形字母标记；导航项高度约 32px，图标、文字和选中背景保持对齐。
- **FR-010**: 左侧菜单 MUST 按固定顺序显示 8 个入口：聊天、Agent 管理、模型管理、工具管理、MCP 管理、Skills 管理、运行记录、Agent 评测。
- **FR-011**: 每个菜单 MUST 有独立地址；默认打开聊天页面；点击菜单后右侧页面正常切换，当前项有选中态；刷新任意地址仍能打开对应页面，不出现空白页。
- **FR-012**: 浏览器宽度小于 900px 时，左侧菜单 MUST 收起为窄栏或抽屉（选一种稳定做法），收起后仍能打开所有菜单，主内容不被菜单遮挡。

**页面与视觉**

- **FR-013**: 右侧页面 MUST 使用统一结构：顶部为页面标题和一句简短说明，下方为内容卡片。
- **FR-014**: 占位页面 MUST 写明"本模块将在后续阶段开发"，并告诉使用者当前阶段先完成什么；不得出现虚构的统计数字、对话和列表。
- **FR-015**: 颜色 MUST 集中定义为全局 CSS 变量并统一引用（含背景层级 `--bg-deep/--bg-base/--bg-surface/--bg-hover/--bg-active`、边框三级、主色 `--accent` 系、文本四级、语义色 success/warning/danger），各色块按约定用途使用，不得在页面内写相近色。
- **FR-016**: 字体 MUST 集中定义为变量：正文 `--font-body`（DM Sans 优先）、标题与产品名 `--font-display`（Outfit 优先）、代码命令日志 `--font-mono`（Fira Code 优先）；网络字体不可用时依次回退系统字体，不因加载失败导致页面不可用。
- **FR-017**: 字号 MUST 遵循规格：页面主标题 18px/字重 650；卡片标题 14–15px/600；正文和表单 12.5px；按钮和菜单文字 12–12.5px；辅助说明与时间 10.5–11.5px；代码和命令 12px；正文行高 1.5；不使用 32px 以上的大标题。
- **FR-018**: 页面 MUST NOT 出现蓝紫渐变、霓虹光效、大面积纯黑背景和高饱和荧光色；阴影保持很轻且只用于弹窗和浮层；卡片依靠白色背景和浅色边框区分。

**开发规范文档**

- **FR-019**: 根目录 `AGENTS.md` MUST 补充完善，写清项目名称、固定技术栈、前后端目录、常用启动和测试命令、Python 必须使用 uv 的规则、数据库迁移方式、配色与字号入口、每次修改后需要运行的前后端检查，并包含前后端开发规范；后续约定变化只更新该文件。

### Key Entities

本阶段不涉及业务数据实体（无业务表）；唯一持久化产物为 SQLite 数据库与 Alembic 基线迁移，业务实体将在后续各模块的 spec 中定义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 开发者在一台仅装有 Node.js 与 uv 的干净机器上，仅依据仓库内文档（README / AGENTS.md）在 30 分钟内完成依赖安装并把前后端同时启动起来。
- **SC-002**: 8 个菜单页面 100% 可通过点击与直接输入地址两种方式访问；对全部 8 个地址执行刷新，0 次出现空白页。
- **SC-003**: 质量检查全部通过：前端 `npm run build` 零错误、Vitest 全部通过；后端 `uv run pytest` 全部通过、pyright 无错误。
- **SC-004**: 视觉抽查通过：全部页面与导航的颜色、字体、字号 100% 引用全局 CSS 变量/规格，无散落硬编码相近色，无禁用视觉元素（蓝紫渐变、霓虹光效、大面积纯黑、高饱和荧光色）。
- **SC-005**: 在 360px–1920px 范围内拖动浏览器宽度：整页无横向滚动；<900px 时菜单收起且 8 个入口全部可达、主内容不被遮挡。
- **SC-006**: 数据库迁移可重复执行：全新环境执行迁移命令成功生成 SQLite 数据库与基线结构，重复执行不报错。
- **SC-007**: 工程内不存在无业务内容的空文件/空目录（除文档声明保留者），占位页面数量与模块数量一致（8 个入口均可达对应页面）。

## Assumptions

- 第一阶段不含任何业务功能：聊天页与其他 7 个模块均为占位页面，业务功能在后续阶段逐模块开发。
- SQLite 数据库本阶段仅建立连接与基线迁移，无业务表；后端接口层仅提供健康检查等最小入口，不预建无消费方的业务目录。
- 目标使用平台为桌面浏览器；移动浏览器非目标平台，但宽度低至约 360px 时布局仍需可用（不横向滚动、菜单可达）。
- 窄屏收起方案（窄栏 vs 抽屉）由实现阶段选定一种稳定做法即可，两种均符合需求。
- 网络字体的具体引入方式（自托管包或本地回退）由实现阶段决定，但必须满足"字体不可用时页面仍可用"的回退要求。
- 开发环境为 Windows；命令以跨平台可用为准（后端命令统一通过 `uv run` 执行）。
- `0user chat/` 目录由用户主动维护，任何自动化流程不得写入或修改。
- 仓库当前尚未启用 git；`AGENTS.md` 中的命令与检查清单不依赖 git 工作流（后续启用 git 时再补充相关约定）。
