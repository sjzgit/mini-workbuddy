## User Scenarios & Testing *(mandatory)*

### User Story 1 - Skills 列表与手动刷新 (Priority: P1)

使用者进入"Skills 管理"页面后，看到当前项目所有 Skill 组成的列表，每行展示：名称、简短说明、启用状态和更新时间，并提供导入、编辑、删除、启用、停用和手动刷新操作入口。Skill 统一保存在项目的 workspace/skills 目录下，每个 Skill 使用独立目录；使用者也可以直接在该目录下手动创建 Skill，点击页面上的刷新按钮后，系统重新扫描目录并更新列表，无需重启服务。目录为空或尚无任何 Skill 时，页面展示空状态，而不是空白列表或报错。

**Why this priority**: 列表是 Skills 管理的入口视图，"目录扫描 + 手动刷新"是本功能区别于普通配置管理的核心机制（Skill 以文件为本，页面是文件的视图）；后续编辑、启停、导入操作都建立在列表之上。

**Independent Test**: 在 workspace/skills 下手动创建一个合规的 Skill 目录，点击刷新按钮，核对它出现在列表中且名称、说明、更新时间正确，全程无需重启服务；清空目录后刷新，核对出现空状态。

**Acceptance Scenarios**:

1. **Given** workspace/skills 下已存在若干 Skill， **When** 使用者打开 Skills 管理页面， **Then** 列表完整展示每个 Skill 的名称、简短说明、启用状态和更新时间。
2. **Given** 使用者在 workspace/skills 目录下手动创建了一个新的 Skill 目录， **When** 点击页面上的刷新按钮， **Then** 列表更新并包含该 Skill，无需重启服务。
3. **Given** workspace/skills 目录为空或不存在任何 Skill， **When** 使用者打开 Skills 管理页面， **Then** 页面展示空状态，不出现报错或残缺列表。

---

### User Story 2 - Skill 编辑与文件同步 (Priority: P1)

使用者点击列表中的编辑入口后进入编辑页，页面提供三个主要区域：名称、用途说明和详细指令。详细指令支持 Markdown，输入区域适合编辑较长内容。保存后，修改同步写入对应的 Skill 文件，列表中的信息和更新时间随之更新；再次刷新或重启服务后，内容与保存时一致。

**Why this priority**: 编辑是 Skill 生命周期中最频繁的操作，"页面修改 ↔ 文件同步写回"保证文件始终是唯一事实来源，与手动维护目录的工作流兼容，属于最小可用集。

**Independent Test**: 打开某 Skill 的编辑页，修改名称与用途说明、在详细指令中编辑一段较长 Markdown 内容并保存，核对列表信息与更新时间已更新；直接查看磁盘上的 Skill 文件，核对内容与页面保存一致；刷新页面后核对内容未被还原。

**Acceptance Scenarios**:

1. **Given** 使用者打开某 Skill 的编辑页， **When** 页面加载完成， **Then** 名称、用途说明、详细指令三个区域展示该 Skill 的当前内容。
2. **Given** 使用者在编辑页修改了名称、用途说明并在详细指令区域编辑了长篇 Markdown 内容， **When** 点击保存， **Then** 保存成功后对应的 Skill 文件被同步更新，列表中的信息与更新时间随之刷新。
3. **Given** 一次已保存的编辑， **When** 使用者刷新页面或重启服务后再次查看， **Then** 页面内容与保存时完全一致。

### User Story 3 - Skill 启停与删除 (Priority: P1)

使用者可以对任意 Skill 执行启用或停用，启用状态持久化保存，刷新页面或重启服务后仍然保留。停用后，Skill 文件继续保留在磁盘上，但不再提供给 Agent 使用。删除前需要使用者确认，确认后系统删除对应的 Skill 目录并更新列表。

**Why this priority**: 启停是使用者控制 Agent 可用能力边界的核心手段（与已交付的工具启停一致），删除则是目录管理的完备操作；两者共同保证"文件保留"与"Agent 可用性"可以独立控制。

**Independent Test**: 停用某 Skill 后刷新页面并重启服务，核对状态仍为停用、磁盘上文件仍在、该 Skill 已不在提供给 Agent 的启用集合中；对某 Skill 执行删除并确认，核对列表更新且对应目录已从磁盘移除；取消删除确认时核对文件未被动过。

**Acceptance Scenarios**:

1. **Given** 某 Skill 处于启用状态， **When** 使用者执行停用， **Then** 列表状态更新为停用，Skill 文件继续保留在磁盘上，但该 Skill 不再提供给 Agent 使用。
2. **Given** 某 Skill 已停用， **When** 使用者刷新页面并重启服务， **Then** 启用状态仍保持为停用。
3. **Given** 使用者对某 Skill 点击删除， **When** 在确认对话中确认删除， **Then** 对应的 Skill 目录被删除且列表即时更新。
4. **Given** 使用者对某 Skill 点击删除， **When** 在确认对话中取消， **Then** 该 Skill 及其文件保持不变。

---

### User Story 4 - Skill ZIP 导入 (Priority: P2)

使用者可以通过上传 ZIP 文件导入 Skill。导入时系统检查 ZIP 内的文件结构和必要内容，将符合要求的 Skill 解压到 workspace/skills 目录下并更新列表。导入失败时明确提示原因。同名 Skill 已存在时不得直接覆盖已有内容。解压时校验文件路径，确保文件不会写入目标目录之外。

**Why this priority**: 导入是分发与复用 Skill 的便捷途径，但手动放置目录 + 刷新（User Story 1）已能达成同等结果，故作为增强能力放在核心闭环之后交付。

**Independent Test**: 准备一个结构合规的 Skill ZIP 上传导入，核对解压到 workspace/skills、列表更新；再分别上传损坏的 ZIP、缺少必要内容的 ZIP、与现有 Skill 同名的 ZIP、包含 `..` 路径片段的 ZIP，核对四类场景均被拒绝且提示明确原因、原目录内容未被覆盖或破坏。

**Acceptance Scenarios**:

1. **Given** 一个文件结构与必要内容均合规的 Skill ZIP， **When** 使用者上传并导入， **Then** Skill 被解压到 workspace/skills 目录下，列表更新并包含该 Skill。
2. **Given** 一个损坏或缺少必要内容的 ZIP， **When** 使用者尝试导入， **Then** 导入失败并明确提示失败原因。
3. **Given** workspace/skills 下已存在同名 Skill， **When** 使用者导入同名 Skill 的 ZIP， **Then** 导入被拒绝并提示同名冲突，已有内容未被覆盖。
4. **Given** ZIP 内包含 `..` 等可逃逸目标目录的路径， **When** 使用者尝试导入， **Then** 解压被拒绝，没有任何文件写入目标目录之外。

### User Story 5 - MCP Server 配置管理 (Priority: P1)

使用者进入"MCP 管理"页面后，看到 MCP Server 列表，每行展示：服务器名称、说明、类型、最近一次测试结果，以及最近一次成功测试发现的工具数量（点击后弹窗展示具体工具列表）；尚未测试时明确显示"未测试"，工具数量显示为"未知"。使用者可以新增、编辑、删除、启用、停用和测试连接，删除前需要确认。

新增和编辑页提供名称、说明、类型三个基础字段；类型支持本机启动和远程 HTTP（暂不支持 OAuth 和账号授权）。选择本机启动时展示 stdio 通信相关字段：启动命令、启动参数（以列表形式填写，保留顺序）、环境变量（可选，键值对）；选择远程 HTTP 时展示：url 和可自定义添加多个的请求 Header。页面为这些字段提供简短说明和填写示例，告知用户配置通常可以从 MCP Server 的使用说明中获取，无需理解协议细节。

启动命令和参数分开保存、直接传给进程，不得拼接成 Shell 命令执行。配置和启用状态持久化，刷新页面或重启服务后仍然保留。环境变量的值可能包含密钥等敏感信息：保存后以掩码展示，不出现在列表、日志、错误信息或测试结果中；编辑时允许保留或替换已有值，不会把掩码当作实际值保存。

**Why this priority**: 配置管理是 MCP 功能的基础——没有录入配置就没有测试与启停的对象；敏感信息掩码与"命令参数分离"是用户明确的安全底线，必须随配置能力同批交付。

**Independent Test**: 分别新增一个本机启动型和一个远程 HTTP 型 Server，按字段说明填写并保存，核对列表展示名称、说明、类型、"未测试"与工具数"未知"；编辑本机启动型 Server 填写含特殊字符的环境变量并保存，核对列表与任何返回信息中只见掩码不见原文，重新进入编辑页选择保留原值再保存后测试仍可用该值；核对刷新与重启后配置与启用状态保留；对删除操作确认与取消两个分支分别验证。

**Acceptance Scenarios**:

1. **Given** 使用者打开 MCP 管理页面， **When** 页面加载完成， **Then** 列表展示每个 Server 的名称、说明、类型、最近一次测试结果与最近一次成功测试发现的工具数量；尚未测试的 Server 明确显示"未测试"、工具数量显示"未知"。
2. **Given** 列表中某 Server 存在最近一次成功测试发现的工具数量， **When** 使用者点击该数量， **Then** 弹窗展示具体工具列表。
3. **Given** 使用者新增 Server 并选择"本机启动"类型， **When** 填写名称、说明、启动命令、启动参数列表与环境变量后保存， **Then** 保存成功，命令与参数作为独立字段分别保存，配置出现在列表中。
4. **Given** 使用者新增 Server 并选择"远程 HTTP"类型， **When** 填写名称、说明、url 与若干请求 Header 后保存， **Then** 保存成功且配置出现在列表中。
5. **Given** 使用者处于新增或编辑页， **When** 查看任一字段， **Then** 旁边有简短说明和填写示例，说明这些配置通常可从 MCP Server 的使用说明中获取。
6. **Given** 某已配置的 Server 含环境变量等敏感值， **When** 配置保存后查看列表、日志、错误信息或测试结果， **Then** 敏感值只以掩码形式出现，完整原文不暴露。
7. **Given** 使用者编辑一个已设置环境变量的 Server， **When** 选择保留已有值并保存， **Then** 实际保存的是原有值而非掩码文本，该 Server 后续使用该值仍可正常工作。
8. **Given** 使用者已保存 Server 配置， **When** 刷新页面并重启服务， **Then** 配置与启用状态完整保留。
9. **Given** 使用者对某 Server 点击删除， **When** 在确认对话中确认， **Then** 该 Server 被删除且列表即时更新；**When** 取消确认， **Then** 该 Server 保持不变。
10. **Given** 任一 Server 的启动命令与参数配置， **When** 系统启动该 Server 进程， **Then** 命令与参数按独立字段直接传给进程，不经过 Shell 拼接执行。

### User Story 6 - MCP 测试连接 (Priority: P1)

使用者点击"测试连接"后，系统实际启动 MCP Server，完成协议初始化并读取工具列表，测试结束后正常关闭连接并清理进程；测试仅发现工具，不执行任何工具。

测试成功时，展示工具数量，以及每个工具的名称、用途和参数说明（包括参数类型、是否必填等信息）；Server 未提供工具时显示"连接成功，未发现工具"。测试失败时，根据实际错误尽量区分以下情况并给出便于理解的提示：启动命令不存在、程序启动失败或提前退出、连接或读取工具超时、协议版本或响应格式不兼容、Server 主动返回错误、连接失败；无法确定原因时明确提示未知错误，并提供经过敏感信息脱敏的诊断信息。测试过程中显示进行状态、禁止重复提交；同一个 Server 不允许同时进行多次测试；无论成功、失败还是超时，都清理测试进程，避免后台残留。

**Why this priority**: 测试连接是 MCP 管理的核心价值——使用者在启用前先验证配置真实可用、直观看到 Server 提供哪些工具；进程安全（只发现不执行、无残留）是用户明确的安全底线，与配置管理共同构成最小可用集。

**Independent Test**: 对一个配置正确的本机启动型 Server 点击测试连接，核对展示工具数量与每个工具的名称、用途、参数类型与是否必填，测试结束后系统无残留进程；对一个不提供工具的 Server 测试，核对显示"连接成功，未发现工具"；分别构造启动命令不存在、程序启动即退出、连接超时、协议不兼容、Server 返回错误、连接失败六类失败场景，核对提示能正确区分且可理解；测试进行中重复点击测试按钮，核对被禁止；测试结束后核对后台无残留进程。

**Acceptance Scenarios**:

1. **Given** 一个配置正确且提供工具的 MCP Server， **When** 使用者点击"测试连接"， **Then** 测试完成后展示发现的工具数量，以及每个工具的名称、用途和参数说明（含参数类型、是否必填）。
2. **Given** 一个连接成功但不提供任何工具的 MCP Server， **When** 使用者点击"测试连接"， **Then** 显示"连接成功，未发现工具"。
3. **Given** 配置的启动命令在当前系统上不存在， **When** 使用者点击"测试连接"， **Then** 测试失败并提示"启动命令不存在"类可理解原因。
4. **Given** Server 程序启动失败或启动后立即退出， **When** 使用者点击"测试连接"， **Then** 测试失败并提示"程序启动失败或提前退出"类可理解原因。
5. **Given** Server 启动后长时间不完成协议初始化或工具读取， **When** 超过测试时限， **Then** 测试以超时失败结束并给出可理解提示。
6. **Given** Server 使用的协议版本或响应格式与系统不兼容， **When** 使用者点击"测试连接"， **Then** 测试失败并提示"协议版本或响应格式不兼容"类可理解原因。
7. **Given** Server 在协议交互中主动返回错误， **When** 使用者点击"测试连接"， **Then** 测试失败并展示 Server 返回的错误信息。
8. **Given** 远程 HTTP 型 Server 的地址无法连通， **When** 使用者点击"测试连接"， **Then** 测试失败并提示"连接失败"类可理解原因。
9. **Given** 测试失败且无法归入以上各类原因， **When** 测试结束， **Then** 明确提示未知错误，并附敏感信息已脱敏的诊断信息。
10. **Given** 某 Server 的测试正在进行， **When** 使用者再次点击该 Server 的"测试连接"， **Then** 请求被拒绝，同一 Server 不会同时进行多次测试。
11. **Given** 任一次测试结束（无论成功、失败还是超时）， **When** 查看系统进程， **Then** 测试启动的 Server 进程与连接均已被清理，无后台残留。
12. **Given** 任一次测试连接过程， **When** 测试进行中， **Then** 页面显示进行状态且测试入口禁止重复提交。

### User Story 7 - MCP 启停与测试结果有效性 (Priority: P2)

启用状态决定该 Server 是否可供 Agent 使用。"测试连接"是独立操作：停用状态下也可以测试，测试成功不会自动启用。修改启动命令、参数或环境变量后，原测试结果标记为"配置已变更，待重新测试"，避免将旧结果误认为当前配置的验证结果。

**Why this priority**: 启停控制与"测试结果跟随配置版本"防止误判，属于管理闭环的完善项；在配置与测试能力（P1）交付后再补齐，不影响最小可用集。

**Independent Test**: 停用某 Server 后点击测试连接，核对测试可以执行且成功后启用状态仍为停用；对已测试成功的 Server 修改启动参数，核对其最近测试结果变为"配置已变更，待重新测试"，重新测试成功后恢复为成功状态。

**Acceptance Scenarios**:

1. **Given** 某 Server 处于停用状态， **When** 使用者点击"测试连接"， **Then** 测试正常执行；测试成功后该 Server 的启用状态仍为停用。
2. **Given** 某 Server 存在最近一次测试结果， **When** 使用者修改其启动命令、启动参数或环境变量并保存， **Then** 该 Server 的最近测试结果标记为"配置已变更，待重新测试"。
3. **Given** 某 Server 的测试结果已被标记为"配置已变更，待重新测试"， **When** 使用者重新测试成功， **Then** 测试结果更新为最新一次的结果。
4. **Given** 某 Server 处于启用状态， **When** 使用者执行停用， **Then** 该 Server 不再提供给 Agent 使用；重新启用后恢复。

### Edge Cases

- workspace/skills 目录为空或不存在时打开 Skills 管理页怎么办？—— 展示空状态，页面不报错；目录后续被手动创建后再刷新即可发现内容。
- 手动刷新时目录中存在结构不合规的 Skill（缺少必要内容）怎么办？—— 跳过该目录不纳入列表，并给出可发现的提示，不影响其他合规 Skill 的展示。
- 编辑保存时对应的 Skill 文件已被外部修改或删除怎么办？—— 保存失败并给出明确错误提示，不静默覆盖外部修改。
- ZIP 文件损坏或不是有效压缩包怎么办？—— 导入失败并提示明确原因。
- ZIP 内部结构与 Skill 必要内容要求不符怎么办？—— 导入失败并指出缺失或不符合的内容。
- ZIP 解压目标已存在同名 Skill 怎么办？—— 拒绝导入并提示同名冲突，已有内容不被覆盖。
- ZIP 中包含 `..` 路径片段或绝对路径等可逃逸目标目录的条目怎么办？—— 拒绝解压，任何文件不写入目标目录之外。
- 删除 Skill 时目录被外部程序占用导致无法删除怎么办？—— 删除失败并给出明确错误提示，列表状态与磁盘实际保持一致。
- MCP Server 的启动参数为空列表怎么办？—— 视为无参数，按仅命令启动。
- 环境变量的值包含特殊字符或非常长怎么办？—— 原样保存与传给进程，掩码展示规则不受影响。
- 使用者在编辑页直接提交掩码文本作为环境变量值怎么办？—— 系统识别掩码占位语义，不把掩码当作实际值保存（保留原值或按明确替换处理）。
- HTTP 类型 Server 的 url 填写格式非法怎么办？—— 保存时校验并提示格式问题。
- 测试连接期间 Server 挂起无响应怎么办？—— 有测试超时上限，超时按失败返回可理解提示。
- 测试超时或失败后 Server 进程未自行退出怎么办？—— 系统强制清理测试启动的进程，保证无后台残留。
- 多个页面/入口同时对同一 Server 发起测试怎么办？—— 后续请求被拒绝，同一 Server 同时只有一次测试。
- 不同 Server 同时测试怎么办？—— 各自独立执行、互不影响。
- Server 返回数量很多的工具怎么办？—— 弹窗完整展示列表，可滚动浏览，不截断信息。
- 修改了配置但尚未重新测试时查看列表怎么办？—— 该 Server 显示"配置已变更，待重新测试"，不显示旧结果作为当前依据。
- 删除一个正在测试中的 Server 怎么办？—— 需先完成或终止测试再删除，删除入口在测试进行中不可用。
- 后端重启后 Skills 启停状态与 MCP 配置、启用状态怎么办？—— 全部持久化，重启后保持。

## Requirements *(mandatory)*

### Functional Requirements

**Skills 列表与目录扫描**

- **FR-001**: 系统 MUST 提供"Skills 管理"页面，以列表展示所有 Skill，每行包含名称、简短说明、启用状态和更新时间，并提供导入、编辑、删除、启用、停用和手动刷新操作。
- **FR-002**: Skill MUST 统一保存在当前项目的 workspace/skills 目录下，每个 Skill 使用独立目录。
- **FR-003**: 点击手动刷新后，系统 MUST 重新扫描目录并更新列表，无需重启服务；用户在目录下手动创建的 Skill MUST 能被发现。
- **FR-004**: workspace/skills 中不存在任何合规 Skill 时，页面 MUST 展示空状态，不出现报错或残缺列表。
- **FR-005**: 目录扫描遇到结构不合规的 Skill 目录时 MUST 跳过该目录并给出可发现的提示，MUST NOT 影响其他合规 Skill 的展示。

**Skill ZIP 导入**

- **FR-006**: 系统 MUST 支持通过 ZIP 文件导入 Skill：导入时检查文件结构和必要内容，将符合要求的 Skill 解压到 workspace/skills 目录下并更新列表。
- **FR-007**: 导入失败时 MUST 明确提示原因（文件损坏、结构不符、同名冲突等）。
- **FR-008**: 目标目录下已存在同名 Skill 时 MUST NOT 直接覆盖已有内容，MUST 拒绝导入并提示冲突。
- **FR-009**: 解压时 MUST 校验文件路径，确保文件不会写入目标目录之外（含 `..` 路径片段、绝对路径等形式的逃逸）。

**Skill 编辑与生命周期**

- **FR-010**: 编辑页 MUST 提供名称、用途说明和详细指令三个主要区域；详细指令 MUST 支持 Markdown，输入区域 MUST 适合编辑较长内容。
- **FR-011**: 保存后，修改 MUST 同步写入对应的 Skill 文件，并更新列表中的信息和更新时间。
- **FR-012**: Skill 的启用状态 MUST 持久化保存，刷新页面或重启服务后仍然保留。
- **FR-013**: Skill 停用后，文件 MUST 继续保留，但 MUST NOT 再提供给 Agent 使用。
- **FR-014**: 删除 Skill 前 MUST 要求用户确认；确认后 MUST 删除对应的 Skill 目录并更新列表。

**MCP 列表与配置**

- **FR-015**: 系统 MUST 提供"MCP 管理"页面，以列表展示每个 Server 的名称、说明、类型、最近一次测试结果，以及最近一次成功测试发现的工具数量；尚未测试时 MUST 明确显示"未测试"，工具数量显示为"未知"。
- **FR-016**: 点击工具数量 MUST 以弹窗展示具体工具列表。
- **FR-017**: 用户 MUST 能对 Server 执行新增、编辑、删除、启用、停用和测试连接；删除前 MUST 要求确认。
- **FR-018**: 系统 MUST 支持两类 MCP Server：本机启动（通过 stdio 通信）与远程 HTTP；本版本 MUST NOT 支持 OAuth 和账号授权。
- **FR-019**: 新增和编辑页 MUST 提供以下字段：名称、说明、类型；本机启动型 MUST 提供启动命令、启动参数（以列表形式填写、保留参数顺序）和可选的环境变量（键值对）；远程 HTTP 型 MUST 提供 url 和可自定义添加多个的请求 Header。
- **FR-020**: 新增和编辑页 MUST 为各字段提供简短说明和填写示例，告知用户这些配置通常可以从 MCP Server 的使用说明中获取，无需理解协议细节。
- **FR-021**: 启动命令和启动参数 MUST 分开保存、直接传给进程，MUST NOT 拼接成 Shell 命令执行。
- **FR-022**: Server 配置和启用状态 MUST 持久化，刷新页面或重启服务后仍然保留。

**敏感信息保护**

- **FR-023**: 环境变量的值保存后 MUST 以掩码展示；列表、日志、错误信息和测试结果 MUST NOT 暴露完整原文。
- **FR-024**: 编辑时 MUST 允许保留或替换已有值；系统 MUST NOT 将掩码作为实际值保存。

**MCP 测试连接**

- **FR-025**: 点击"测试连接"后，系统 MUST 实际启动 MCP Server，完成协议初始化并读取工具列表；测试结束后 MUST 正常关闭连接并清理进程。
- **FR-026**: 测试 MUST 仅发现工具，MUST NOT 执行任何工具。
- **FR-027**: 测试成功时 MUST 展示工具数量，以及每个工具的名称、用途和参数说明（包括参数类型、是否必填等信息）；Server 未提供工具时 MUST 显示"连接成功，未发现工具"。
- **FR-028**: 测试失败时 MUST 根据实际错误尽量区分以下情况并给出便于理解的提示：启动命令不存在、程序启动失败或提前退出、连接或读取工具超时、协议版本或响应格式不兼容、Server 主动返回错误、连接失败。
- **FR-029**: 无法确定失败原因时 MUST 明确提示未知错误，并提供经过敏感信息脱敏的诊断信息。
- **FR-030**: 测试过程中 MUST 显示进行状态并禁止重复提交；同一个 Server MUST NOT 同时进行多次测试。
- **FR-031**: 无论测试成功、失败还是超时，系统 MUST 清理测试启动的进程，MUST NOT 产生后台残留进程。

**MCP 启停与结果有效性**

- **FR-032**: Server 的启用状态 MUST 决定该 Server 是否可供 Agent 使用。
- **FR-033**: "测试连接" MUST 是独立操作：停用状态下也可以测试，测试成功 MUST NOT 自动启用。
- **FR-034**: 修改启动命令、启动参数或环境变量并保存后，原测试结果 MUST 标记为"配置已变更，待重新测试"。

**页面一致性**

- **FR-035**: Skills 管理与 MCP 管理页面的配色、字号、布局和交互方式 MUST 与已有管理页面保持一致。

### Key Entities

- **Skill（技能）**: 一份供 Agent 阅读的任务说明，描述处理某类任务时需要遵守的步骤、输出格式和限制；本身不执行代码、不直接调用工具。属性：名称、简短说明、详细指令（Markdown）、启用状态、更新时间、所在目录。生命周期：手动创建或 ZIP 导入 → 编辑 → 启用/停用 → 删除。
- **Skill 文件存储（workspace/skills 目录）**: Skill 内容的唯一事实来源；每个 Skill 一个独立目录，页面列表是该目录的视图，手动刷新触发重新扫描。
- **MCP Server 配置（MCP Server Configuration）**: 一项外部工具来源的连接配置。属性：名称、说明、类型（本机启动 / 远程 HTTP）、启动命令、启动参数（有序列表）、环境变量（键值对，值可能敏感）、url、请求 Header（多个）、启用状态。
- **MCP 测试结果（MCP Test Result）**: 最近一次"测试连接"的记录。属性：结果状态（成功 / 各类失败 / 未知错误）、失败原因分类与可理解提示、脱敏诊断信息、发现的工具数量与工具列表（成功时）、测试时间、是否因配置变更而失效（"配置已变更，待重新测试"）。
- **MCP 工具信息（MCP Tool Info）**: 测试连接发现的单个工具描述。属性：工具名称、用途、参数说明列表（每个参数的名称、类型、是否必填、含义）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 workspace/skills 下手动创建的合规 Skill，点击刷新按钮后 100% 出现在列表中且信息正确，全程无需重启服务。
- **SC-002**: Skill 编辑保存后，页面内容与磁盘上 Skill 文件的一致率为 100%，列表更新时间 100% 刷新；刷新与重启后内容 100% 保留。
- **SC-003**: 在"同名冲突、路径逃逸、结构不符、文件损坏"四类非法 ZIP 导入测试中，拒绝率 100% 且每次均提示明确原因，已有目录内容零破坏；合规 ZIP 导入成功率 100%。
- **SC-004**: Skill 与 MCP Server 的启用状态在页面刷新与服务重启后 100% 保留；MCP 配置（含启动命令、参数、环境变量、url、Header）重启后 100% 保留。
- **SC-005**: 在列表、日志、错误信息和测试结果的全部抽样检查中，敏感环境变量值完整原文出现次数为 0，仅以掩码形式出现。
- **SC-006**: 覆盖"命令不存在、启动失败或提前退出、超时、协议不兼容、Server 返回错误、连接失败"六类失败场景的测试集中，原因区分正确率 100%，每次均返回便于理解的提示。
- **SC-007**: 任一次测试连接（成功、失败、超时）结束后，系统残留的测试进程数为 0。
- **SC-008**: 测试成功的 Server 100% 展示工具数量与每个工具的名称、用途、参数类型、是否必填；无工具 Server 100% 显示"连接成功，未发现工具"。
- **SC-009**: 配置变更（命令/参数/环境变量）后，原测试结果 100% 即时标记"配置已变更，待重新测试"；停用状态下测试可正常执行且成功后零例自动启用。

## Assumptions

- Skill 目录内部的文件组织（说明文件的命名、名称/说明/指令如何承载）由 Plan 阶段定义，遵循"一个目录一个 Skill、含一份可供 Agent 阅读的说明文件"的原则；本 spec 只约束页面可见字段与目录级管理行为。
- "提供给 Agent 使用"的消费方（Agent Loop）属于后续阶段；本阶段交付完整管理能力，并保证停用 Skill 与停用 Server 在数据层面即时从"可供 Agent 使用的启用集合"中移除，供后续阶段直接消费。
- "结构不合规 Skill"的具体判定标准（必要文件与必要字段）由 Plan 阶段定义，并在导入失败提示与刷新提示中保持同一口径。
- ZIP 导入第一版仅支持 ZIP 格式，且假定单个 ZIP 对应一个 Skill；解压安全采用"逐条目路径解析后必须落在目标目录内"的校验策略。
- 测试连接的超时上限、并发策略细节由 Plan 阶段确定，并需在界面或使用说明中对使用者明示。
- MCP 协议初始化与工具发现遵循业界标准 MCP 协议的 stdio 与远程 HTTP 传输方式；本阶段不支持 OAuth 与账号授权，需要鉴权的远程 Server 暂不在范围内。
- 环境变量掩码的具体形式（如保留前几位或统一占位符）由 Plan 阶段结合项目已有的敏感信息处理机制确定；"编辑时保留原值"通过明确的选择操作表达，不依赖猜测。
- workspace/skills 目录的具体位置由 Plan 阶段的系统配置设计确定。
- 本产品为单机本地部署、单用户使用，不处理多用户权限；跨页面的同 Server 并发测试按"拒绝第二次请求"处理。
