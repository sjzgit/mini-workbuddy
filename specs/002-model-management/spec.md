**Feature Branch**: `002-model-management`

**Created**: 2026-09-10

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 模型列表与空状态 (Priority: P1)

使用者进入"模型管理"页面后，看到已添加模型组成的列表，每行展示：显示名称、请求使用的模型标识、服务地址、上下文长度、密钥配置状态（已配置/未配置）、是否为默认模型和最后更新时间。列表对每个模型提供新增、编辑、删除、测试连接和设置默认模型的操作入口。当系统中还没有任何模型时，页面展示空状态并提供"添加模型"入口，而不是空白表格或报错。

**Why this priority**: 列表是模型管理的入口视图，空状态保证首次使用者有明确引导；所有其他操作都从列表或其入口发起。

**Independent Test**: 添加 2-3 个模型后打开页面，核对列表各列信息完整正确；删除全部模型后刷新，验证回到带添加入口的空状态。

**Acceptance Scenarios**:

1. **Given** 系统中已有若干模型， **When** 使用者打开模型管理页面， **Then** 列表完整展示每个模型的显示名称、模型标识、服务地址、上下文长度、密钥配置状态、是否默认和最后更新时间。
2. **Given** 系统中没有任何模型， **When** 使用者打开模型管理页面， **Then** 页面展示空状态与添加入口，不出现报错或残缺表格。
3. **Given** 列表中存在模型， **When** 使用者查看某一行的操作， **Then** 可对该模型发起编辑、删除、测试连接和设置默认模型。

---

### User Story 2 - 新增与编辑模型配置 (Priority: P1)

使用者通过新增/编辑表单维护模型配置。表单提供以下配置项：显示名称（页面中识别模型）、模型标识（请求时使用的名称，需与服务商一致）、服务地址（API Base URL）、API Key、上下文长度（token）、最大输出长度（token）、温度、输入单价（元/百万输入 token）、输出单价（元/百万输出 token）、缓存命中输入单价（元/百万缓存命中输入 token）。每个字段配有清晰的填写说明；预填默认值明确标注为"建议值"，并说明上下文长度、输出限制与价格以服务商说明为准，示例值不作为模型实际参数。服务地址提供示例说明是否需要包含 /v1，引导填写 Base URL 而非完整 /chat/completions 地址。保存前系统校验必填项、服务地址格式和数字范围：上下文长度与最大输出长度必须为正整数且最大输出不超过上下文长度；温度按所支持接口的范围校验；价格不得为负数，未填写与为零含义不同。校验失败时在对应字段旁说明原因。

**Why this priority**: 配置的准确录入是后续一切模型调用（测试连接、聊天、计费）的基础；字段说明与校验直接决定录入质量和使用者对成本、能力参数的理解。

**Independent Test**: 依次提交合法表单与各类非法表单（缺必填、服务地址格式错误、最大输出大于上下文、温度越界、价格为负），验证合法者保存成功、非法者在对应字段旁收到明确原因。

**Acceptance Scenarios**:

1. **Given** 使用者在新增页填写全部合法配置， **When** 保存， **Then** 模型保存成功并在列表中可见。
2. **Given** 某必填项为空、服务地址格式不合法或数字超出范围， **When** 保存， **Then** 保存被拒绝，对应字段旁显示具体原因。
3. **Given** 最大输出长度大于上下文长度， **When** 保存， **Then** 校验失败并在字段旁说明原因。
4. **Given** 使用者未填写某价格字段，或填写 0， **When** 分别保存， **Then** 系统区分"未配置价格"与"免费（0）"两种状态。
5. **Given** 使用者首次打开表单， **When** 浏览各字段， **Then** 每个字段有清晰填写说明，预填默认值标注为建议值，并说明上下文长度、输出限制和价格以服务商说明为准。
6. **Given** 使用者填写服务地址， **When** 查看该字段说明， **Then** 有示例说明是否需要包含 /v1，避免误填完整的 /chat/completions 地址。

---

### User Story 3 - 密钥安全保护 (Priority: P1)

使用者提交的 API Key 使用项目认可的本地密钥保存方式存储，不以明文写入普通业务数据表、前端持久化存储或版本库。列表、详情、保存等所有返回前端的接口响应只返回"密钥是否已配置"，不返回密钥正文；日志、错误信息和连接测试结果同样不泄露密钥。编辑模型时，已配置密钥的输入框保持为空并提示"已配置，留空则保留原密钥"；只有用户填写新密钥时才替换，编辑其他字段不会清除原密钥。

**Why this priority**: 密钥是敏感凭据，泄露会造成直接经济损失；保护要求贯穿存储、传输、展示、编辑全链路，必须与基本功能同步交付，不能事后补加。

**Independent Test**: 保存含密钥的模型后，逐一检查列表/详情/保存接口的响应、日志与前端存储，确认密钥正文无处可寻；仅修改显示名称保存后发起测试连接，验证原密钥仍生效。

**Acceptance Scenarios**:

1. **Given** 使用者保存了带 API Key 的模型， **When** 查看列表、详情与保存接口的响应， **Then** 只能看到密钥是否已配置，看不到密钥正文。
2. **Given** 已配置密钥的模型， **When** 使用者打开编辑表单， **Then** 密钥输入框为空并显示"已配置，留空则保留原密钥"。
3. **Given** 已配置密钥的模型， **When** 使用者只修改显示名称并保存， **Then** 原密钥保留，测试连接仍能通过。
4. **Given** 任意操作（保存失败、测试连接失败等）， **When** 查看日志与错误提示， **Then** 不出现密钥正文。
5. **Given** 使用者在编辑时填写了新密钥， **When** 保存后再使用该模型， **Then** 使用的是新密钥。

---

### User Story 4 - 默认模型与删除流程 (Priority: P1)

系统最多只有一个默认模型。保存第一个模型时自动将其设为默认；设置新的默认模型时自动取消旧模型的默认状态。删除普通模型前需要用户确认；删除当前默认模型且还存在其他模型时，先让使用者选择新的默认模型，再完成删除与切换；删除最后一个模型时确认后删除，清除默认模型设置，页面回到空状态。全程保证数据一致性：不出现多个默认模型，默认模型不指向已删除记录。删除模型时同时清理其保存的密钥。

**Why this priority**: 默认模型是后续聊天等功能的统一调用入口，其唯一性与一致性直接影响后续阶段；删除是不可逆操作且涉及密钥清理与默认状态切换，需要严格流程保障。

**Independent Test**: 按顺序执行"保存首个模型自动设默认 → 切换默认到另一模型 → 删除普通模型 → 删除默认模型（先选新默认）→ 删除最后一个模型"，每步核对列表展示与默认状态。

**Acceptance Scenarios**:

1. **Given** 系统中没有任何模型， **When** 使用者保存第一个模型， **Then** 该模型自动成为默认模型。
2. **Given** 已有默认模型 A 和其他模型 B， **When** 使用者将 B 设为默认， **Then** B 成为唯一默认模型，A 的默认状态自动取消。
3. **Given** 使用者删除一个非默认模型， **When** 点击删除， **Then** 系统要求确认，确认后完成删除，默认模型不受影响。
4. **Given** 使用者删除当前默认模型且还有其他模型， **When** 点击删除， **Then** 系统先要求选择新的默认模型，选择后才完成删除与默认切换。
5. **Given** 使用者删除最后一个（默认）模型， **When** 确认删除， **Then** 默认设置清除，该模型密钥一并清理，页面回到空状态。
6. **Given** 任意的添加、切换默认、删除操作序列， **When** 每步操作后查看数据， **Then** 任意时刻默认模型数不超过 1，且默认模型始终指向存在的记录。

---

### User Story 5 - 测试连接 (Priority: P2)

使用者点击"测试连接"后，后端使用该模型的完整配置发起一次真实请求。测试过程中显示"正在测试"并禁止重复提交。测试成功时显示"模型已连接"并展示一小段真实回复；失败时根据实际响应尽量区分密钥错误、模型标识错误、服务地址不可访问、请求超时和返回格式异常，提示便于理解并提供必要的排查建议；无法确定原因时如实说明，不展示程序异常或堆栈信息。

**Why this priority**: 测试连接帮助使用者在保存前后验证配置可用性、快速定位填错项，是重要但非阻塞的辅助能力——没有它，模型仍可保存并供后续阶段使用。

**Independent Test**: 分别用正确配置、错误密钥、错误模型标识、不可达地址构造场景，核对各类提示的分类准确性与可理解性；测试进行中连续点击，验证不会重复提交。

**Acceptance Scenarios**:

1. **Given** 一个配置正确的模型， **When** 使用者点击测试连接， **Then** 显示"正在测试"，完成后显示"模型已连接"并展示一小段真实回复。
2. **Given** 测试正在进行， **When** 使用者再次点击测试连接， **Then** 操作被禁止，不会发起第二次请求。
3. **Given** 模型配置了错误的密钥， **When** 测试连接， **Then** 提示指向密钥问题并给出排查建议。
4. **Given** 模型配置了错误的模型标识， **When** 测试连接， **Then** 提示指向模型标识问题并建议核对服务商提供的标识。
5. **Given** 服务地址不可访问或请求超时， **When** 测试连接， **Then** 分别给出地址不可访问或超时的提示与排查建议。
6. **Given** 服务返回了无法识别的内容或无法归类的原因， **When** 测试连接， **Then** 提示返回格式异常或如实说明原因无法确定，不展示程序异常或堆栈。

---

### Edge Cases

- 用户在服务地址中误填了完整的 /chat/completions 路径怎么办？—— 通过字段示例说明引导正确填写；若仍如此保存，测试连接时能给出指向地址写法的可理解提示。
- 最大输出长度填了大于上下文长度的值怎么办？—— 保存校验失败，在字段旁说明原因。
- 三个价格字段只填写了部分（如只填输入单价）怎么办？—— 每个价格字段独立校验与保存，允许部分配置，未填字段表示"未配置价格"。
- 服务地址带末尾斜杠等常见书写差异怎么办？—— 系统做规范化处理，不影响实际调用与测试连接。
- 显示名称或模型标识只填了空白字符怎么办？—— 视为未填写，被必填项校验拦截。
- 测试连接时网络完全不可用或后端正忙怎么办？—— 归入"服务地址不可访问/请求超时"类提示，页面不崩溃、不残留"正在测试"状态。
- 删除模型后密钥是否残留？—— 删除模型时同步清理其保存的密钥。
- 快速连续操作默认模型（设置/删除交错）怎么办？—— 默认模型唯一性与存在性由系统在数据层保证，最终状态一致。

## Requirements *(mandatory)*

### Functional Requirements

**列表与操作入口**

- **FR-001**: 系统 MUST 提供"模型管理"页面，以列表展示所有已配置模型，每行包含显示名称、请求使用的模型标识、服务地址、上下文长度、密钥配置状态、是否为默认模型和最后更新时间。
- **FR-002**: 当系统中不存在任何模型时，系统 MUST 展示空状态并提供添加模型的入口。
- **FR-003**: 列表页 MUST 提供新增、编辑、删除、测试连接和设置默认模型操作。

**表单与校验**

- **FR-004**: 新增/编辑表单 MUST 提供以下配置项：显示名称、模型标识、服务地址、API Key、上下文长度、最大输出长度、温度、输入单价、输出单价、缓存命中输入单价。
- **FR-005**: 表单 MUST 为每个字段提供清晰的填写说明；预填的默认值 MUST 标注为建议值，并说明上下文长度、输出限制与价格以服务商说明为准，示例值不作为模型实际参数。
- **FR-006**: 服务地址字段 MUST 提供填写示例，说明是否需要包含 /v1，引导用户填写 API Base URL 而非完整的 /chat/completions 地址。
- **FR-007**: 保存前系统 MUST 校验：必填项完整、服务地址格式合法、上下文长度与最大输出长度为正整数、最大输出长度不超过上下文长度、温度在所支持接口的范围内、价格不为负数，且未填写价格与价格为零两种状态可区分。
- **FR-008**: 校验失败时，系统 MUST 在对应字段旁说明具体原因，并阻止保存。

**密钥保护**

- **FR-009**: 系统 MUST 使用项目认可的本地密钥保存方式存储 API Key，不得将明文密钥写入普通业务数据表、前端持久化存储或版本库。
- **FR-010**: 列表、详情与保存接口的响应 MUST 只返回密钥是否已配置，不得返回密钥正文；所有返回给前端的数据均不得包含密钥正文。
- **FR-011**: 日志、错误信息和连接测试结果 MUST NOT 泄露密钥正文。
- **FR-012**: 编辑已配置密钥的模型时，密钥输入框 MUST 保持为空并提示"已配置，留空则保留原密钥"；仅当用户填写新密钥时才替换，编辑其他字段 MUST NOT 清除原密钥。

**测试连接**

- **FR-013**: 点击"测试连接"后，系统 MUST 在后端使用该模型的完整配置发起一次真实请求。
- **FR-014**: 测试过程中系统 MUST 显示"正在测试"并禁止重复提交。
- **FR-015**: 测试成功时系统 MUST 显示"模型已连接"并展示一小段真实回复。
- **FR-016**: 测试失败时系统 MUST 根据实际响应尽量区分密钥错误、模型标识错误、服务地址不可访问、请求超时和返回格式异常，给出便于理解的提示和必要的排查建议；无法确定原因时 MUST 如实说明，不得仅展示程序异常或堆栈信息。

**默认模型与删除**

- **FR-017**: 系统 MUST 保证任意时刻最多只有一个默认模型。
- **FR-018**: 保存第一个模型时，系统 MUST 自动将其设为默认模型。
- **FR-019**: 设置新的默认模型时，系统 MUST 自动取消旧模型的默认状态。
- **FR-020**: 删除普通模型前系统 MUST 要求用户确认；删除当前默认模型且仍有其他模型时，MUST 先让用户选择新的默认模型，再完成删除与切换；删除最后一个模型时，MUST 在确认后删除并清除默认模型设置，页面回到空状态。
- **FR-021**: 删除模型时系统 MUST 同时清理其保存的密钥，并保证默认模型不指向已删除的记录。

**数据与页面**

- **FR-022**: 模型配置与默认状态 MUST 持久化，刷新页面或重启服务后仍然保留，密钥配置状态正确展示。
- **FR-023**: 本阶段系统 MUST 只支持兼容 OpenAI Chat Completions 接口的模型服务，所有模型统一使用一套调用逻辑，不为不同厂商分别实现。
- **FR-024**: 模型管理页面的配色、字号、布局和交互方式 MUST 与已有管理页面保持一致。

### Key Entities

- **模型配置（Model Configuration）**: 一条语言模型服务的接入配置。属性：显示名称、模型标识、服务地址、上下文长度（token）、最大输出长度（token）、温度、输入单价（元/百万输入 token）、输出单价（元/百万输出 token）、缓存命中输入单价（元/百万缓存命中输入 token）、是否默认模型、创建时间、最后更新时间。
- **模型密钥（Model Credential）**: 与模型配置一一对应的 API Key，独立于普通业务数据安全保存；对外仅暴露"是否已配置"状态；仅可整体替换，随模型配置删除而一并清理。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者从打开新增表单到成功保存一个模型不超过 3 分钟，且无需查阅外部文档即可理解每个字段的含义与填法。
- **SC-002**: 在覆盖列表、详情、保存、测试连接的全量接口响应与日志检查中，密钥正文出现次数为 0。
- **SC-003**: 在覆盖新增、切换默认、删除普通模型、删除默认模型、删除最后一个模型的全流程测试中，任意时刻默认模型数量不超过 1，且默认模型指向的记录始终存在。
- **SC-004**: 刷新页面并重启服务后，模型列表信息与默认模型状态 100% 保留。
- **SC-005**: 针对密钥错误、模型标识错误、服务地址不可访问、请求超时、返回格式异常五类场景的连接测试中，至少 4 类能给出明确分类提示与排查建议；其余情况如实说明原因，100% 不展示堆栈或原始程序异常。
- **SC-006**: 所有校验失败的提交都能在对应字段旁看到具体原因，使用者据此一次修正后即可保存成功（以新使用者试用验证）。

## Assumptions

- 温度按 OpenAI Chat Completions 通用范围 0–2（含边界）校验，表单预填建议值 0.7，具体范围在字段说明中告知使用者。
- 上下文长度、最大输出长度与价格的预填默认值仅为建议值（如上下文长度 8192、最大输出长度 4096），实际以服务商说明为准；表单明确标注这一点。
- 价格币种为人民币，单位为"元/百万 token"；三个价格字段允许部分填写，未填写表示"未配置价格"，与 0（免费）含义不同。
- "项目认可的本地密钥保存方式"的具体机制（如独立密钥文件、系统凭据库或加密存储）由 Plan 阶段确定，但必须满足本 spec 的全部密钥保护约束（FR-009 ~ FR-012）。
- 本产品为单机本地部署、单用户使用，不处理多用户权限与多人并发编辑冲突；默认模型唯一性与存在性由系统在数据层保证。
- 除"填写新密钥替换"外，本阶段不提供单独的"清除密钥"操作；密钥清理随删除模型完成。
- 服务地址示例按"包含 /v1"与"不包含 /v1"两种形态给出；系统对末尾斜杠等常见书写差异做规范化处理，不影响调用。
- 本阶段只交付模型管理本身；聊天等功能对默认模型的消费属于后续阶段。
