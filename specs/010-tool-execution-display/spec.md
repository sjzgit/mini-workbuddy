# Feature Specification: 工具执行过程展示（第十阶段）

**Feature Branch**: `010-tool-execution-display`

**Created**: 2026-09-15

**Status**: Draft

## Clarifications

### Session 2026-09-15

- Q: 本阶段是否实现运行记录持久化（每轮 LLM 调用输入输出、工具调用与结果的存储）？ → A: 不实现。维持范围排除：本阶段仅页面内实时展示与内存态保留，运行记录持久化（含每轮 LLM 输入输出与工具明细）整体留给后续"运行记录"阶段，沿用 009 阶段 FR-007 的禁令。
- Q: 生成过程中切换到其他会话时，正在进行的运行如何处理？ → A: 切走保持流连接：运行继续、不被取消，返回原会话后从离开时的状态无缝继续实时展示；仅用户主动停止、关闭页面或浏览器连接整体断开才触发取消（沿用 009 规则）。
- Q: 加载历史会话（回复产生于本页面生命周期之外）时，过程卡片如何处理？ → A: 不还原历史卡片。历史消息只展示已保存正文，不出现还原的工具过程卡片或占位卡片；卡片仅存在于本页面生命周期内产生的运行。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 工具过程卡片实时展示 (Priority: P1)

使用者在聊天页与绑定了工具的 Agent 对话时，每当工具开始执行，当前 Agent 回复区域立即出现一张"过程卡片"，展示工具名称和"正在执行"状态；执行结束后，卡片更新为成功或失败状态，并显示实际耗时。本地工具展示易读名称；MCP 工具同时展示 MCP Server 名称和工具名称。内部编号只用于事件关联，不作为卡片主要标题。

**Why this priority**: 让用户"看见 Agent 在做什么"是本阶段的核心价值，没有过程卡片，其余展示能力都无从谈起。

**Independent Test**: 向绑定了内置工具的 Agent 提出需要调用工具的问题 → 观察到卡片先出现"正在执行"，随后变为成功或失败并显示耗时。

**Acceptance Scenarios**:

1. **Given** Agent 绑定了已启用的工具，**When** 模型在回复中请求调用工具，**Then** 回复区域立即出现该工具的过程卡片，展示工具名称与"正在执行"状态。
2. **Given** 一张处于"正在执行"状态的卡片，**When** 工具执行完成，**Then** 卡片更新为成功或失败状态，并显示实际耗时。
3. **Given** 调用的是本地内置工具，**When** 查看卡片标题，**Then** 展示该工具的易读名称。
4. **Given** 调用的是 MCP 工具，**When** 查看卡片标题，**Then** 同时展示 MCP Server 名称和工具名称，且不以内部编号作为主要标题。
5. **Given** 同一个工具在一次回复中被多次调用，**When** 查看回复区域，**Then** 每次调用都有一张独立卡片，各自记录各自的状态与耗时。

---

### User Story 2 - 正文与卡片按事件顺序交错展示 (Priority: P1)

一次 Agent 回复中的正文文字与工具过程卡片，按照实际事件发生顺序交错展示：工具调用之前生成的文字保留在卡片上方，工具结束后生成的文字接在卡片下方。理解上，每次工具执行也是 Agent 回复内容的一部分，因此按序展示，而不是把所有工具卡片统一堆到回复开头或结尾。后端并行调用工具时，卡片按开始顺序排列，完成时在原位置更新，不按结束顺序重新排序。开始与完成事件通过运行标识和工具调用标识关联到同一张卡片，避免重复创建或更新错位。

**Why this priority**: 顺序错乱会让用户完全无法理解 Agent 的行动脉络，是与卡片本身同等重要的核心体验；事件关联错误（重复卡片、更新错位）会直接破坏信任。

**Independent Test**: 向 Agent 提出会"先说一句话 → 调用工具 → 再继续说明"的问题 → 观察到文字与卡片严格按发生顺序交错排列，无重复卡片。

**Acceptance Scenarios**:

1. **Given** 一次包含工具调用的回复，**When** 查看消息区域，**Then** 正文与卡片按实际事件顺序交错排列，工具调用前的文字在卡片上方，之后的文字在卡片下方。
2. **Given** 模型在一次回复中先后请求两个工具，**When** 查看展示，**Then** 两张卡片按调用开始顺序排列，不因完成先后而改变位置。
3. **Given** 一次运行的事件流，**When** 每个工具完成事件到达，**Then** 它更新的是由运行标识和工具调用标识对应的那张已有卡片，不新建卡片。
4. **Given** 同一工具被连续调用两次，**When** 查看展示，**Then** 出现两张独立卡片，各自显示各自的执行结果。

---

### User Story 3 - 卡片详情展开与内容整理 (Priority: P2)

过程卡片默认收起，展示一句简短的执行摘要。用户展开卡片后，可以查看整理后的输入参数和执行结果。输入与结果按内容类型整理展示：短文本直接显示并保留必要换行；结构化内容使用格式化缩进，方便查看字段和值；长内容默认只展示前一部分，明确标注已截断，并提供展开操作；二进制内容不展示正文或编码数据，只提示内容类型和大小信息。工具失败时，展示便于理解的原因，不直接显示程序异常堆栈。对可展开内容设置合理的展示上限，超过上限时明确提示未展示全部内容。结果摘要优先从工具返回的状态和内容中提取，不额外调用模型生成摘要。

**Why this priority**: 详情展开满足"看懂 Agent 具体做了什么"的进阶需求，并承担防泄露、防卡顿、防注入的展示安全职责；相比 P1 的可见性，它属于深化体验。

**Independent Test**: 展开一张成功卡片查看输入与结果 → 短文本完整可读、结构化内容有缩进、超长内容被截断且标注、二进制只显示类型与大小。

**Acceptance Scenarios**:

1. **Given** 一张默认收起的卡片，**When** 查看内容，**Then** 卡片展示一句简短的执行摘要。
2. **Given** 一张收起的卡片，**When** 用户展开，**Then** 可以查看整理后的输入参数和执行结果。
3. **Given** 输入或结果为短文本，**When** 展示，**Then** 直接显示并保留必要的换行。
4. **Given** 输入或结果为结构化内容，**When** 展示，**Then** 以格式化缩进呈现字段和值，便于阅读。
5. **Given** 输入或结果为长内容，**When** 展示，**Then** 默认只显示前一部分，明确标注已截断，并提供展开操作；展开后超过展示上限时提示未展示全部内容。
6. **Given** 输入或结果为二进制内容，**When** 展示，**Then** 不显示正文或编码数据，只提示内容类型和大小信息。
7. **Given** 工具执行失败，**When** 用户展开卡片，**Then** 显示便于理解的原因，不出现程序异常堆栈。
8. **Given** 工具返回内容中包含网页脚本或标记文本，**When** 在卡片中展示，**Then** 仅作为纯文本显示，不被执行或渲染为页面内容。

### User Story 4 - 滚动跟随与交互体验 (Priority: P2)

生成过程中聊天区域保持可滚动：当用户位于底部附近时，界面自动跟随新文字和工具状态更新；用户主动向上查看历史消息后，暂停自动跟随且不强行拉回底部；用户回到底部后恢复自动跟随，并提供"回到最新消息"的快捷按钮。展开或收起卡片时尽量保持当前阅读位置，避免页面明显跳动。

**Why this priority**: 长回复叠加工具事件时，跟随策略直接决定"能否安心阅读"；但它建立在卡片（US1）与顺序（US2）正确的基础上，属于体验打磨。

**Independent Test**: 触发一次包含工具调用的长回复 → 停在底部时自动跟随；向上滚动后界面不再自动下拉；回到底部后跟随恢复，且可点击"回到最新消息"按钮。

**Acceptance Scenarios**:

1. **Given** 生成过程正在进行，**When** 用户停留在聊天区域底部附近，**Then** 新文字与工具状态更新出现时视图自动跟随。
2. **Given** 生成过程正在进行，**When** 用户向上滚动查看历史消息，**Then** 自动跟随暂停，视图不被强行拉回底部。
3. **Given** 自动跟随已暂停，**When** 用户回到底部，**Then** 自动跟随恢复。
4. **Given** 自动跟随已暂停且下方有新内容，**When** 用户查看界面，**Then** 存在"回到最新消息"的快捷按钮，点击后到达底部。
5. **Given** 一张卡片处于收起状态，**When** 用户展开或收起它，**Then** 当前阅读位置基本保持不变，页面无明显跳动。

---

### User Story 5 - 取消与中断的明确终态 (Priority: P3)

运行被用户取消时，所有尚未结束的工具卡片被标记为"已取消"；连接中断且无法确认执行结果时，对应卡片标记为"状态未知"。任何情况下卡片都不得一直停留在"正在执行"，也不得被误标为成功。

**Why this priority**: 属于异常路径的正确性要求，出现频率低于正常流程，但一旦出现会严重误导用户，因此必须覆盖。

**Independent Test**: 在工具执行过程中点击停止 → 未结束的卡片立即显示"已取消"；断开网络后 → 无法确认结果的卡片显示"状态未知"。

**Acceptance Scenarios**:

1. **Given** 一次运行中存在"正在执行"的工具卡片，**When** 用户取消运行，**Then** 所有未结束的卡片被标记为"已取消"。
2. **Given** 连接中断且无法确认某工具的执行结果，**When** 中断发生，**Then** 对应卡片被标记为"状态未知"。
3. **Given** 任意异常终止场景（取消、错误、断连），**When** 查看卡片状态，**Then** 不存在仍停留在"正在执行"的卡片，也没有失败或取消的卡片被标为成功。

---

### User Story 6 - 页面内状态保留 (Priority: P3)

本阶段至少保证当前页面内各会话的工具过程完整保留：切换到其他会话再返回时，已有卡片、执行状态和消息顺序仍然正确。刷新页面后的过程恢复不在本阶段实现，留到后续运行记录开发阶段，本阶段不提前增加持久化功能。

**Why this priority**: 会话切换是工作台常规操作，卡片丢失会让用户困惑；但完整恢复依赖后续运行记录持久化，本阶段做到页面内保留即可。

**Independent Test**: 触发一次含工具调用的回复 → 切换到另一会话 → 返回原会话 → 卡片、状态与顺序与离开前完全一致。

**Acceptance Scenarios**:

1. **Given** 某会话中已有带过程卡片的回复，**When** 用户切换到其他会话再返回，**Then** 卡片数量、执行状态、正文与卡片的交错顺序与离开前一致。
2. **Given** 某会话正在生成中，**When** 用户切换到其他会话再返回，**Then** 运行仍在继续（未被取消），卡片与正文从离开时的状态无缝继续实时更新。
3. **Given** 加载历史会话（回复产生于本页面生命周期之外），**When** 查看该回复，**Then** 只展示已保存正文，不出现还原的工具过程卡片或占位卡片。
4. **Given** 本阶段实现范围，**When** 用户刷新页面，**Then** 工具过程不要求恢复（属于后续运行记录阶段的能力），页面不因此报错。

---

### Edge Cases

- 同一工具在极短时间内被调用多次，每次调用是否都有独立卡片且状态互不串扰？
- 并行调用的多个工具中先开始的反而后结束，卡片位置是否仍保持开始顺序？
- 工具结果接近或达到展示上限（如超大文本）时，是否仍可操作页面、明确提示未展示全部内容？
- 工具返回的内容包含网页脚本或标记文本时，是否仅按纯文本展示？
- 工具在开始事件与完成事件几乎同时到达时，是否仍正确创建并更新同一张卡片？
- 运行因达到最大轮数或模型错误结束时，未结束的卡片是否进入明确终态而非停留"正在执行"？
- 工具失败且后端无法给出具体原因时，是否展示通用但可理解的失败提示？
- 用户在生成过程中快速切换会话，返回后状态是否依然正确？
- 生成中切换会话再返回：运行不被取消，展示无缝续播，而非进入"已取消"终态。
- 加载历史会话（页面生命周期外的回复）：只展示已保存正文，不还原过程卡片，也不出现空白卡片或占位错误。

## Requirements *(mandatory)*

### Functional Requirements

**过程卡片**

- **FR-001**: 系统 MUST 在工具调用开始时，于当前 Agent 回复区域插入一张过程卡片，展示工具名称与"正在执行"状态。
- **FR-002**: 系统 MUST 在工具执行结束后将卡片更新为成功或失败状态，并显示实际耗时。
- **FR-003**: 本地工具 MUST 展示易读名称；MCP 工具 MUST 同时展示 MCP Server 名称与工具名称；内部编号 MUST NOT 作为卡片主要标题。
- **FR-004**: 卡片 MUST 默认收起并展示简短执行摘要，用户 MUST 能够展开查看整理后的输入参数与结果。
- **FR-005**: 工具失败时，系统 MUST 展示便于理解的失败原因，MUST NOT 直接展示程序异常堆栈。

**消息顺序与事件关联**

- **FR-006**: 同一次回复中的正文与工具卡片 MUST 按实际事件顺序交错展示，MUST NOT 将所有工具卡片统一移动到回复开头或结尾。
- **FR-007**: 系统 MUST 使用运行标识与工具调用标识关联开始、完成及失败事件并更新对应卡片，MUST NOT 重复创建卡片或更新错位。
- **FR-008**: 同一工具的多次调用 MUST 各自独立展示。
- **FR-009**: 并行调用时，卡片 MUST 按开始顺序排列，完成时在原位置更新，MUST NOT 按结束顺序重新排序。

**输入与结果展示**

- **FR-010**: 短文本 MUST 直接显示并保留必要换行；结构化内容 MUST 使用格式化缩进展示字段与值。
- **FR-011**: 长内容 MUST 默认只展示前一部分、明确标注已截断并提供展开操作。
- **FR-012**: 二进制内容 MUST NOT 展示正文或编码数据，只 MUST 提示内容类型与大小信息。
- **FR-013**: 可展开内容 MUST 设置合理的展示上限，超过上限时 MUST 明确提示未展示全部内容。
- **FR-014**: 结果摘要 MUST 优先从工具返回的状态和内容中提取，MUST NOT 为生成摘要而额外调用模型。
- **FR-015**: 工具返回内容 MUST 按不可信文本处理，MUST NOT 作为页面脚本或标记直接执行。

**滚动与交互**

- **FR-016**: 生成过程中聊天区域 MUST 保持可滚动；用户位于底部附近时 MUST 自动跟随新内容更新。
- **FR-017**: 用户向上查看历史后 MUST 暂停自动跟随且不强行拉回底部；用户回到底部后 MUST 恢复跟随。
- **FR-018**: 界面 MUST 提供"回到最新消息"的快捷按钮。
- **FR-019**: 展开/收起卡片 MUST 尽量保持当前阅读位置，避免页面明显跳动。

**异常终态与状态保留**

- **FR-020**: 运行取消时，尚未结束的卡片 MUST 被标记为"已取消"。
- **FR-021**: 连接中断且无法确认执行结果时，对应卡片 MUST 被标记为"状态未知"。
- **FR-022**: 任何情况下卡片 MUST NOT 长时间停留在"正在执行"，失败或取消的卡片 MUST NOT 被误标为成功。
- **FR-023**: 当前页面内各会话的工具过程 MUST 完整保留：切换会话再返回时，卡片、执行状态与消息顺序 MUST 保持正确。生成中切换会话时，流式连接 MUST 保持，运行 MUST NOT 因此被取消，返回原会话后 MUST 从离开时的状态无缝继续实时展示；仅用户主动停止、关闭页面或浏览器连接整体断开才触发取消（沿用 009 规则）。
- **FR-024**: 本阶段 MUST NOT 新增任何运行记录持久化能力（包括每轮 LLM 调用输入输出、工具调用与结果的存储），MUST NOT 实现刷新后的过程恢复；两者均留待后续运行记录阶段（009 FR-007 的禁令继续有效）。
- **FR-025**: 加载历史会话（回复产生于本页面生命周期之外）时，系统 MUST NOT 还原工具过程卡片，历史消息只展示已保存正文；工具过程卡片仅存在于本页面生命周期内产生的运行。

**展示一致性**

- **FR-026**: 卡片配色、字号、间距和展开交互 MUST 与现有聊天页面保持一致。
- **FR-027**: 卡片状态 MUST 同时使用文字与视觉标识区分，MUST NOT 仅依靠颜色。

### Key Entities *(include if feature involves data)*

- **工具过程卡片**：一次工具调用的前端展示实体。包含显示名称（本地工具的易读名称，或 MCP Server 名称 + 工具名称）、调用标识（用于事件关联，不作标题）、状态（正在执行/成功/失败/已取消/状态未知）、实际耗时、执行摘要、整理后的输入参数与结果展示内容。
- **事件关联关系**：通过运行标识 + 工具调用标识将"工具调用开始""工具调用完成/失败"事件关联到同一张卡片；一次运行可包含多次调用，同一工具可被多次调用，每次调用一张卡片。
- **内容展示片段**：卡片内输入或结果的一份整理后内容，具有类型（短文本/结构化/长内容/二进制）、截断标记与展示上限。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 工具开始执行后，使用者无需刷新即可在回复区域看到对应卡片出现，感知为即时。
- **SC-002**: 非开发背景的使用者仅通过卡片本身，即可说出 Agent 用了哪些工具、每次调用成功与否、各自耗时。
- **SC-003**: 展示的正文字片与卡片顺序与实际事件顺序的一致率为 100%（无前置内容被移到后方、无卡片错位）。
- **SC-004**: 单次运行包含 20 个以上工具调用、且部分结果内容很长时，页面仍保持可滚动与可交互，无卡顿死锁。
- **SC-005**: 失败卡片展示的原因能让非开发背景的使用者理解"发生了什么"，且页面上不出现程序异常堆栈。
- **SC-006**: 展开/收起卡片时，当前阅读位置不发生明显跳动。
- **SC-007**: 运行取消或连接中断后，所有未完成卡片及时进入"已取消"或"状态未知"终态，不存在停留"正在执行"的卡片。

## Assumptions

- 后端 Agent Runtime（009 阶段）已提供工具调用开始/完成事件及运行标识、调用标识，本阶段在其基础上补足展示所需信息（如完整参数与结果、MCP Server 名称、中断终态等），具体契约增补在 Plan 阶段确定。
- "长内容前一部分"的截断阈值与"展示上限"采用合理默认值（如按字符量级设定），Plan 阶段细化为具体数值。
- 结果摘要直接从工具返回的状态与内容提取（如取前若干字符），本阶段不引入模型生成摘要。
- 单用户工作台定位，本阶段不涉及多用户权限差异；"不泄露敏感信息"通过不展示堆栈、二进制正文与限制展开上限实现。
- 刷新后的过程恢复依赖后续运行记录持久化阶段，本阶段明确排除；历史会话加载（页面生命周期外的回复）同样不还原卡片，历史正文由 008 阶段的会话消息持久化自然展示。
