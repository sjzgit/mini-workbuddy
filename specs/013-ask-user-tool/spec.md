# Feature Specification: Ask User 询问工具（第十三阶段）

**Feature Branch**: `013-ask-user-tool`

**Created**: 2026-09-18

**Status**: Draft

**Input**: User description: "在工具管理中增加 Ask User 工具：LLM 可以使用该工具向用户发起询问；触发该工具时，聊天界面需要展示一个询问弹窗；询问格式有开放式与选项式两种，最终把用户的回答内容返回给 LLM"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Ask User 工具注册与启用 (Priority: P1)

使用者打开"工具管理"页面，看到新增的内置工具"询问用户"（ask_user），展示形式与既有内置工具一致：名称、用途说明、参数说明、启用状态、系统内置标记；参数说明写清三种信息如何填写——问题文本（必填）、选项列表（可选，提供即为选项式）、多选开关（可选，仅选项式有意义）。使用者可以启用/停用该工具，可以把启用后的工具绑定到某个 Agent；未绑定或停用时，该 Agent 的模型不会调用它。

**Why this priority**: 治理是该工具一切行为的前置——先作为一等内置工具进入既有治理体系（注册/启停/绑定），后续询问交互才有触发入口。

**Independent Test**: 打开工具管理页核对"询问用户"工具条目与参数说明完整性；停用后经运行验证模型目录中不含该工具；重新启用并绑定到 Agent 后模型可调用。

**Acceptance Scenarios**:

1. **Given** 系统完成升级， **When** 使用者打开工具管理页， **Then** 列表中出现"询问用户"内置工具，含用途说明与参数说明（问题必填、选项可选、多选开关可选），可正常启用/停用。
2. **Given** 该工具已启用且已绑定某 Agent， **When** 该 Agent 运行， **Then** 模型的可用工具目录中包含询问用户工具。
3. **Given** 该工具未绑定某 Agent 或处于停用状态， **When** 该 Agent 运行， **Then** 模型的可用工具目录中不包含该工具，模型无法发起询问。

---

### User Story 2 - 开放式询问端到端 (Priority: P1)

Agent 运行中，模型判断需要用户补充信息时调用询问用户工具，仅传入一个问题文本。使用者的聊天界面随即弹出询问弹窗，展示该问题和一个文本输入框；在用户提交回答前，本次运行暂停推进（界面不再产生新的模型输出）。使用者输入回答并提交后，弹窗关闭，回答内容作为工具结果交还模型，模型基于回答继续生成；使用者能在运行记录的工具调用过程中看到这次问答（问题与回答）。

**Why this priority**: 开放式问答是最小可用闭环——没有它，该工具没有任何价值；选项式只是回答控件的变体。

**Independent Test**: 让绑定了该工具的 Agent 处理一个必须反问用户才能继续的任务（如"帮我写一段话，但先问我写给谁"），验证弹窗出现、运行暂停、输入回答提交后模型继续并且回复内容体现了回答。

**Acceptance Scenarios**:

1. **Given** Agent 已绑定启用的询问用户工具， **When** 模型发起一次仅含问题文本的询问， **Then** 聊天界面弹出询问弹窗，展示问题文本与文本输入框。
2. **Given** 询问弹窗已弹出， **When** 使用者尚未提交回答， **Then** 本次运行暂停推进，界面不出现新的模型输出，会话保持生成中状态。
3. **Given** 使用者在输入框中填写了回答文本并提交， **When** 弹窗关闭， **Then** 回答内容作为工具结果交还模型，模型继续生成且后续回复体现该回答。
4. **Given** 一次已完成的问答， **When** 使用者回看该次运行的记录， **Then** 能看到这次工具调用的问题与回答内容。

---

### User Story 3 - 选项式询问 (Priority: P1)

模型调用询问用户工具时传入问题文本和选项列表，弹窗展示问题与选项；系统自动在选项列表末尾追加一个固定的"其他，我手动输入"选项。选择方式由模型指定：单选（只能选一项）或多选（可勾选多项）。使用者选中"其他"时，选项下方出现输入框供手动填写回答。提交后，选中的选项内容（以及"其他"的手动输入文本）作为回答交还模型。

**Why this priority**: 选项式是需求明确的第二种询问格式，与开放式并列构成完整能力；"其他"兜底保证选项不满足时用户仍可自由回答。

**Independent Test**: 分别构造单选与多选询问（含 2~4 个选项），验证单选只能选一项、多选可勾选多项、末尾自动出现"其他，我手动输入"、选中其他后出现输入框；提交后核对返回给模型的内容与所选选项/输入文本一致。

**Acceptance Scenarios**:

1. **Given** 模型传入问题与选项列表（未指定多选）， **When** 弹窗展示， **Then** 选项为单选——使用者只能选中一项；列表末尾自动出现"其他，我手动输入"。
2. **Given** 模型传入问题、选项列表并指定多选， **When** 弹窗展示， **Then** 选项为多选——使用者可勾选多项；列表末尾自动出现"其他，我手动输入"。
3. **Given** 使用者选中"其他，我手动输入"， **When** 查看弹窗， **Then** 选项下方出现文本输入框供填写自定义回答。
4. **Given** 使用者在没有任何选中项或输入的情况下尝试提交， **When** 点击提交， **Then** 提交被阻止并给出提示，空回答不会被交还模型。
5. **Given** 使用者完成选项式回答并提交， **When** 回答交还模型， **Then** 返回内容准确反映所选选项（多选含全部选中项）；选中"其他"时返回手动输入的文本。

### User Story 4 - 等待期间取消与中断恢复 (Priority: P2)

询问弹窗等待回答期间，使用者点击停止运行：运行按既有取消语义结束，弹窗关闭，取消不被当作有效回答交还模型，会话随后可立即发起新消息。回答提交前使用者刷新页面：弹窗随运行状态恢复重新出现，仍可正常回答，运行继续推进。

**Why this priority**: 取消与恢复是等待类交互的健壮性底线——实现不正确会造成会话卡死或弹窗丢失；但它们不新增能力，属于核心闭环之上的保障。

**Independent Test**: 弹窗等待中点击停止，核对运行进入取消终态、弹窗关闭、可立刻发送新消息；再次发起询问后在回答前刷新页面，核对弹窗重新出现且回答后运行正常继续。

**Acceptance Scenarios**:

1. **Given** 询问弹窗等待回答， **When** 使用者停止运行， **Then** 运行以取消终态结束，弹窗关闭，会话可立即发起新消息。
2. **Given** 询问弹窗等待回答， **When** 使用者刷新页面， **Then** 弹窗随运行恢复重新出现，问题与选项内容不变。
3. **Given** 刷新后弹窗重现， **When** 使用者正常提交回答， **Then** 运行恢复推进，回答交还模型，与未刷新场景行为一致。

---

### User Story 5 - 等待上限与无人值守场景 (Priority: P2)

等待回答存在上限：超过时限仍未回答时，运行不会无限挂起，而是以明确的结果收尾（告知模型用户未在时限内回答）。在无人在场的自动运行场景（如 Agent 评测）中模型调用该工具时，不弹窗、不挂起，立即返回明确的失败结果交还模型，模型可据此前行或调整。

**Why this priority**: 超时与无人值守防护是防御性保障，防止会话被永久占用；正常交互路径不依赖它们。

**Independent Test**: 将等待上限调小后发起询问且不回答，核对到时后运行以明确结果收尾；在评测运行中让模型调用该工具，核对立即返回失败结果且评测流程不受阻。

**Acceptance Scenarios**:

1. **Given** 询问弹窗超过等待上限仍未回答， **When** 上限到达， **Then** 运行不再等待，以明确的结果继续收尾，会话不处于永久生成中状态。
2. **Given** 评测等无人值守的自动运行， **When** 模型调用询问用户工具， **Then** 不出现弹窗、不挂起，立即返回明确的失败结果，运行继续。

---

### Edge Cases

- 模型传入了空的选项列表怎么办？—— 视为开放式询问，展示输入框。
- 模型传入的选项有重复项怎么办？—— 原样展示（去重交给模型），系统只负责追加"其他"。
- 模型传入选项式但未指定单选/多选怎么办？—— 默认单选。
- 使用者在输入框只填了空白字符就提交怎么办？—— 视为空回答，提交被阻止。
- 多选模式下只勾选了"其他"怎么办？—— 以输入框文本作为回答。
- 多选模式下既勾选了普通选项又勾选了"其他"怎么办？—— 回答为全部选中项与输入文本的组合。
- 使用者长时间不回答怎么办？—— 等待有上限，到时以明确结果收尾（见 US5）。
- 同一轮运行中模型连续发起多个询问怎么办？—— 依次逐个弹窗，回答一个再出现下一个。
- 回答文本过长怎么办？—— 沿用运行记录对工具结果的既有长度限制处理，交还模型前按既有规则截断。
- 该工具处于停用/未绑定状态时模型点名调用怎么办？—— 走既有"工具不存在或不在目录"的拒绝路径，返回明确失败结果。
- 询问弹窗出现时使用者切换到其他会话再回来怎么办？—— 弹窗仍可正常回答；会话间互不干扰。

## Requirements *(mandatory)*

### Functional Requirements

**治理与注册**

- **FR-001**: 系统 MUST 将"询问用户"作为系统内置工具纳入既有工具治理：工具管理页展示名称、用途说明、参数说明、启用状态与内置标记；允许启停，MUST NOT 提供删除或修改用途的入口。
- **FR-002**: 工具参数说明 MUST 写清三类信息：问题文本（必填）、选项列表（可选，提供即为选项式）、多选开关（可选，仅选项式有意义）；说明需引导模型何时发起询问。
- **FR-003**: 该工具 MUST 遵循既有"绑定 Agent × 启用"的可用性规则：未绑定或停用时不出现在该 Agent 运行的模型工具目录中。

**询问交互**

- **FR-004**: 模型调用该工具时，聊天界面 MUST 弹出询问弹窗，展示问题文本；回答格式按模型传入的参数决定。
- **FR-005**: 开放式询问（无选项列表）MUST 展示文本输入框；使用者提交文本后，回答 MUST 作为工具结果交还模型。
- **FR-006**: 选项式询问 MUST 展示选项列表，并在末尾自动追加固定文案的"其他，我手动输入"选项；使用者选中"其他"时 MUST 出现输入框供手动填写。
- **FR-007**: 选项式询问 MUST 支持单选与多选两种方式，由模型在调用时指定；未指定时默认单选。
- **FR-008**: 空回答（未选中任何选项且未输入有效文本）MUST 被阻止提交。
- **FR-009**: 使用者提交回答后，弹窗 MUST 关闭，回答内容 MUST 作为该次工具调用的结果交还模型，运行 MUST 恢复推进。

**等待语义**

- **FR-010**: 等待回答期间运行 MUST 暂停推进：不产生新的模型输出；期间会话维持生成中状态，沿用既有会话互斥规则。
- **FR-011**: 等待期间使用者停止运行 MUST 使运行按既有取消语义结束：弹窗关闭，取消 MUST NOT 被当作有效回答交还模型，会话解除占用。
- **FR-012**: 回答提交前页面刷新或重连 MUST 使弹窗随运行状态恢复重现（问题、选项、已选内容如实恢复），回答后行为与未刷新一致。
- **FR-013**: 等待回答 MUST 有上限时限：超过时限运行 MUST NOT 无限挂起，以明确的结果收尾并解除会话占用；时限值可在系统配置中调整。
- **FR-014**: 无人值守的自动运行（评测等）中调用该工具 MUST NOT 弹窗或挂起，MUST 立即返回明确的失败结果交还模型。
- **FR-015**: 同一轮运行的多次询问 MUST 依次逐个弹窗处理，每个回答对应各自的工具结果。

**记录与展示**

- **FR-016**: 每次问答 MUST 进入该次运行的记录：工具调用过程中可见问题与回答（含选中的选项），回看时完整可读。
- **FR-017**: 询问弹窗内的回答提交 MUST 有进行中状态防重复提交；提交结果失败时给出可理解提示且弹窗不关闭，可重试。

### Key Entities

- **询问请求（Ask User Request）**: 模型一次询问调用的参数集合。属性：问题文本（必填）、选项列表（可选，空/缺省表示开放式）、多选标记（可选，默认单选）；与一次工具调用一一对应。
- **用户回答（User Answer）**: 使用者对一次询问的回应。属性：选中的选项集合（选项式，可为空）、手动输入文本（开放式或选中"其他"时）、提交时间；提交后不可修改，作为工具结果交还模型。
- **询问用户工具**: 系统内置工具，纳入既有工具治理实体（注册信息 + 启停状态 + Agent 绑定），其参数说明与行为约束由本 spec 定义。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 端到端验证中，模型每次成功调用该工具后弹窗 100% 出现；回答提交后 100% 成为模型下一轮的可见输入（以模型后续回复是否体现回答验证）。
- **SC-002**: 开放式、选项式单选、选项式多选、选中"其他"手动输入四类场景全部可用，返回给模型的内容与使用者实际输入/选择 100% 一致。
- **SC-003**: 等待回答期间模型新增输出为零；等待中取消的运行 100% 进入取消终态、弹窗关闭、会话可立即复用。
- **SC-004**: 回答提交前刷新页面，弹窗 100% 恢复重现且回答后行为与未刷新一致。
- **SC-005**: 无人值守场景调用该工具 100% 不挂起，立即返回明确失败结果，自动运行流程不受阻。
- **SC-006**: 超时场景运行 100% 在时限内收尾，会话不进入永久生成中状态。
- **SC-007**: 工具管理页展示与启停行为和既有内置工具 100% 一致；未绑定/停用时模型工具目录中不出现该工具。

## Assumptions

- 该工具遵循既有内置工具治理体系（注册表 + 工具启停 + Agent 绑定），不引入新的治理概念；工具在系统升级后即出现在工具管理页（内置工具随系统提供）。
- "其他，我手动输入"为系统固定追加的选项文案，不可由模型覆盖；选项式未指定单选/多选时默认单选。
- 回答以文本形式交还模型：开放式与"其他"为输入文本；选项式为所选选项文本（多选按选择顺序拼接）；截断沿用运行记录对工具结果的既有上限规则。
- 等待上限的具体时长与超时后交还模型的具体文案由 Plan 阶段确定（进系统配置，可调整），本阶段只约束"必须有上限且行为明确"。
- 等待期间会话处于生成中，沿用既有互斥规则（期间不能发起新的生成）；刷新恢复依赖运行事件的重放机制（011 运行记录既有能力）。
- 无人值守场景（评测等）以"运行请求中无交互界面在场"为判定，具体判定方式由 Plan 阶段确定；该场景下返回的失败文案需让模型能理解"当前没有用户可回答"并自行调整。
- 模型自行决定何时调用该工具（通过工具说明引导），系统不强制模型在特定情况下发问；工具说明中给出适用场景（缺少关键信息、需要用户在候选项间抉择等）。
- 弹窗中使用者尚未提交的回答不持久化（刷新后已选内容恢复以运行状态为准，输入中的草稿文本不保证保留）。
