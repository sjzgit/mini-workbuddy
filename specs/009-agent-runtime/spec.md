# Feature Specification: 统一 Agent Runtime（第九阶段）

**Feature Branch**: `009-agent-runtime`

**Created**: 2026-09-15

**Status**: Draft

**Input**: User description: "按文档开发：0user chat/7 AgentRuntime.md —— 在读懂当前聊天请求、上下文构造、模型调用和取消处理流程的基础上，在后端建立统一的 Agent Runtime，并将 Agent Loop 放在 Runtime 内实现。Runtime 负责加载 Agent 配置、组装上下文、准备可用工具与 Skill 目录、调用模型、执行工具循环、处理取消和资源清理，以及输出统一运行事件。聊天接口只负责接收请求和转发事件，不能自行维护模型与工具循环。本阶段不提前开发评测模块，也不要求实现运行记录持久化。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 聊天经由统一 Runtime 完成直答运行 (Priority: P1)

使用者像往常一样在聊天页发送消息。聊天接口收到请求后不再自行组装上下文、调用模型，而是把 Agent 标识、用户输入、历史消息、运行级能力限制和取消信号交给统一的 Agent Runtime。Runtime 加载该 Agent 的模型配置与系统提示词，按会话历史组装上下文，发起模型请求，并把运行事件（运行开始、内容增量、模型请求结束、运行结束等）转发给聊天页面流式展示。每次运行生成唯一运行标识；运行结束事件包含最终状态与结束原因，且每次运行只产生一次。

**Why this priority**: 统一入口是本阶段一切能力的前提。直答链路先迁移到 Runtime，工具循环与 Skill 加载才有统一的落点；聊天接口瘦身为"接收请求 + 转发事件"也是后续阶段（评测直接复用 Runtime）的结构基础。

**Independent Test**: 在聊天页向一个未绑定任何工具与 Skill 的 Agent 发送一条消息 → 收到流式回复且正文完整 → 检查后端日志，出现唯一运行标识、运行开始与运行结束事件，结束原因为正常结束。

**Acceptance Scenarios**:

1. **Given** 系统中存在未绑定任何工具与 Skill 的可用 Agent，**When** 使用者在聊天页发送一条非空消息，**Then** 收到流式回复，正文完整，本次运行由统一 Runtime 完成。
2. **Given** 同一会话已有历史消息，**When** 使用者发送新消息，**Then** Runtime 组装的上下文包含该会话按顺序排列的有效历史消息与当前 Agent 的系统提示词，模型能理解连续追问。
3. **Given** 一次正在进行的运行，**When** 查看事件流，**Then** 事件携带唯一运行标识，顺序字段在运行内严格递增，且运行结束事件恰好出现一次并标明最终状态与结束原因。
4. **Given** 聊天页与后端的交互，**When** 检查聊天接口的职责，**Then** 聊天接口只接收请求和转发事件，不自行维护模型调用与工具循环。

### User Story 2 - 工具调用循环 (Priority: P1)

对于绑定了工具的 Agent，模型在需要时请求调用工具。Runtime 通过统一执行入口完成权限与参数校验并执行工具，把结果追加到上下文后再次请求模型，循环往复，直到模型给出最终回答、达到 Agent 管理中设置的最大执行轮数、发生运行级错误或被取消。模型在工具调用前后生成的正文片段都按顺序保留，不覆盖、不清空。

**Why this priority**: 工具循环是 Agent 真正"能干活"的核心，也是把 Agent Loop 放入 Runtime 的主要目的；没有循环，Skill 按需加载和后续评测都无从谈起。

**Independent Test**: 为 Agent 绑定一个内置工具 → 提出必须借助该工具才能回答的问题 → 观察到工具调用开始与结果事件、工具调用前后的正文片段按序保留、最终回答正确引用了工具结果。

**Acceptance Scenarios**:

1. **Given** Agent 绑定了已启用的工具，**When** 模型在回答过程中请求调用该工具，**Then** Runtime 通过统一入口执行工具，将结果追加到上下文，并再次请求模型。
2. **Given** 一次包含工具调用的运行，**When** 查看流式输出，**Then** 工具调用前生成的正文片段与工具调用后生成的正文片段都按顺序保留，进入下一轮时不被覆盖或清空。
3. **Given** 模型直接给出回答且未请求任何工具，**When** 循环判断，**Then** 本次运行正常结束。
4. **Given** 运行已达到该 Agent 设置的最大执行轮数，**When** 模型仍请求继续，**Then** 运行结束，结束原因标明达到轮数限制，已生成的正文保留。
5. **Given** Skill 加载完成后模型按其中步骤调用工具，**When** 工具被执行，**Then** 与普通工具调用一样经过同一执行入口并产生同样的事件。

### User Story 3 - Skills 发现与按需加载 (Priority: P1)

Agent 绑定且启用了 Skills 时，Runtime 在运行开始只把 Skill 的标识、名称和说明放入上下文（不预先放入全部详细指令），并说明"任务符合某个 Skill 的用途时，先加载其完整指令，再按指令执行"。Runtime 提供内置的 `load_skill` 工具，接收 Skill 稳定标识，读取对应完整指令作为工具结果进入上下文，模型按指令继续执行任务。Agent 没有可用 Skill 时，不提供该工具。

**Why this priority**: Skills 按需加载让 Agent 具备可扩展的任务能力，同时控制上下文成本，是本阶段 Runtime 的关键能力；它与工具循环（US2）共同构成 Agent Loop 的完整闭环。

**Independent Test**: 为 Agent 绑定一个描述"如何完成某类任务"的 Skill → 提出与之相关的任务 → 观察到目录说明进入上下文、模型调用 load_skill、完整指令作为工具结果出现、模型按指令继续调用工具或给出回答。

**Acceptance Scenarios**:

1. **Given** Agent 绑定且启用了若干 Skill，**When** 运行开始，**Then** 上下文只包含这些 Skill 的标识、名称、说明及按需加载指引，不包含全部详细指令。
2. **Given** 模型调用 load_skill 并传入已绑定且当前启用的 Skill 稳定标识，**When** 执行前校验通过，**Then** 读取到的完整指令作为工具结果追加到上下文，模型按指令继续处理任务。
3. **Given** Agent 没有任何可用 Skill，**When** 运行开始，**Then** 提供给模型的工具列表中不包含 load_skill。
4. **Given** load_skill 被调用，**When** 查看事件流，**Then** 它复用工具调用事件并标记工具类型，产生工具开始、成功或失败事件；加载后的指令作为工具结果保留在本次运行上下文中。
5. **Given** load_skill 收到不存在、未绑定、已停用的 Skill 标识，或对应文件缺失、内容无法读取，**When** 执行前校验，**Then** 返回明确的工具错误交还模型，由模型决定后续处理。
6. **Given** 某 Skill 的指令内容超过设定的大小上限，**When** 模型加载该 Skill，**Then** 返回明确报错，不做静默截断。

### User Story 4 - 工具权限校验与拒绝反馈 (Priority: P2)

Runtime 在每次运行前完成工具发现与映射：已绑定且启用的内置工具、已绑定且启用的 MCP Server 提供的工具，以及存在可用 Skill 时的 load_skill，使用统一的工具标识与映射规则，避免名称冲突。每次工具执行前再次校验权限与参数：未绑定、已停用、不存在或参数不合法的请求都被拒绝执行，明确的错误结果交还模型。模型填写了某个工具名称，或 Skill 指令要求使用某个工具，都不能使校验被绕过。

**Why this priority**: 这是运行时的安全边界。基本可用性由 US2 保证后，本故事把"不该调用的绝不调用"补严，防止越权与误用。

**Independent Test**: 构造模型请求调用未绑定、已停用、不存在的工具及参数不合法的情形 → 每次请求都被拒绝并返回明确错误，工具未执行任何动作；让本地工具与 MCP 工具同名，确认统一标识与映射规则下无冲突。

**Acceptance Scenarios**:

1. **Given** 模型请求调用未绑定到当前 Agent 的工具，**When** 执行前校验，**Then** 拒绝执行，明确的错误结果交还模型。
2. **Given** 模型请求调用已绑但已停用的工具，**When** 执行前校验，**Then** 拒绝执行，明确的错误结果交还模型。
3. **Given** 工具请求的参数不合法，**When** 执行前校验，**Then** 拒绝执行，并返回指明原因的参数错误信息。
4. **Given** 本地工具与 MCP Server 工具存在同名情形，**When** 组装工具列表或解析模型调用，**Then** 统一的标识与映射规则保证名称无冲突、调用无歧义。
5. **Given** Skill 指令要求使用某个工具且该工具未绑定或已停用，**When** 模型据此发起调用，**Then** 调用仍被拒绝。
6. **Given** 任意一次工具执行，**When** 检查执行行为，**Then** 沿用既有工具执行层的权限校验与危险操作限制；load_skill 只能读取授权的 Skill 指令，不构成绕过文件访问限制的入口。

### User Story 5 - 取消与资源清理 (Priority: P2)

使用者在聊天页点击停止生成、关闭页面或浏览器连接断开时，聊天接口触发取消信号。Runtime 把信号传递到模型请求、工具执行和循环调度，尽快停止模型请求、后续轮次和正在执行的工具。无论运行以成功、失败、达到限制还是取消结束，都要关闭连接并清理本次运行创建的 MCP 进程等资源，清理逻辑覆盖所有退出路径。

**Why this priority**: 取消与清理保证运行可控、资源不泄漏；主流程（US1~US3）稳定后补齐，但"所有退出路径都清理"是后续阶段（断开后后台运行）的安全前提。

**Independent Test**: 生成期间点击停止，输出尽快终止；分别构造成功、失败、达到轮数限制、取消四种退出路径（含工具执行中取消），每次运行结束后检查无本次运行创建的残留 MCP 进程或连接。

**Acceptance Scenarios**:

1. **Given** 一次运行正在进行，**When** 取消信号到达，**Then** 模型请求、后续轮次和正在执行的工具尽快停止。
2. **Given** 使用者点击停止生成、关闭页面或浏览器连接断开，**When** 聊天接口处理，**Then** 由聊天接口触发取消；Runtime 自身不监听浏览器连接。
3. **Given** 正在执行的工具收到取消信号，**When** 工具层处理，**Then** 取消信号被传递到工具执行，正在执行的动作尽快终止。
4. **Given** 运行以成功、失败、达到限制或取消任意一种方式结束，**When** 退出路径执行，**Then** 关闭连接并清理本次运行创建的 MCP 进程等资源，清理覆盖所有退出路径。

---

### User Story 6 - 运行事件契约与日志规范 (Priority: P2)

每次运行生成唯一运行标识。Runtime 统一输出运行开始、模型请求开始、内容增量、模型请求结束、工具调用开始、工具调用结果和运行结束等事件，前后端使用统一的事件标识。事件包含运行标识、运行内递增的顺序字段、事件类型，以及适用的轮次和调用标识；模型请求与工具调用的开始、结束事件通过各自的调用标识配对。模型请求结束事件记录状态、耗时和接口实际返回的 Token 用量（未返回时标记未知，不填零）。后台日志记录运行标识、轮次、调用标识、工具名称、执行状态与结束原因；日志与展示事件都使用脱敏摘要，模型上下文所需的完整工具结果与页面展示的安全摘要分开处理。

**Why this priority**: 完整的事件契约与日志规范是排障、展示和后续评测的基础；聊天基本可用（US1）不依赖全部字段，故排在主流程之后完善。

**Independent Test**: 触发一次含工具调用与 Skill 加载的运行 → 逐条核对事件：运行标识一致、顺序字段递增、开始与结束按调用标识配对、模型请求结束含状态/耗时/Token 用量（缺失则未知）、运行结束恰好一次；核对日志无完整上下文、Skill 正文或未处理工具结果。

**Acceptance Scenarios**:

1. **Given** 一次包含模型请求与工具调用的运行，**When** 查看事件流，**Then** 模型请求开始/结束、工具调用开始/结果通过各自的调用标识一一配对。
2. **Given** 一次模型请求结束事件，**When** 查看其内容，**Then** 包含状态与耗时，以及接口实际返回的 Token 用量；接口未返回用量时标记为未知，不出现填零的情况。
3. **Given** Skill 加载发生，**When** 查看相关事件，**Then** 复用工具调用事件并带有工具类型标记，可与其他工具调用区分。
4. **Given** 一次工具执行完成，**When** 对比模型上下文与页面展示及日志，**Then** 模型上下文保留完整工具结果，页面事件与日志只包含脱敏后的安全摘要。
5. **Given** 任意日志与展示事件，**When** 检查内容，**Then** 不包含完整上下文、Skill 指令正文、未处理的工具结果或密钥等敏感信息。

## Edge Cases

- 模型幻觉出未绑定或不存在的工具名称：拒绝执行并把明确错误交还模型，运行可继续而非中断。
- load_skill 收到的是文件路径而非 Skill 稳定标识：拒绝，不读取任何文件，返回明确工具错误。
- Skill 在运行期间被停用或文件被删除：执行前再次校验失败，返回明确工具错误，由模型决定后续处理。
- MCP Server 启动失败或执行中断连：以明确错误结果交还模型，运行不崩溃；退出路径上清理已创建的资源。
- 工具执行过程中收到取消：工具动作尽快终止，后续轮次不再发起，运行以"已取消"结束。
- 取消信号恰好在模型请求完成或工具刚好结束时到达：不产生半个事件，运行结束事件仍恰好一次，最终状态以实际发生者为准。
- 达到轮数限制时模型仍在请求工具：不再执行新的工具调用，运行正常收尾并标明"达到轮数限制"，已生成正文保留。
- 一次运行内正文与工具调用多次交错：全部正文片段按生成顺序保留展示，无丢失、重复或乱序。
- 模型接口未返回 Token 用量：事件中标记为未知，不填零。
- 运行期间 Agent 被删除或模型被删除：本次运行按既有失败处理结束，结束原因明确；不影响已保存的会话记录。
- 会话绑定的 Agent 存在已停用能力：运行时只暴露已绑定且仍然启用的能力，停用项不提供给模型。
- 浏览器断开触发取消后使用者回到会话：已生成部分按第八阶段的未完成规则保存与展示，不当作正常完成。

## Requirements *(mandatory)*

### Functional Requirements

**Runtime 职责与边界**

- **FR-001**: 系统 MUST 提供统一的 Agent Runtime，负责加载 Agent 配置（模型、系统提示词、可用 Skill 目录、工具定义）、组装上下文、调用模型、执行工具循环、处理取消与资源清理，并输出统一运行事件。
- **FR-002**: Runtime MUST 接收 Agent 标识、用户输入、历史消息、运行级能力限制与取消信号，输出运行事件及最终结果。
- **FR-003**: 运行级能力限制 MUST 只能收窄 Agent 已有权限，MUST NOT 额外授予未绑定或已停用的能力。
- **FR-004**: 聊天接口 MUST 只负责接收请求和转发事件，MUST NOT 自行维护模型调用与工具循环。
- **FR-005**: Runtime MUST NOT 依赖前端页面、HTTP 请求对象或浏览器连接；后续评测可以直接调用同一 Runtime（本阶段不开发评测模块）。
- **FR-006**: Runtime MUST 复用现有模型调用与工具执行基础设施，MUST NOT 另建重复实现。
- **FR-007**: 本阶段不要求实现运行记录持久化，MUST NOT 为运行记录新建存储。

**循环流程**

- **FR-008**: 每次运行开始时，Runtime MUST 加载所选 Agent 的模型、系统提示词、可用 Skill 目录和工具定义等配置，结合当前会话上下文发起模型请求。
- **FR-009**: 模型直接给出回答、没有请求工具时，本次运行 MUST 正常结束。
- **FR-010**: 模型请求调用工具时，Runtime MUST 通过统一入口执行，将结果追加到上下文，并再次请求模型。
- **FR-011**: 模型调用 Skill 加载工具时，Runtime MUST 将读取到的完整指令作为工具结果追加到上下文，并再次请求模型，由模型按照指令继续处理任务。
- **FR-012**: 循环 MUST 持续到正常结束、达到 Agent 管理中设置的轮数限制、发生运行级错误或被取消为止。
- **FR-013**: Runtime MUST 保留现有流式输出能力；模型在工具调用前后生成的正文片段 MUST 按顺序保留，MUST NOT 在进入下一轮时覆盖或清空。

**Skills 发现与按需加载**

- **FR-014**: 运行开始时，系统 MUST 只向模型提供当前 Agent 已绑定且仍然启用的 Skill 标识、名称和说明，不预先加入全部详细指令；上下文 MUST 说明"任务符合某个 Skill 用途时，先加载其完整指令，再按照指令执行"。
- **FR-015**: 系统 MUST 提供统一的 load_skill 工具，接收 Skill 稳定标识并读取对应完整指令；Agent 没有可用 Skill 时 MUST NOT 提供该工具。
- **FR-016**: load_skill 属于 Runtime 提供的内置能力，MUST NOT 要求使用者在 Agent 管理页重复绑定；执行前 MUST 再次校验绑定关系和启用状态。
- **FR-017**: load_skill MUST NOT 接受任意文件路径，MUST NOT 读取未授权目录。
- **FR-018**: Skill 不存在、已停用、未绑定、文件缺失或内容无法读取时，系统 MUST 返回明确的工具错误，由模型决定后续处理。
- **FR-019**: load_skill 返回内容 MUST 设置合理的大小上限；超过上限时 MUST 明确报错，MUST NOT 静默截断指令。
- **FR-020**: load_skill MUST 与其他工具一样，通过正式工具调用标识配对请求和结果，产生工具开始、成功或失败事件，并标记工具类型；加载后的指令 MUST 作为工具结果保留在本次运行上下文中。

**工具发现与权限**

- **FR-021**: 提供给模型的工具 MUST 包括：当前 Agent 已绑定且仍然启用的内置工具、已绑定且启用的 MCP Server 提供的工具，以及存在可用 Skill 时的 load_skill 工具。
- **FR-022**: 本地工具、MCP 工具和 Skill 加载工具 MUST 使用统一的工具标识与映射规则以避免名称冲突，并通过同一个执行入口处理权限校验、参数校验、结果、错误信息和取消信号。
- **FR-023**: 工具执行前 MUST 再次校验权限；未绑定、已停用、不存在或参数不合法的工具请求 MUST 拒绝执行，并将明确的错误结果交还模型。
- **FR-024**: 系统 MUST NOT 因为模型填写了某个工具名称，或 Skill 指令要求使用某个工具，就允许调用。
- **FR-025**: 系统 MUST 沿用已有工具执行层的权限校验和危险操作限制；Skill 加载工具只能读取授权的 Skill 指令，MUST NOT 成为绕过文件访问限制的入口。

**取消与资源清理**

- **FR-026**: Runtime MUST 接收独立的取消信号，并将信号传递到模型请求、工具执行和循环调度。
- **FR-027**: 本阶段由聊天接口在用户停止生成、关闭页面或浏览器连接断开时触发取消；Runtime MUST NOT 直接监听浏览器连接。
- **FR-028**: 收到取消信号后，系统 MUST 尽快停止模型请求、后续轮次和正在执行的工具。
- **FR-029**: 无论成功、失败、达到限制还是取消，系统 MUST 关闭连接并清理本次运行创建的 MCP 进程等资源；清理逻辑 MUST 覆盖所有退出路径。

**聊天接入、事件与日志**

- **FR-030**: 聊天页 MUST 改为调用统一 Agent Runtime，继续支持流式展示，并正确处理各种结束状态（正常完成、达到限制、失败、取消）。
- **FR-031**: 每次运行 MUST 生成唯一运行标识；Runtime MUST 统一输出运行开始、模型请求开始、内容增量、模型请求结束、工具调用开始、工具调用结果和运行结束事件；前后端 MUST 使用统一的事件标识。
- **FR-032**: 事件 MUST 包含运行标识、运行内递增的顺序字段和事件类型，以及适用的轮次和调用标识。
- **FR-033**: 模型请求和工具调用的开始、结束事件 MUST 通过各自的调用标识配对；Skill 加载 MUST 复用工具调用事件并标记工具类型，方便后续展示。
- **FR-034**: 模型请求结束事件 MUST 记录状态、耗时以及接口实际返回的 Token 用量；未返回用量时 MUST 标记为未知，MUST NOT 填写为零。
- **FR-035**: 运行结束事件 MUST 包含最终状态和结束原因，且每次运行只产生一次。
- **FR-036**: 后台日志 MUST 记录运行标识、轮次、模型或工具调用标识、工具名称、执行状态和结束原因。
- **FR-037**: 日志及展示事件 MUST 使用经过脱敏的摘要，MUST NOT 直接记录完整上下文、Skill 指令正文或未经处理的工具结果。
- **FR-038**: 模型上下文所需的工具结果与供页面展示的安全摘要 MUST 分开处理，避免为了记录日志而丢失模型执行所需的信息。

### Key Entities *(include if feature involves data)*

- **Agent 运行（Run）**：Runtime 的一次执行实例。属性：唯一运行标识、所属 Agent、最终状态与结束原因（正常完成 / 达到轮数限制 / 失败 / 取消）、本次运行的能力收窄配置。仅存在于运行期间，本阶段不持久化。
- **运行事件（RunEvent）**：Runtime 对外输出的最小信息单元。属性：运行标识、运行内递增的顺序字段、事件类型、适用轮次、调用标识；按事件类型附带状态、耗时、Token 用量或脱敏摘要。是聊天页展示与后台日志的共同来源。
- **工具调用（ToolCall）**：一次工具执行。属性：调用标识（用于开始/结束事件配对）、工具名称、工具类型（内置工具 / MCP 工具 / Skill 加载）、执行状态（成功 / 失败 / 被拒绝 / 被取消）。完整结果仅进入模型上下文；对外只暴露脱敏摘要。
- **Skill 目录条目**：运行时呈现给模型的 Skill 概要。属性：稳定标识、名称、用途说明。完整指令仅在 load_skill 成功后进入本次运行上下文。
- **运行级能力限制**：调用方随请求传入的收窄参数，只能在 Agent 已绑定且启用的能力范围内做进一步限制。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 聊天链路 100% 的模型调用与工具执行经由统一 Runtime 完成，聊天接口中不存在自行维护的模型调用或工具循环。
- **SC-002**: 抽查 10 次含工具调用的运行，工具调用前后的正文片段均按生成顺序完整展示，无丢失、重复或乱序。
- **SC-003**: 未绑定、已停用、不存在或参数不合法的工具调用请求 100% 被拒绝执行，且交还模型的错误信息明确说明原因。
- **SC-004**: load_skill 对不存在、未绑定、已停用、文件缺失、内容不可读及超出大小上限的请求 100% 返回明确错误，不出现静默截断。
- **SC-005**: 在成功、失败、达到轮数限制、取消四类退出路径上分别验证，资源清理 100% 执行，运行结束后无本次运行创建的残留 MCP 进程或连接。
- **SC-006**: 任意一次运行的运行标识唯一；事件顺序字段严格递增；运行结束事件恰好出现一次（抽检 100% 符合）。
- **SC-007**: 模型接口未返回 Token 用量时，100% 的事件标记为未知，不出现以零冒充的情况。
- **SC-008**: 使用者点击停止后，前端 1 秒内停止追加展示新内容，后端模型输出在 3 秒内停止，运行以"已取消"状态结束并产生运行结束事件；正在执行的工具按平台能力尽快终止（抽检 100% 产生取消收尾事件）。
- **SC-009**: 抽查日志与展示事件，100% 不含完整上下文、Skill 指令正文、未处理的工具结果及密钥等敏感信息。
- **SC-010**: 不经过前端页面与浏览器，直接调用 Runtime 可完成一次含工具调用的运行并获得事件与最终结果（为后续评测复用验证通道）。

## Assumptions

- 运行记录（事件流、工具调用明细）不持久化；刷新页面后聊天记录仍按第八阶段规则展示已保存的正文，不回放工具调用中间过程。
- 会话与消息持久化沿用第八阶段实现，本阶段不改动会话数据模型；工具调用过程不新增持久化内容。
- 聊天接口本阶段传入的运行级能力限制为空（不收窄）；收窄机制本身必须实现，供后续阶段（如评测）使用。
- Skill 指令内容大小上限的具体数值在 Plan 阶段确定（合理默认量级为几十 KB），超出即明确报错。
- 达到轮数限制时，不再执行新的工具调用，运行正常收尾，结束原因标明"达到轮数限制"，已生成正文保留。
- 模型在同一运行中重复调用 load_skill 时，按普通工具调用处理，不做强制去重。
- MCP Server 连接与进程的清理范围以"本次运行创建的资源"为准；若现有基础设施存在共享常驻连接，其清理边界在 Plan 阶段确认。
- 事件类型与标识的统一清单在本阶段 contracts 中定义，前后端共同消费，禁止各自硬编码。
- 聊天界面对工具调用过程以简要状态提示展示（如"正在调用工具：×××"），具体展示形态由 Plan 阶段确定，且不得影响流式正文的顺序展示。
- 浏览器连接断开在本阶段触发取消并按取消路径收尾；"断开后仍在后台运行"留给后续阶段（Runtime 不监听浏览器连接的设计已为此留出空间）。
- 无可用 Agent、Agent 被删除、模型请求失败等入口校验与异常处理沿用第八阶段既有规则。
- 本阶段不做：评测模块、运行记录持久化、浏览器断开后后台继续运行、上下文自动压缩或摘要。
