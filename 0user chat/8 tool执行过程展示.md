# 工具执行过程展示

请在现有聊天页面中展示 Agent Loop 的工具执行过程。后端已经能够调用本地工具和 MCP 工具，本阶段重点是让普通用户看懂 Agent 做了什么，同时避免泄露敏感信息或在聊天中直接展示大段原始数据。

## 过程卡片

1. 工具调用开始时，在当前 Agent 回复区域插入一张过程卡片，展示工具名称和“正在执行”状态。执行结束后，更新为成功或失败，并显示实际耗时。
2. 本地工具使用易读名称；MCP 工具同时展示 MCP Server 名称和工具名称。内部编号只用于事件关联，不作为主要标题。
3. 卡片默认收起，展示简短的执行摘要。用户展开后，可以查看整理后的输入参数和结果。工具失败时，展示便于理解的原因，不直接显示程序异常堆栈。
4. 运行取消时，尚未结束的卡片需要标记为“已取消”；连接中断且无法确认执行结果时，标记为“状态未知”。不得一直停留在“正在执行”，也不得误标为成功。

## 消息顺序与事件关联

1. 同一次 Agent 回复中的正文和工具卡片，按照实际事件顺序交错展示。工具调用前的文字保留在卡片上方，后续生成的文字接在卡片下方，不得将所有工具卡片统一移动到回复开头或结尾。可以理解为：每次工具执行也是Agent回复内容的一部分，所以需要按序展示
2. 使用运行标识和工具调用标识关联开始、完成及失败事件，更新对应卡片，避免重复创建或更新错位。同一个工具被多次调用时，每次调用都需要独立展示。
3. 如果后端存在并行调用，卡片按开始顺序排列，完成时更新原位置，不按结束顺序重新排序。

## 输入与结果展示

1. 输入和结果需要按内容类型整理：
- 短文本：直接显示，保留必要的换行。
- 结构化内容：使用格式化缩进，方便查看字段和值。
- 长内容：默认只展示前一部分，明确标注已截断，并提供展开操作。
- 二进制内容：不展示正文或 Base64 数据，只提示内容类型和可用的大小信息。

2. 对可展开内容设置合理的展示上限。超过上限时，明确提示未展示全部内容，避免一次渲染大量数据导致页面卡顿。
3. 结果摘要优先从工具返回的状态和内容中提取，本阶段不额外调用模型生成摘要。工具返回内容按不可信文本处理，不得作为 HTML 或脚本直接执行。

## 滚动与交互

1. 生成过程中，聊天区域保持可滚动。当用户位于底部附近时，自动跟随新文字和工具状态更新。
2. 用户主动向上查看历史消息后，暂停自动跟随，不得强行拉回底部。用户回到底部后，恢复自动跟随，并提供“回到最新消息”的快捷按钮。
3. 展开或收起卡片时，尽量保持当前阅读位置，避免页面明显跳动。

## 状态保留与页面

1. 本阶段至少保证当前页面内各会话的工具过程完整保留。切换会话再返回时，已有卡片、执行状态和消息顺序仍然正确。
2. 刷新页面后的过程恢复留到后续运行记录开发阶段实现，现在不提前增加持久化功能。
3. 卡片配色、字号、间距和展开交互与现有聊天页面保持一致。状态需要同时使用文字和视觉标识区分，不能只依靠颜色。
