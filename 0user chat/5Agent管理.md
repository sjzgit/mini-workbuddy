# Agent 管理
开发 Agent 管理功能。模型、工具、Skills 和 MCP 管理已经完成。

Agent 用于组合模型、系统提示词、工具、Skills 和 MCP Server，形成面向具体任务的配置。本阶段只实现配置管理和页面状态，不开发 Agent Loop、运行记录和历史会话。

## 列表（卡片）页面

1. 页面提供新建、编辑、删除和设置默认 Agent 操作。没有 Agent 时，展示空状态，并提供新建入口。
2. 列表采用卡片的样式
3. Agent 卡片：
   1. 顶部：需要展示名称、说明、使用的模型、绑定的工具数量、Skills 数量、MCP Server 数量、是否为默认 Agent，以及最后更新时间。排布方式你自己决定
   2. 下方：展示关联的工具、技能、MCP，最多展示三个，超过显示`+N`
   3. 底部：编辑、删除按钮
   4. 点击卡片进入Agent详情

## Agent详情

1. Agent详情页面：用全屏的dialog展示
   1. 顶部-基本信息：
      - 名称：用于识别 Agent。
      - 说明：描述 Agent 的用途和适用任务。
      - 是否默认Agent
      - 发布按钮：点击Agent所有配置，包含下方主体内容中的配置
   2. 下方主体内容分为三列：
      1. 系统提示词：
         1. textarea, 高度铺满, 不限长度，使用大字段保存
         2. 默认填充如下文本：
            ```text
            # 角色：角色名称
            角色概述和主要职责的一句话描述

            ## 目标：
            角色的工作目标，如果有多目标可以分点列出，但建议更聚焦1-2个目标

            ## 技能：
            1. 为了实现目标，角色需要具备的技能1"
            2. 角色需要具备的技能2"

            ## 工作流：
            1. 描述角色工作流程的第一步
            2. 描述角色工作流程的第二步


            ## 输出格式：
            如果对角色的输出格式有特定要求，可以在这里强调并举例说明想要的输出格式

            ## 限制：
            - 描述角色在互动过程中需要遵循的限制条件1

            ```
         3. 右上角展示版本选择，可以切换版本查看维护，每次系统提示词变化后保存时会新增一个版本
      2. Agent编排：自上而下包含如下内容
         - 模型选择：选择一个已配置的模型
         - 工具选择：多选工具管理中的工具
         - Skills 选择：多选skill管理中的skill
         - MCP选择：多选MCP管理中的MCP Server
         - 最大执行轮数：整数，限制后续 Agent Loop 的执行轮数。本阶段只保存配置，执行限制在 Agent Loop 阶段实现。
      3. 预览与调试：暂时保留占位，后续等Agent完整对话功能完成后再嵌入到这里

2. 各选择项使用卡片列表的方式，需要展示名称和用途说明。模型选项展示名称及模型标识，不能只显示内部编号。工具、Skills 和 MCP Server 支持多选，也允许不选。
3. 新建 Agent 时，默认选中当前默认模型。没有可用模型时，明确提示用户先添加模型，并提供前往模型管理的入口。
4. 保存前校验名称、模型选择和最大执行轮数等字段。最大执行轮数必须为正整数，并提供合理的默认值和范围说明。
## 系统提示词版本
1. Agent 首次保存时，为系统提示词生成第一个版本，版本号从 1 开始。以后只有系统提示词内容发生变化时，才生成新版本并递增版本号。修改名称、模型或能力绑定等其他配置，不增加提示词版本号。
2. 维护Agent系统提示词时可以切换版本进行编辑修改，保存后保存为新版本

## 能力选择与停用状态

1. 只有启用的工具、Skills 和 MCP Server 可以新增到 Agent 配置中。
2. 已经绑定的能力后来被停用时，需要保留原绑定，并在编辑页标记为“已停用，不可用”。用户可以手动移除，也可以保留绑定后保存其他修改，不得自动清除。
3. 列表中的绑定数量按实际保存的绑定统计，包含已经停用的能力。本阶段只处理配置和可用状态展示，运行时过滤停用能力的逻辑在 Agent Loop 阶段实现。

## 默认 Agent 与删除
1. 系统最多只能有一个默认 Agent。有 Agent 时，应保持一个默认项：
- 保存第一个 Agent 时，自动将其设为默认 Agent。
- 设置新的默认 Agent 时，自动取消旧 Agent 的默认状态。
- 删除普通 Agent 前，需要用户确认。
- 删除当前默认 Agent 时，如果还有其他 Agent，需要先让用户选择新的默认项，再完成删除和切换。
- 删除最后一个 Agent 时，允许确认后删除，清除默认设置，并让页面回到空状态。

2. 默认切换和删除需要保证数据一致性，避免出现多个默认 Agent，或默认设置指向已删除记录。当前阶段没有历史会话，不加入会话引用限制。

## 资源引用保护
1. 从本阶段开始，Agent 会实际引用模型、Skills 和 MCP Server，需要同步补充这些管理模块的删除保护。
2. 某个模型、Skill 或 MCP Server 被任意 Agent 引用时，必须阻止删除，并展示正在使用它的 Agent 名称。
3. 用户需要先修改相关 Agent，移除对应绑定或更换模型，或者删除相关 Agent；资源没有任何 Agent 引用后，才允许删除。不得自动解除绑定或替换模型。内置工具继续保持不可删除。
4. 引用检查必须在后端执行，不能只依靠前端禁用按钮。删除默认模型时，应先检查 Agent 引用，再执行模型管理已有的默认项切换规则。
## 数据保存与页面
Agent 配置、能力绑定、默认状态和系统提示词版本需要持久化，刷新页面或重启服务后仍然保留。
页面配色、字号、布局和交互方式与已有管理页面保持一致。
