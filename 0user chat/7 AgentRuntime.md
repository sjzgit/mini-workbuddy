# 统一 Agent Runtime

**请先读懂当前聊天请求、上下文构造、模型调用和取消处理流程，在后端建立统一的 Agent Runtime，并将 Agent Loop 放在 Runtime 内实现。**
1. Agent Runtime 负责加载 Agent 配置、组装上下文、准备可用工具与 Skill 目录、调用模型、执行工具循环、处理取消和资源清理，以及输出统一运行事件。
2. Runtime 接收 Agent 标识、用户输入、历史消息、运行级能力限制和取消信号，输出运行事件及最终结果。运行级能力限制只能收窄 Agent 已有权限，不能额外授予未绑定或已停用的能力。
3. 聊天接口负责接收请求和转发事件，不能自行维护模型与工具循环。Runtime 不依赖前端页面、HTTP 请求对象或浏览器连接，后续评测可以直接调用同一个 Runtime。本阶段不提前开发评测模块，也不要求实现运行记录持久化。
4. 复用现有模型调用和工具执行基础设施，避免另建重复实现。

## 循环流程

1. 每次运行时，由 Agent Runtime 加载所选 Agent 的模型、系统提示词、可用 Skill 目录和工具定义等配置，结合当前会话上下文发起模型请求。
2. 循环按照以下过程执行：
- 模型直接给出回答，没有请求工具时，本次运行正常结束。
- 模型请求调用工具时，通过统一入口执行，将结果追加到上下文，再次请求模型。
- 模型调用 Skill 加载工具时，将读取到的完整指令作为工具结果追加到上下文，再次请求模型，由模型按照指令继续处理任务。
- 循环持续到正常结束、达到Ageng管理中设置的轮数限制、发生运行级错误或被取消。
3. 保留现有流式输出能力。模型在工具调用前后生成的正文片段都需要按顺序保留，不得在进入下一轮时覆盖或清空。

## Skills 发现与按需加载

本阶段将为Agent提供已启用 Skills的加载运行

1. 运行开始时，只向模型提供当前 Agent 已绑定且仍然启用的 Skill 标识、名称和说明，不预先加入全部详细指令。上下文中需要说明：当任务符合某个 Skill 的用途时，先加载其完整指令，再按照指令执行。
2. 提供统一的 `load_skill` 工具，接收 Skill 稳定标识，读取对应 Skill 的完整指令。Agent 没有可用 Skill 时，不提供该工具。
3. load_skill 属于 Runtime 提供的内置能力，不要求用户在 Agent 管理页重复绑定。它只能读取当前 Agent 已绑定且当前启用的 Skill，执行前必须再次校验绑定关系和启用状态。不得接受任意文件路径，也不得读取未授权目录。
4. Skill 不存在、已停用、未绑定、文件缺失或内容无法读取时，返回明确的工具错误，由模型决定后续处理。返回内容设置合理的大小上限，超过上限时明确报错，不得静默截断指令。
5. Skill 加载完成后，模型可以按照其中的步骤调用当前可用工具。
6. load_skill 与其他工具一样，通过正式工具调用标识配对请求和结果，产生工具开始、成功或失败事件。加载后的指令作为工具结果保留在本次运行上下文中。

## 工具发现与权限

1. 提供给模型的工具包括当前 Agent 已绑定且仍然启用的内置工具、已绑定且启用的 MCP Server 提供的工具，以及存在可用 Skill 时提供的 load_skill 工具。
2. 本地工具、MCP 工具和 Skill 加载工具使用统一的工具标识与映射规则，避免名称冲突，并通过同一个执行入口处理权限校验、参数校验、结果、错误信息和取消信号。
3. 工具执行前再次校验权限。未绑定、已停用、不存在或参数不合法的工具请求，都需要拒绝执行，并将明确的错误结果交还模型。不得因为模型填写了某个工具名称，或 Skill 指令要求使用某个工具，就允许调用。
4. 沿用已有工具执行层的权限校验和危险操作限制。Skill 加载工具只能读取授权的 Skill 指令，不能作为绕过文件访问限制的入口。

## 取消与资源清理

1. Runtime 接收独立的取消信号，并将信号传递到模型请求、工具执行和循环调度。
本阶段由聊天接口在用户停止生成、关闭页面或浏览器连接断开时触发取消。Runtime 内部不直接监听浏览器连接，便于后续阶段调整为浏览器断开后仍在后台运行。
2. 收到取消信号后，尽快停止模型请求、后续轮次和正在执行的工具。
3. 无论成功、失败、达到限制还是取消，都需要关闭连接并清理本次运行创建的 MCP 进程等资源。清理逻辑必须覆盖所有退出路径。

## 聊天接入、事件与日志

1. 聊天页面改为调用统一 `Agent Runtime`，继续支持流式展示，并正确处理各种结束状态。
2. 每次运行生成唯一运行标识。Runtime 统一输出运行开始、模型请求开始、内容增量、模型请求结束、工具调用开始、工具调用结果和运行结束等事件。这里前后端需要统一这些事件标识。
3. 事件包含运行标识、运行内递增的顺序字段、事件类型，以及适用的轮次和调用标识。模型请求和工具调用的开始、结束事件通过各自的调用标识配对。Skill 加载复用工具调用事件，并标记工具类型，方便后续展示。
4. 模型请求结束事件记录状态、耗时，以及接口实际返回的 Token 用量。未返回用量时标记为未知，不得填写为零。运行结束事件包含最终状态和结束原因，并且每次运行只产生一次。
5. 后台日志记录运行标识、轮次、模型或工具调用标识、工具名称、执行状态和结束原因。日志及展示事件使用经过脱敏的摘要，不直接记录完整上下文、Skill 指令正文或未经处理的工具结果。
6. 模型上下文所需的工具结果与供页面展示的安全摘要分开处理，避免为了记录日志而丢失模型执行所需的信息。
