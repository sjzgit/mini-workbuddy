2. 按照已有的 Run 记录和统一 Agent runtime 产生的真实事件，不重复创建记录，也不另写一套模拟日志。后续评测通过同一套接口记录运行过程。

   2. 007中已经保存了基础的会话和消息数据，需要在此基础上拓展存储

## Run 生命周期与状态说明

1. 每次用户发送消息并启动 Agent 时，对应一条 Run，而不是为整个会话或每轮模型调用创建一条 Run。
2. Run 至少区分以下状态：
- 运行中：请求已经开始，尚未结束。
- 成功：Agent 正常完成并返回最终回答。
- 部分完成：因执行轮数耗尽等限制结束，未能正常完成任务。
- 失败：模型服务错误或内部异常导致运行终止。
- 已取消：用户主动停止运行。
3. 状态与结束原因分开保存。单个工具失败后，Agent 仍可能继续完成任务，不应直接将整个 Run 标记为失败。模型失败前即使已经输出部分文字，Run 仍标记为失败，并保留未完成内容。
4. 浏览器断开后，沿用 runtime 的后台运行机制，最终结果仍写入原 Run。后端重启或异常退出导致运行无法继续时，需要将遗留记录标记为失败，并注明“运行中断”，不能永久停留在运行中。

## 运行列表

1. 运行列表按开始时间倒序展示，支持分页，以及按状态和 Agent 筛选。
2. 每行展示状态、Agent、模型、开始时间、总耗时、模型调用次数、工具调用次数、Token 用量和错误摘要。
3. Agent 和模型名称保留运行时的快照，后续配置改名或删除不应改变历史记录。错误摘要保持简短，正常完成的运行无需显示错误。
4. 列表只读取摘要字段，不加载完整事件、模型输入或工具结果。通过必要的快照字段、关联查询或批量查询获取展示数据，不得为每一行单独查询 Agent、模型和事件。

## 指标统计

1. 指标必须来自实际运行事件和模型返回的用量信息，并明确统计口径：
- 总耗时：从 Run 开始到进入最终状态的时间。
- 模型调用次数：实际发出的模型请求次数，包含失败请求；发生重试时，每次请求单独计数。
- 工具调用次数：实际进入工具执行入口的次数。权限或参数校验阶段被拒绝的请求单独记录，不计为已执行。
- Token 用量：汇总各次模型请求返回的输入、输出及可用的缓存命中用量，避免重复累计。
- 首个输出耗时：从 Run 开始到收到首段可展示正文的时间，不将空数据块或工具参数片段算作正文输出。
2. 模型服务未返回 Token 用量时，显示“未知”或“统计不完整”，不得填写为零。没有正文输出时，首个输出耗时显示“无正文输出”。缓存命中用量是否包含在输入 Token 中，应按接口定义处理，不能重复相加。

## 运行详情与时间线

1. 点击 Run 后进入详情页，展示运行摘要和按真实事件顺序排列的时间线。
2. 时间线包括 Agent 开始、模型请求、工具执行、最终回答、错误和运行结束。如果系统实际发生了上下文压缩，也需要展示压缩事件；本阶段不为展示时间线而额外实现压缩功能，也不生成虚构事件。
3. 模型步骤展示模型名称、状态、耗时、调用API时的完整输入输出和 Token 用量。工具步骤展示易读名称、状态、输入摘要、结果摘要和耗时；MCP 工具同时展示 Server 名称。
4. 事件需要包含 Run 标识、步骤或调用标识，以及稳定的顺序字段。使用调用标识关联开始与结束事件，不能仅靠时间戳或工具名称配对。失败步骤应清楚标明原因，目的是实现用户无需翻看原始日志也能定位到问题。
5. 详情默认读取安全事件和摘要，大段详细载荷按需单独加载。

## 与聊天页面共用事件

1. 聊天中的工具卡片和运行详情使用同一批事件及同一套名称、状态、摘要规则，避免同一次调用在两个页面显示不同结果。
2. 事件重复投递或重新加载时，不得重复插入步骤、重复累计次数或 Token。运行状态、指标汇总和事件保存应保持一致，不能出现 Run 已结束但步骤永久显示执行中的情况。

## 敏感信息与详细载荷

1. 在写入日志、运行记录和展示事件之前统一脱敏。模型 API Key、MCP 环境变量、认证 Header、完整系统环境和用户设备绝对路径，不得进入持久化记录。
2. 路径需要展示时，使用工作区相对路径或脱敏占位符(${workspace})。错误信息和工具输出也必须经过检查，避免间接泄露敏感内容。
3. 普通列表和事件只保存安全摘要。模型输入或完整工具结果，应使用独立、受控的详细载荷存储，限制读取入口和保存大小。详细载荷同样需要脱敏，不得因为访问受控就保存秘密原文。

## 查询与页面

1. 页面配色、字号、筛选控件和状态展示与已有管理页面保持一致。
2. 检查并测试列表查询次数，保证在相同分页条件下，数据库查询次数不会随返回行数逐条增长。详情事件和详细载荷不得在列表加载时提前读取。

## 测试与验证

1. 请为正常成功、工具失败后继续完成、模型失败、用户取消、轮数耗尽、后台运行结束和异常中断恢复补充测试。
2. 同时覆盖调用次数、Token 汇总、首个输出耗时、事件配对与去重、聊天和详情状态一致、敏感信息脱敏，以及列表查询次数。
3. 完成后，运行相关后端测试、前端类型检查和构建，修复所有失败项，并说明 Run 数据结构、事件复用方式、指标口径和验证结果。
