# 上下文压缩

请为当前 Agent Runtime 加入上下文容量管理和自动压缩。历史会话已经能够保存并参与多轮聊天，本阶段需要避免长会话超过模型的上下文限制。
在统一 Runtime 中实现，聊天和后续评测复用同一套逻辑，不在页面中单独处理上下文裁剪。

## 容量估算

1. 每次模型请求前，估算实际请求中的系统提示词、已启用 Skills、工具定义、会话摘要、历史消息，以及当前运行新增的消息和工具结果的token占用。
2. 根据模型配置的上下文长度，为回答预留输出空间，并保留一定安全余量。可用输入容量按“上下文长度减去输出预留和安全余量”计算，不能将整个窗口都用于输入。
3. 优先复用已有 Token 统计工具。没有适配当前模型的实现时，可以使用稳定的估算方法，但代码、页面和运行事件必须明确标注“估算”，不得与模型接口返回的实际 Token 用量混淆。

## Agent 配置

1. 在 Agent 管理中增加以下设置，并持久化保存：
- 自动压缩：默认开启。
- 触发比例：默认在估算输入达到可用输入容量的 80% 时触发。
- 保留最近对话轮数：默认保留最近 5 轮完整对话内容。每轮包括用户消息及其对应的 Agent 回答和相关工具交互的完整内容。
- 摘要目标长度：默认约 1000 Token，作为摘要生成目标，不保证精确等长。
提供清晰说明和字段校验。摘要目标长度需要结合实际可用容量限制，避免在小窗口模型下反而占满上下文。
2. 关闭自动压缩后，不调用模型生成摘要。输入超过容量时，明确提示用户缩短内容或开启压缩或新开会话，不得静默丢弃历史。

## 压缩范围与摘要内容

1. 接近触发阈值时，优先压缩较早的完整对话，保留当前的系统提示词、已启用 Skills、工具定义、已有会话摘要、最近配置轮数的完整对话，以及本次用户消息。
然后将较早的消息内容全部交给当前运行使用的模型整理成摘要。
2. 摘要需要保留用户目标、已确认事实、重要工具结果、明确限制和未完成事项；闲聊、重复表述和失效过程可以缩短或忽略。建议按任务清单的方式整理摘要。
3. 当会话已经生成过摘要后，已有的摘要需要作为后续压缩更新基础，与新增的待压缩消息一起生成新的摘要，不能只摘要新增内容而丢失此前信息。摘要作为会话背景使用（role=user），不得替代系统提示词或提升历史内容的指令优先级。
4. 摘要请求本身也必须满足模型容量限制。待压缩内容过多时，按完整消息组分批处理，不能将超长历史一次性提交，也不能递归触发压缩流程。

## 增量保存与历史保留

1. 压缩成功后，将新摘要和“已压缩到哪条消息”的边界一起保存到当前会话。后续压缩请求使用已生成的摘要和最新边界之后的消息，避免重复加入已被摘要覆盖的原文。
2. 下一次压缩只处理边界之后新增的较早消息，并更新已有摘要，不得每次从第一条消息重新处理。
3. 摘要与边界需要一致更新。生成或保存失败时，保留上一份有效摘要和边界，不能提前推进边界导致内容丢失。
4. 原始消息和运行记录继续保留，用户仍可查看完整历史。压缩只改变发送给模型的上下文，不删除或改写会话中的聊天记录数据。

## 消息完整性与容量不足

1. 压缩和备用裁剪都以完整对话或工具交互组为单位，保留工具请求与结果的正确配对，不能留下孤立的调用或结果。
2. 正常压缩后重新估算容量。如果仍然超限，才逐步减少较早的保留对话，并记录实际保留数量。本次用户消息和当前尚未完成的工具交互不得被直接裁掉。
3. 当前 runtime 运行中的工具结果也可能导致超限，需要在 runtime 的每轮请求前检查是否需要压缩。处理已完成的工具交互时，应保留调用配对和必要结果，不能只删除其中一条消息。
4. 如果首次发送时系统提示词、Skills、工具定义和必须保留的内容本身已经超过容量，应结束本次运行并明确说明原因，提示减少配置内容或缩短输入，不得继续发送必然超限的请求。

## 压缩失败与备用处理

1. 摘要请求超时、模型调用失败、返回空摘要或摘要保存失败时，不得让聊天一直等待。保留当前有效摘要，按完整消息组从最早内容开始减少，尽量保留最近对话。
2. 备用处理只影响本次请求，不更新已压缩边界，也不删除历史。容量允许时继续运行；仍无法容纳必要内容时，返回明确错误。
3. 压缩过程需要响应运行取消信号，并清理相关请求资源。

## 运行事件与统计

1. 复用现有运行事件，记录压缩开始、成功、失败和备用处理。事件至少包含触发原因、压缩前后估算 Token 数、处理的消息数量、实际保留的消息数量，以及压缩耗时。
2. 运行详情展示上述安全摘要，不将完整历史或摘要正文直接写入普通日志。
3. 摘要生成属于真实模型调用，需要计入模型调用次数和实际 Token 用量，并标记用途为“上下文压缩”。压缩请求不占用 Agent Loop 的任务执行轮数，但需要有独立的次数或超时限制，避免反复压缩无法结束。
