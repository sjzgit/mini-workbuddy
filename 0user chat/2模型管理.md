# 模型管理

## 需求描述
1. 用户可以在“模型管理”页面添加和维护语言模型。本阶段只支持兼容 OpenAI Chat Completions 接口的模型服务，统一使用一套调用逻辑，无需为不同厂商分别实现。
列表页面
2. 模型列表需要展示显示名称、请求使用的模型标识、服务地址、上下文长度、密钥配置状态、是否为默认模型和最后更新时间。
3. 页面提供新增、编辑、删除、测试连接和设置默认模型操作。没有模型时，展示空状态，并提供添加入口。
### 新增与编辑
新增和编辑页面提供以下配置项：
- 显示名称：用于在页面中识别模型。
- 模型标识：请求接口时使用的模型名称，需要与服务商提供的标识一致。
- 服务地址：模型服务的 API Base URL。提供填写示例，说明是否需要包含 /v1，避免用户填入完整的 /chat/completions 地址。
- API Key：调用模型服务所需的密钥。
- 上下文长度：模型支持的上下文窗口大小，单位为 token。
- 最大输出长度：单次请求允许生成的最大 token 数。
- 温度：控制输出的随机性。
- 输入单价：每百万输入 token 的价格，单位为人民币。
- 输出单价：每百万输出 token 的价格，单位为人民币。
- 缓存命中输入单价：每百万缓存命中输入 token 的价格，单位为人民币。
表单需要提供清楚的填写说明。默认值应明确标注为建议值，上下文长度、输出限制和价格以服务商说明为准，不得将示例值作为模型的实际参数。
保存前校验必填项、服务地址格式和数字范围。上下文长度与最大输出长度必须为正整数，最大输出长度不得超过上下文长度；温度按所支持接口的范围校验；价格不得为负数，未填写价格与价格为零需要区分。校验失败时，在对应字段旁说明原因。
### 密钥保护
使用当前项目认可的本地密钥保存方式，不得将明文密钥写入普通业务表、前端持久化存储或版本库。
保存后，列表、详情接口及保存接口的响应只返回密钥是否已配置，不得返回密钥正文。日志、错误信息和连接测试结果也不得泄露密钥。
编辑模型时，已配置密钥的输入框保持为空，并提示“已配置，留空则保留原密钥”。只有用户填写新密钥时才替换，不能因为编辑其他字段而清除原密钥。
### 测试连接
点击“测试连接”后，后端需要使用该模型配置发起一次真实请求。测试过程中显示“正在测试”，禁止重复提交。
测试成功时，显示“模型已连接”，并展示一小段真实回复。测试失败时，根据实际响应尽量区分密钥错误、模型标识错误、服务地址不可访问、请求超时和返回格式异常。
错误提示需要便于理解，并提供必要的排查建议。无法确定原因时如实说明，不要仅展示程序异常或堆栈信息。
### 默认模型与删除
系统最多只能有一个默认模型。有模型时，应保持一个默认模型：
- 保存第一个模型时，自动将其设为默认模型。
- 设置新的默认模型时，自动取消旧模型的默认状态。
- 删除普通模型前，需要用户确认。
- 删除当前默认模型时，如果还有其他模型，需要先让用户选择新的默认模型，再完成删除和切换。
- 删除最后一个模型时，允许确认后删除，清除默认模型设置，并让页面回到空状态。
默认模型切换和删除需要保证数据一致性，避免出现多个默认模型，或默认模型指向已删除记录。删除模型时，同时清理其保存的密钥。
### 数据保存与页面
模型配置和默认状态需要持久化，刷新页面或重启服务后仍然保留。密钥配置状态需要正确展示，所有返回给前端的数据都不得包含已保存的密钥正文。
页面配色、字号、布局和交互方式与已有管理页面保持一致。
