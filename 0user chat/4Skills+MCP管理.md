# Skills 管理

这里的 Skill 是一份供 Agent 阅读的任务说明，用于描述处理某类任务时需要遵守的步骤、输出格式和限制。Skill 本身不执行代码，也不直接调用工具。
## 列表页面
1. Skills 列表需要展示名称、简短说明、启用状态和更新时间，并提供导入、编辑、删除、启用、停用和手动刷新操作。
2. Skill 统一保存在当前项目的 workspace/skills 目录下，每个 Skill 使用独立目录。用户也可以在该目录下手动创建 Skill，点击页面上的刷新按钮后，系统重新扫描目录并更新列表，无需重启服务。
## 导入方式
1. 第一版支持通过 ZIP 文件导入 Skill。导入时需要检查文件结构和必要内容，将符合要求的 Skill 解压到 workspace/skills 目录下，并更新列表。
2. 导入失败时，需要明确提示原因。同名 Skill 不得直接覆盖已有内容。解压时需要校验文件路径，确保文件不会写入目标目录之外。
## 编辑与管理
1. 编辑页提供名称、用途说明和详细指令三个主要区域。详细指令支持 Markdown，输入区域应适合编辑较长内容。保存后，修改需要同步写入对应的 Skill 文件，并更新列表中的信息和更新时间。
2. 启用状态需要持久化保存，刷新页面或重启服务后仍然保留。停用后，Skill 文件继续保留，但不再提供给 Agent 使用。删除前需要用户确认，确认后删除对应的 Skill 目录，并更新列表。
## 页面与验证
页面配色、字号、布局和交互方式与已有管理页面保持一致。

# MCP 管理

MCP Server 可以通过外部程序向 Agent 提供工具。需支持在本机启动(通过 stdio 通信) 及 支持远程 HTTP 的MCP Server。暂不支持 OAuth和账号授权。

## 列表页面

MCP 管理页面需要展示服务器名称、说明、类型、最近一次测试结果，以及最近一次成功测试发现的工具数量（点击弹窗展示具体工具列表）。尚未测试时，明确显示“未测试”，工具数量显示为“未知”。
用户可以新增、编辑、删除、启用、停用和测试连接。删除前需要确认。

## 新增与编辑
1. 新增和编辑页面提供以下字段：
- 名称：用于在列表中识别 MCP Server。
- 说明：描述该 Server 的用途。
- 类型：支持本机启动和远程 HTTP。
  - stdio 通信相关字段：
    - 启动命令：启动程序所需的可执行文件名称或路径。
    - 启动参数：以列表形式填写，每一项对应一个参数，保留参数顺序。
    - 环境变量：可选，以键值对形式填写。
  - HTTP 相关字段：
    - url: MCP server地址
    - 请求Header: 请求头信息，可以自定义添加多个请求头

2. 页面需要提供简短说明和填写示例，告知用户这些配置通常可以从 MCP Server 的使用说明中获取，无需理解协议细节。
3. 启动命令和参数需要分开保存、直接传给进程，不得拼接成 Shell 命令执行。配置和启用状态需要持久化，刷新页面或重启服务后仍然保留。
4. 环境变量的值可能包含密钥等敏感信息。保存后应以掩码展示，不得在列表、日志、错误信息或测试结果中暴露完整原文。编辑时允许保留或替换已有值，不应将掩码作为实际值保存。
## 测试连接
1. 点击“测试连接”后，系统需要实际启动 MCP Server，完成协议初始化并读取工具列表，测试结束后正常关闭连接并清理进程。测试仅发现工具，不执行工具。
2. 测试成功时，展示工具数量，以及每个工具的名称、用途和参数说明，包括参数类型、是否必填等信息。Server 未提供工具时，显示“连接成功，未发现工具”。
3. 测试失败时，根据实际错误尽量区分以下情况，并给出便于理解的提示：
- 启动命令不存在。
- 程序启动失败或提前退出。
- 连接或读取工具超时。
- 协议版本或响应格式不兼容。
- Server 主动返回错误。
- 链接失败
4. 无法确定原因时，明确提示未知错误，并提供经过敏感信息脱敏的诊断信息。
5. 测试过程中显示进行状态，禁止重复提交。同一个 Server 不允许同时进行多次测试。无论成功、失败还是超时，都需要清理测试进程，避免后台残留。
## 启用与停用
1. 启用状态决定该 Server 是否可供 Agent 使用。“测试连接”是独立操作，停用状态下也可以测试，测试成功不会自动启用。
2. 修改启动命令、参数或环境变量后，原测试结果需要标记为“配置已变更，待重新测试”，避免将旧结果误认为当前配置的验证结果。
## 页面与验证
页面配色、字号、布局和交互方式与已有管理页面保持一致。
完成后，运行相关测试、前端类型检查和构建，修复所有失败项，并说明实现内容和验证结果。
